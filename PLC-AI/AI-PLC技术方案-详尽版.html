1. 项目概述与愿景

1.1 项目背景

工业自动化领域长期面临以下痛点：

痛点现状影响
品牌壁垒西门子、罗克韦尔、三菱等PLC使用互不兼容的编程软件工程师需学习多套工具，切换成本高
电气设计与编程分离电气CAD（E3、Capital X）和PLC IDE（TIA Portal、CODESYS）是独立工具数据不同步，重复劳动，易出错
AI渗透率低工业领域AI应用仍以"辅助建议"为主未能实现端到端自动化
数据孤岛PLC数据分散在各设备中，缺乏统一采集分析平台数据价值未被充分挖掘

2.2 架构设计原则

  1. 模型无关的AI架构 — AI引擎通过抽象LLM接口层隔离具体模型，支持GPT-4o、Claude Opus 4、Gemini 2.5、Llama 4、Qwen 3等模型热切换
  2. 插件化扩展 — PLC品牌驱动、通信协议、AI模型均以插件形式注册，第三方可通过gRPC插件SDK贡献
  3. 事件驱动通信 — 核心服务间使用NATS消息队列实现松耦合异步通信
  4. 边缘-云协同 — 边缘节点处理毫秒级实时任务，云端处理AI推理和长期存储
  5. 安全纵深防御 — 传输层TLS 1.3、应用层API签名、数据层字段级加密、访问层RBAC+ABAC混合模型

4. AI 智能引擎深度设计

AI引擎是本系统的核心差异化能力，基于大语言模型（LLM）+ 检索增强生成（RAG）+ 领域知识图谱三重技术构建，实现从需求输入到PLC程序部署的全链路智能化。参考西门子、施耐德、罗克韦尔等工业AI产品的最佳实践，同时突破其封闭生态限制。

4.1 需求自动解析与电路设计 — AI管道5步流程

用户自然语言输入 → Step 1: 需求规范化 (LLM提取实体关系 + NER设备识别) → Step 2: 结构化提取 (Schema-guided Generation → ControlSpec JSON) → Step 3: 设备匹配 (RAG检索符号库向量相似度匹配) → Step 4: 电路合成 (主电路/控制电路/I/O接线图 + A*自动布线) → Step 5: 人机协同 (可视化呈现 + 用户拖拽微调 + 强化学习反馈)

4.2 自动编写PLC控制程序

4.2.1 代码生成策略

策略适用场景方法准确率
模板匹配标准控制模式（启停、正反转、星三角）RAG检索→参数化→填充~98%
AST生成中等复杂度逻辑LLM生成UIR AST→验证→编译~92%
多智能体协同复杂系统分解→多个Agent并行生成→合并~88%

4.2.2 RAG增强生成流程

用户需求 → Query Encoder → Milvus Vector DB (PLC指令库/模板库) → Top-K 相关指令召回 → Context Window 组装 → LLM Generation → IEC编译器验证 → (通过?) → 输出代码 → (失败?) → 错误反馈→重新生成(最多3次)
准确率保障：AI生成的代码自动通过三层验证 — 语法检查（IEC 61131-3编译器）、逻辑等效性检查（SMT求解器）、仿真验证（软PLC运行时）。参考Wipro PARI的方案，目标将代码准确率从85%提升至95%以上。

4.3 PLC逻辑关系分析

多维分析引擎： ├─ 控制流分析: LD/FBD→Petri网模型转换、状态空间枚举、死锁/活锁检测 ├─ 数据流分析: Use-Define链、变量生存期、数据依赖图、扇入/扇出 ├─ 时序分析: 定时器参数合理性、时序冲突检测、响应时间上界计算 ├─ 安全分析: 安全联锁完整性(SIL验证)、FTA/ETA、HAZOP引导 ├─ 合规分析: PackML状态机完整性、ISA-88批处理模式 └─ 复杂度度量: 圈复杂度、霍尔斯特德度量、可维护性指数

4.4 PLC错误检测与修正 — 三层验证体系

Layer 1: 静态分析

检测悬空线圈、未复位定时器、锁存缺失解锁触点、重复输出、除零风险、数组越界、隐式类型转换、未初始化变量、注释与代码不一致（NLP对比）等9类常见编程错误。

Layer 2: 形式化验证

基于Z3 Theorem Prover，将关键安全逻辑转换为SMT公式进行可达性分析和死锁检测。验证"急停后所有电机停止"、"互锁条件成立时禁止同时启动"等安全属性。

Layer 3: 仿真测试

内置软PLC运行时，支持虚拟I/O信号注入、时序波形查看、断点/单步调试、状态快照对比、覆盖率报告（语句/分支/MCDC），集成数字孪生闭环验证。

AI智能修正

检测到错误后自动生成3个候选修正方案，按安全性>正确性>简洁性排序，展示修改前后代码对比和影响范围分析，支持一键应用或手动调整。

Snap PLC 启示：系统未来可扩展支持用户拍摄控制柜面板照片，AI自动识别指示灯、继电器、接线端子，推断可能的PLC逻辑，辅助故障排查与逆向工程。

8. 安全架构设计

8.1 纵深防御模型

Layer 1: 传输安全

TLS 1.3（AES-256-GCM）、mTLS服务间通信、WSS、证书自动化管理。

Layer 2: 认证授权

JWT (RS256, 15min+7d)、MFA(TOTP/WebAuthn)、RBAC+ABAC混合、SSO(SAML/OIDC)。

Layer 3: 应用安全

API限流(Token Bucket)、CSP+XSS防护、CSRF防护、文件上传白名单+病毒扫描。

Layer 4: 数据安全

AES-256静态加密、字段级加密(PLC密码)、HashiCorp Vault密钥管理、不可变审计日志。

Layer 5: 基础设施

VPC网络隔离、WAF、DDoS防护、容器非root运行、Trivy镜像扫描、季度渗透测试。

8.2 工业特有安全

  • OPC UA Security: Basic256Sha256安全策略强制启用
  • 单向数据二极管: SIL3场景可选硬件隔离
  • PLC程序签名: 数字签名防篡改 + 安全启动 + 固件哈希验证
  • 数据主权: 分级存储（GDPR/中国数据安全法合规）、跨境传输加密+法律审查

10. 部署架构

系统支持三种部署模式，满足不同规模与安全等级的企业需求：

SaaS 云端模式

适合中小型制造企业，按需订阅，零运维成本。AI能力基于云端大模型持续更新。数据TLS加密传输，SOC 2合规。

架构：CDN → ALB → APISIX → K8s(Go Core + Python AI) → PostgreSQL RDS + TDengine Cloud

混合部署模式

适合中大型企业，边缘节点部署在工厂侧处理实时数据，核心AI和可视化在云端。关键数据不出厂区。

边缘：K3s+NeuronEX+TDengine Edge(7天) → MQTT/TLS → 云端AI+长期存储

私有化部署模式

适合军工、制药、核电等高安全行业。全部组件本地部署，AI引擎基于开源模型（Llama 4、Qwen 3）私有化运行，完全离线。

支持国产化：ARM(鲲鹏/飞腾)+麒麟OS+达梦DB，Docker Compose/Helm一键部署
