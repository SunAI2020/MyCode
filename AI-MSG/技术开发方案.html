    1.2 核心设计原则

    原则 说明 实现方式
    隐私优先 (Privacy-First) 敏感数据默认端侧处理，不上传云端 端侧模型 + 差分隐私 + 数据脱敏
    端云协同 (Edge-Cloud Synergy) 简单分类端侧完成，复杂推理云端执行 三级路由决策引擎
    模块化设计 (Modular) 各功能模块独立开发、独立部署 Clean Architecture + DI
    实时响应 (Real-Time) 信息到达后 500ms 内完成分类 端侧模型 + 异步处理 + 优先级队列
    离线可用 (Offline-First) 核心功能无需网络即可使用 端侧模型 + 本地数据库 + 同步队列
    渐进增强 (Progressive) 用户可选择授予不同级别的权限 权限分级 + 功能降级策略

    3.3 端侧推理流水线

    
// 端侧推理流水线
class OnDeviceInferencePipeline @Inject constructor(
    private val textClassifier: TextClassifier,       // BERT-Tiny
    private val spamDetector: SpamDetector,           // 垃圾信息模型
    private val fraudPatternMatcher: FraudPatternMatcher,
    private val sensitiveContentFilter: SensitiveContentFilter,
    private val ruleEngine: RuleEngine
) {
    suspend fun process(rawMessage: RawMessage): ClassificationResult {
        // 第一级：规则引擎（毫秒级）
        val ruleResult = ruleEngine.evaluate(rawMessage)
        if (ruleResult.isDefinitive) return ruleResult.toClassification()
        
        // 第二级：文本分类（<200ms）
        val textResult = textClassifier.classify(rawMessage.content)
        
        // 第三级：组合评分
        val spamScore = spamDetector.score(rawMessage)
        val fraudScore = fraudPatternMatcher.match(rawMessage)
        val sensitiveScore = sensitiveContentFilter.evaluate(rawMessage)
        
        // 融合评分
        val finalScore = FusionModel.fuse(
            textResult, spamScore, fraudScore, sensitiveScore
        )
        
        // 判断是否需要上云
        return if (finalScore.confidence < 0.85) {
            ClassificationResult.DeferredToCloud(rawMessage, finalScore)
        } else {
            ClassificationResult.OnDevice(finalScore)
        }
    }
}

    5.3 诈骗检测策略（多层防御）

    
Level 0 — 本地规则引擎（0ms）
  ├── 号码黑名单（国家反诈中心 + 用户自定义 + 协同举报）
  ├── URL 黑名单（钓鱼网站库）
  ├── 关键词规则（"转账"+"安全账户"+"验证码"组合触发）
  └── 正则模式（仿冒银行/运营商号码格式）

Level 1 — 端侧模型初筛（<200ms）
  ├── 文本分类模型（诈骗/疑似/正常）
  ├── 实体识别（银行名称/金额/验证码/身份证号）
  └── URL 风险检测（域名相似度算法）

Level 2 — 云端深度分析（<2s）
  ├── LLM 语义理解：判断是否为诈骗话术
  ├── 向量检索：匹配已知诈骗案例库 (Milvus)
  ├── 关系图谱：号码/URL/账号关联分析
  └── 多模态分析：诈骗图片/二维码/截图识别

Level 3 — 协同联防（准实时）
  ├── 用户举报后 → 同步 hash → 全网用户自动拦截
  ├── 与国家反诈中心接口联动
  └── 运营商诈骗号码库同步

    15.3 应急预案

    
应急场景1：微信封禁无障碍服务采集
  → 降级为纯通知栏采集模式
  → 引导用户手动转发消息到 App
  → 加速与腾讯的官方合作洽谈

应急场景2：AI 服务大面积故障
  → 客户端切换为纯端侧推理模式
  → 功能降级：仅保留分类和过滤，暂停智能回复
  → 恢复后批量同步处理积压消息

应急场景3：数据安全事件
  → 立即启动安全响应小组
  → 72小时内通知受影响用户（PIPL要求）
  → 公开披露事件详情和修复措施
  → 第三方安全审计
