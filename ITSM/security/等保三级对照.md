# 等保 2.0 三级（GB/T 22239-2019）对照表 · ITSM

> 说明：下表为「安全要求 → 本系统实现/证据」对照，作为等保测评准备材料；「证据」列为可提供的实现点，需在实际测评中配合制度、记录与配置核验。

## 1. 安全通信网络

| 要求项 | 实现/证据 |
|---|---|
| 通信传输加密 | 生产建议 nginx 终止 TLS 1.2+（`nginx.conf` 可加证书）；`docker-compose.prod.yml` 服务间内网通信 |
| 网络架构分区分域 | Docker 网络隔离：frontend(80) / backend(8000) 对外，postgres/redis/es 不发布端口 |
| 可信验证 | JWT 签名 + bcrypt 口令哈希 |

## 2. 安全区域边界

| 要求项 | 实现/证据 |
|---|---|
| 边界访问控制 | nginx 仅暴露 80，`/api` 反代 backend；backend 仅绑定 `127.0.0.1:8000` |
| 入侵防范 | 生产前置 WAF/IPS（部署项）；OWASP ZAP 扫描清单见 `owasp-zap-checklist.md` |

## 3. 安全计算环境

| 要求项 | 实现/证据 |
|---|---|
| 身份鉴别 | 七级 RBAC + JWT；密码 bcrypt；无弱默认口令（seed 随机生成） |
| 访问控制 | `require_role`（7 角色）+ 客户行级隔离（`scope_filter`/`assert_scoped`）+ 字段级脱敏 |
| 安全审计 | `sys_audit_log`：before/after + IP + 时间（`audit_service.record`） |
| 数据完整性 | 敏感字段加密（`Outsourcing.nda` Fernet）；口令单向哈希 |
| 数据保密性 | 客户数据行级隔离 + 脱敏（电话/IP/金额）+ 前端水印 |

## 4. 安全管理中心

| 要求项 | 实现/证据 |
|---|---|
| 集中审计 | 审计统一落 `sys_audit_log`，可按资源/动作查询 |
| 系统管理 | 管理员/角色/权限/字典管理（`seed.py` + RBAC） |

## 5. 安全管理制度 / 机构 / 人员

| 要求项 | 实现/证据 |
|---|---|
| 制度 | 需配套安全管理制度文件（等保测评常规项，非代码交付） |
| 人员 | 管理员账号唯一 + 密码策略（登录后修改初始口令） |

## 6. 安全建设管理 / 安全运维管理

| 要求项 | 实现/证据 |
|---|---|
| 备份恢复 | `scripts/backup.sh`（pg_dump，0600 权限）/ `restore.sh`（回滚预案） |
| 变更管理 | 变更单 + 冲突检测 + 审计留痕（FR-14） |
| 漏洞与补丁 | 依赖清单 `requirements.txt`/`package.json`，建议 `pip-audit`/`npm audit` 定期扫描 |

## 7. 结论

系统在**身份鉴别、访问控制、安全审计、数据保密性/完整性**等计算环境控制项实现充分；**通信加密、边界入侵防范、制度/机构/人员、运维记录**需在部署与测评环节配合落地（TLS 证书、WAF、制度文件、运维台账）。可作为等保三级测评的软件侧自评依据。
