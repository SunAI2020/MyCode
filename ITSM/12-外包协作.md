# 步骤十二：外包协作（阶段四 · FR-09）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §4.8 / §6.2
> 范围：外包人员名册 + 外包任务 + 工作汇报 + 状态机（接单/验收/结算）。

## 1. 目标

实现外包管理：维护外包人员名册，内部工单发起外包、指派外包人员、记录保密协议与价格，外包汇报工作进展，走「接单 → 汇报 → 验收 → 结算」状态机；外包账号登录隔离后置（MVP 阶段外包人员以名册记录存在，不单独开受限账号）。

## 2. 表（3 张，依据 §6.2）

| 表 | 关键字段 |
|---|---|
| `outsource_user` 外包人员 | id, name, org, qualification, settle_type, permissions |
| `outsourcing` 外包任务 | id, work_order_id, type, outsource_user_id, price, nda, status |
| `outsourcing_report` 汇报 | id, outsourcing_id, report_date, progress, attachments, acceptance |

## 3. 业务规则

- **外包类型** `type`：能力 / 时间 / 资质。
- **外包人员** `outsource_user`：单位 `org`、资质 `qualification`、结算方式 `settle_type`（按次/按月/按工时）、权限范围 `permissions`。
- **外包任务** `outsourcing`：挂接 `work_order_id`，`nda` 保密协议、`price` 外包价格。
- **状态机** `status`：

```
待接单 → 已接单 / 已拒单
已接单 → 进行中 / 已拒单
进行中 → 待验收
待验收 → 已验收 / 进行中（验收不通过回退）
已验收 → 已结算
```

- **外包汇报** `outsourcing_report`：`progress` 进展、`attachments` 附件、`acceptance` 验收结论。

## 5. API

- `GET/POST /outsource-users`、`GET/PUT/DELETE /outsource-users/{id}`
- `GET/POST /outsourcings`、`GET/PUT/DELETE /outsourcings/{id}`
- `PUT /outsourcings/{id}/status` 状态流转（合法迁移校验）
- `GET/POST /outsourcing-reports?outsourcing_id=`、`GET/PUT/DELETE /outsourcing-reports/{id}`

## 6. 角色

外包域属内部流程，全接口平台侧角色：读/写 `sys_admin / sys_ops / ticket_mgr`，删除 `sys_admin / sys_ops`。
