0V6.0 升级说明（部署 · 安全 · 权限）

V6.0 在 V5.0 业务模型基础上完成三项基础设施级升级：(1) 数据库迁移 PostgreSQL，落实脱敏与加密传输；(2) 明确阿里云部署架构；(3) 建立七级 RBAC 权限模型。

V5.0 在 V4.0 基础上，将单一「客户→工单」模型升级为「客户多合同 → 合同多子项 → 子项多服务对象 → 定期工单」的多层级履约模型，并新增驻场、外包、内部任务三类工单来源。

0.1 模型层级对比

层级V4.0V5.0
客户1 客户1 客户 → N 合同（安全服务/安全运维/设备升级/购机/机房改造…）
合同❌ 无独立层1 合同 → N 合同子项（每个服务项独立频率/SLA/验收）
服务对象资产清单服务对象/系统（OA / XX / YY 系统）作为子项的绑定目标
服务项运维项目 + 服务频率合同子项 = 服务对象 + 运维项目 + 服务频率 + 验收标准
工单来源客户工单客户工单 / 驻场日报 / 内部任务 / 临时工作 / 外包工单
执行人单人/多人多人 按工作量比例分摊（换岗自动重算）

0.2 服务频率枚举扩展

频率单位由「次/天·周·月·年」扩展为：次/天 · 次/周 · 次/月 · 次/季度 · 次/半年 · 次/年 · 不定期。其中「不定期」对应应急处置、临时检查等无固定周期、按需派单的服务项。

1项目概述与总体架构

1.1 核心设计理念

以「合同 → 子项 → 工单」为主轴，统一承载客户合同的全部履约义务（定频服务、驻场服务、临时工作）、公司内部任务与外包协作，配合 AI 增强与流程自动化，形成可追溯、可量化、可考核、可自动化的完整交付闭环。

1.2 核心业务流程

客户/合同登记→合同子项（服务项+频率）→定期/临时工单生成→派单（智能+外包）→执行/驻场/整改→交付/验收→绩效（比例分摊）

5派单模块（含智能派单 + 换岗分摊）

项目经理指派执行人并定价；支持多人执行、按工作量比例分摊；中途换岗自动重算。

5.1 派单表单字段

字段类型说明
运维人员人员选择可单人/多人，多人设定工作量比例
工作量比例百分比多人协作时各自占比（合计 100%），用于绩效分摊
派单方式单选内部员工 / 外包（见第 9 章）
用户名称/资产/项目/频率关联继承自接单/合同子项
派单价格数字结算价格（用于绩效）
服务时间日期区间含 SLA
验收标准富文本验收要求

5.2 智能派单建议 AI

基于技能矩阵 + 当前负载 + 历史绩效与评价，推荐执行人并给出理由；项目经理可采纳或调整。

5.3 换岗 / 比例分摊 新增

换岗机制：人员中途调换时，原执行人登记已完成工作量比例，剩余工作量转给新执行人。系统自动按「各人实际承担时长 × 当日派单价」重算绩效分摊，确保换岗后工作量、结算、绩效精确归属到每个人。

6工单管理（核心）

工单是系统主线，统一承载客户工单、驻场日报、内部任务、外包工单，按「工单类型」区分。

6.1 工单类型

类型来源说明
客户工单合同子项 / 临时工作 / 报障面向客户的履约工单
驻场工单驻场服务日报驻场人员每日工作（第 7 章）
内部任务公司指派非客户工单，公司内部下发（第 8 章）
外包工单内部转派外包给外部人员（第 9 章）

6.2 工单状态机

待派单 → 已派单/进行中 → 计划中 ↔ 进行中 → 待验收 → 已完成
                ↓
          （SLA 预警 / 催办 / 升级）

6.3 状态流转规则（工作流）

状态流转通过工作流引擎（第 16 章）配置：整改通过 → 自动「待验收」；客户签字 → 自动「已关闭」+ 计绩效；外包验收通过 → 自动结算。

9.1 外包流程

9.2 外包管理字段

字段说明

11.1 四类核心交付报告

报告类型内容

12运维人员绩效考核（含换岗分摊）

绩效考核以加权公式自动计算，并支持多人协作 / 换岗按比例分摊。

12.1 绩效构成要素

要素说明
工作量完成工单/服务项数量、投入工时（按周期累计 × 个人比例）
派单价格该单派单价格（× 个人分摊比例）
工作质量管理者/安全专家打分（0.6~1.2）
用户评价客户满意度（0.8~1.2）

12.2 绩效计算公式（含分摊）

个人绩效 = Σ ( 工作量 × 派单价格 × 分摊比例 × 质量系数 × 评价系数 )
分摊比例 = 个人实际承担工作量 / 工单总工作量
换岗分摊：中途换岗时，按「各人实际投入时长/工作量」自动切分，换岗前后分别归属对应人员，结算与绩效精确到人。

12.3 统计维度

  • 按人员、客户、合同、合同子项、运维项目、时间（日/周/月/季/年）
  • 产出：个人报表、团队排名、成本毛利核算、外包成本纳入毛利核算

等级触发颜色

14.3 SLA 契约引擎

19权限、安全与基础技术选型

19.1 权限模型概述

系统采用七级 RBAC（基于角色的访问控制），由系统管理员统一分配各级权限；客户角色基于数据权限（客户级隔离）只能访问本客户数据。详细定义见第 20 章。

19.2 安全要求

  • 数据脱敏（联系方式、IP、密码）；HTTPS + 加密存储
  • 屏幕 + 打印水印；操作审计全留痕
  • 外包数据隔离：外包账号仅见指派工单，跨合同/跨客户数据强隔离
  • AI 数据本地化/脱敏，禁止敏感数据外流
  • 数据加密传输与静态加密（详见第 22 章）

19.3 技术选型

20七级权限模型（RBAC）新增

账号分级设置，由系统管理员统一分配各级权限。角色分为「平台侧」与「客户侧」两大类，客户侧角色受数据权限约束（仅见本客户合同与工单）。

20.1 七级角色定义

序号角色权限范围
1系统管理员最高管理权限：用户与角色管理、权限分配、系统配置、字典、审计、数据管理、全部数据可见
2系统运维人员系统日常运维：监控、备份/恢复、日志、服务启停、性能调优（不参与业务数据修改）
3工单管理人员接单、派单、催单、变更工单时限与服务人员、变更工单价格
4客服人员只读：查看仪表盘、工单进度、查看并联系服务人员；无权修改工单
5客户系统管理员查看/管理己方各合同下的工单进度；不可修改履约中的合同内容与合同价格
6客户服务管理人员查看己方工单；追加合同、追加系统、追加工单、安排临时工单、调整工单时限、服务质量评价、投诉/反馈问题
7工程师查看自己的工单；接收任务与催单提醒；按要求填写表单和工作日志

操作系统管理员系统运维工单管理客服客户管理员客户服务管理工程师

接单/派单/变更价格/时限✅—✅——（追加/调整时限）部分—
查看仪表盘/进度✅✅✅✅✅（本客户）✅（本客户）✅（本人）
修改工单内容✅—✅❌❌部分❌
执行工单 / 填单 / 日志——————✅

20.3 实现要点

  • RBAC 模型：用户 → 角色 → 权限；支持一个用户多角色
  • 数据权限（行级）：客户侧角色通过 customer_id 行级过滤，只能访问本客户数据
  • 字段级权限：合同价格、联系方式等敏感字段按角色控制可读/可写/脱敏
  • 价格限定：客户侧角色不可修改「履约中」合同的合同价格
  • 权限变更全审计留痕

21部署架构（阿里云）新增

系统整体部署在阿里云，采用经典的三层架构 + 云原生服务。结合安服业务对数据安全的高要求，核心数据全部落在国内 Region。

21.1 架构分层

层阿里云服务说明
接入层SLB + WAF + CDN负载均衡、Web 应用防火墙、静态加速
应用层ECS（云服务器）后端应用部署（可配合容器服务 ACK）
数据层RDS PostgreSQL（高可用）主备实例，自动备份 + 跨可用区
缓存Redis（云数据库 Redis 版）会话、缓存、队列
检索Elasticsearch全文检索（知识库）
对象存储OSS + CDN报告、附件、图片（SSE 加密）
安全安全组 + 云防火墙 + 等保网络隔离、入侵防护、合规

21.2 网络与高可用

  • VPC 专有网络：应用与数据库置于同一 VPC，数据库不暴露公网
  • 安全组最小开放：仅 80/443 对外，数据库端口仅内网可达
  • 高可用：RDS PG 主备 + ECS 多可用区 + SLB 健康检查
  • 证书：SSL/TLS 证书（阿里云证书服务）全链路 HTTPS

22数据安全（脱敏 + 加密）新增

依托 PostgreSQL 原生能力 + 应用层双重保障，实现数据脱敏与加密传输。

22.1 加密传输

  • 传输加密：全链路 TLS 1.2+（客户端 ↔ SLB ↔ 应用 ↔ RDS PG）
  • PG 连接加密：RDS PG 启用 SSL 强制连接（ssl=require）
  • 密钥托管：阿里云 KMS 统一管理加密密钥

22.2 数据脱敏方案

类型字段示例脱敏方式
联系方式甲方电话、联系人手机遮蔽中间位：138****1234
IP 地址资产 IP部分遮蔽：10.1.*.*
凭证/密码系统口令不可逆哈希存储，永不展示
金额合同/派单价低权限角色遮蔽或“0.0”占位

22.3 脱敏实现层级

  • 数据库层：postgresql_anonymizer（动态脱敏 DDM / 静态脱敏）或视图 + 掩码函数
  • 应用层：角色/字段级脱敏，按 RBAC 控制（如客服、外包人员看到脱敏后的联系方式）
  • 导出控制：导出报表、下载附件自动脱敏；屏幕/打印水印防拍照

22.4 静态加密

  • 敏感列加密：pgcrypto 或 KMS 信封加密（合同金额、联系方式可加密存储）
  • 存储加密：RDS PG 透明数据加密（TDE）+ OSS SSE 服务端加密
  • 备份加密：RDS 自动备份加密
