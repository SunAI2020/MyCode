# 步骤七：安全硬化与部署收尾（脱敏接线 / 工单号原子化 / 密钥外部化）

> 目的：闭环代码评审与安全审查点名的遗留项，让第一阶段达到「可交付、可上线」。

## 1. 脱敏接线

`core/security.py` 的 `mask_phone/mask_ip/mask_amount` 此前仅有定义、无调用点。本步骤新增：

- `mask_sensitive(data, scope)`：客户侧角色（`scope` 非 None）对 `contact`（电话）、`ip`、`amount/price/contract_price` 脱敏；平台侧角色（scope None）返回原文。
- `masked_page(result, scope)`：对分页结果 `items` 逐条脱敏。

应用于客户 / 合同 / 子项 / CI / 接单的列表与详情接口。

## 2. 工单号原子化

`utils/wo_no.py` 的 `WO-YYYY-NNNN` 先查最大再 +1，多 worker 并发会撞唯一约束。改用 PostgreSQL **事务级咨询锁**（`pg_advisory_xact_lock`）串行化取号；SQLite（测试）自动跳过。

## 3. 部署密钥外部化

| 项 | 改动 |
|---|---|
| `DATABASE_URL` | 改为**必填**（来自 `.env`/环境变量），移除含密码的硬编码默认 |
| `POSTGRES_PASSWORD` | docker-compose 改为 `${POSTGRES_PASSWORD:-itsm_password}`（env 注入，开发默认） |
| 管理员初始密码 | `seed.py` 读 `ADMIN_INITIAL_PASSWORD`，默认 `admin123` |
| `SECRET_KEY` | 上一步已改为随机默认；生产 `.env` 固定强随机值 |
