# 步骤 50 · 项目管理与多合同归档

## 目标

将「合同管理」在语义上提升为「项目管理」：把原「合同」实体作为「项目」，其下可归档多份
合同原件（格式可不同：PDF / Word / 图片 jpg/png），并支持导入时选择挂到已有项目或新建项目。

纯文案变更 + 两处功能扩展（多格式归档、挂载已有项目），**不改数据库表结构**（`contract`
表即「项目」，`contract_archive` 表即「合同原件」）。

## 关键决策（用户已确认）

1. **文件格式**：本次支持 PDF / Word(.docx) + 图片(jpg/png)，图片走 MinerU 云端 OCR；
   `.wps` 暂不支持（需 LibreOffice 转换，后续单独做）。
2. **导入归属**：导入时可选「新建项目」或挂到「已有项目」；挂到已有项目时仅归档原件，
   不重复生成服务对象 / 服务项目。

## 交互流程（变更点）

```
合同管理页「导入合同」按钮
  → 文件选择框（.pdf / .docx / .jpg / .jpeg / .png）
  → POST /contract-archives/upload
       1) 校验扩展名/大小 → 读字节 → 算 SHA-256
       2) 抽文本：PDF(pypdf/MinerU) / Word(python-docx) / 图片(MinerU OCR)
       3) LLM 抽取字段（未配置则规则降级/人工补录）
       4) Fernet 加密写盘；建 ContractArchive(status=待确认)
  → 弹窗：新增「目标项目」选择器（默认「新建项目」，可选已有项目）
  → 确认导入 → POST /contract-archives/{id}/confirm（body 增 contract_id）
       A) 带 contract_id：仅把原件归档到该项目（不建客户/服务对象/服务项目）
       B) 不带 contract_id：维持原逻辑（新建 客户→项目→服务对象→服务项目）
  → 返回项目 → 刷新列表
「查看合同」→ 弹窗列出该项目下全部合同原件（文件名/大小/下载），支持多份
```

## 后端改动

1. `services/contract_extract_service.py`
   - `extract_text` 增加图片分支（`.jpg/.jpeg/.png` → `_extract_image`）。
   - 抽出 `_extract_mineru(data, suffix)` 供 PDF 与图片共用；`_extract_pdf_mineru`
     改为调用它；新增 `_extract_image`。
2. `api/v1/contract_archives.py`
   - `upload_archive`：放行 `.jpg/.jpeg/.png`；MIME 映射 `image/jpeg` / `image/png`；
     `ALLOWED_INLINE_MIME` 增加 `image/jpeg` / `image/png`（图片可内联预览）。
   - `confirm_archive`：支持可选 `contract_id`——命中已有项目则仅归档原件，不重复生成链路。
3. `schemas/contract_archive.py`：`ContractArchiveConfirm` 增加 `contract_id: int | None`。

## 前端改动

1. `layouts/MainLayout.vue`：菜单「合同管理」→「项目管理」。
2. `views/Contracts.vue`：
   - tab / 按钮 / 弹窗标题 / 字段 / 列表列 文案替换（见术语映射）。
   - 隐藏 input `accept` 增加 `.jpg,.jpeg,.png`。
   - 导入弹窗新增「目标项目」选择器（`importTargetProjectId`，null=新建）。
   - `onConfirmImport` 携带 `contract_id`。
   - 「查看合同」改为弹窗列出该项目的多份原件，逐份下载。

## 不改动

- 数据库表结构 / 迁移（`contract_archive.contract_id` 本就一(项目)对多(原件)）。
- 后端 API 路径与其余模块（工单、周期、SLA 等）的引用。
- 前端路由 `path: 'contracts'` 与 `name: 'contracts'`。
