48-工单聚合模型（1 客户 + 多服务对象 + 多服务项目 + 多频次）

背景

主从链路（客户→合同→服务对象→服务项目）已就绪。本步骤实现工单聚合创建：

1 张工单 = 1 个客户 + 多个服务对象（可勾选默认全选）+ 多个服务项目（可勾选默认全选）+ 覆盖合同周期的多个频次（可勾选默认全选）

现有 WorkOrder 是单值引用，无法表达多选聚合。方案：保留单值字段（简单工单不受影响），新增 customer_id + 三张关联表表达聚合。

数据模型 models/work_order.py

  • WorkOrder 加 customer_id（FK→customer.id，nullable）。
  • 新增三张关联表：WorkOrderCi（服务对象）、WorkOrderItem（服务项目）、WorkOrderCycle（频次快照：cycle_no + 起止日期）。

迁移 alembic/versions/0020_work_order_aggregate.py

op.add_column 加 customer_id + Base.metadata.create_all 建三张新表。

隔离 core/deps.py

scope_filter 的 WorkOrder 分支提到 hasattr(customer_id) 之前，OR 里加 model.customer_id == scope。

Schema / API

  • WorkOrderOut 加 customer_id；新增 AggregateCycleIn / AggregateWorkOrderCreate / AggregatePreviewIn。
  • POST /work-orders/aggregate/preview：用 split_cycles 即时算各服务项目的频次（周期）列表。
  • POST /work-orders/aggregate：校验客户/服务对象/服务项目/频次归属一致 → 建工单 + 三张关联表。
  • GET /work-orders/{wid}/scope：返回聚合工单明细。

前端 views/WorkOrders.vue

「新增聚合工单」弹窗：客户下拉 → 服务对象复选（默认全选）→ 服务项目复选（默认全选）→ 频次复选（默认全选），级联加载。列表加「客户」列与「查看」明细。

验证

迁移 0020 → pytest 全绿 → 前端创建聚合工单 → 查看明细正确。
