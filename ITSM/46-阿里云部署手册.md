## 一、购买云服务器（ECS 或轻量应用服务器）

### 1.0 轻量应用服务器 vs ECS（先想清楚买哪个）

两种都可以跑 ITSM（本质都是 Linux + Docker）：

| 对比 | 轻量应用服务器 | ECS 云服务器 |
|---|---|---|
| 价格 | 便宜（几十元/月起） | 略贵 |
| 操作 | 简单，预装应用 | 灵活，自定义强 |
| 适用 | 个人 / 小规模 | 生产 / 可扩展 |
| 跑 ITSM | ✅ 能跑 | ✅ 能跑 |

**内存是唯一关键**（ITSM 要同时跑 PG + Redis + ES + 后端 + 前端）：

| 配置 | 结论 |
|---|---|
| 2 核 2G | ❌ 内存不足，会被杀 |
| 2 核 4G | ✅ 能跑（建议注释掉 ES，系统自动降级 SQL 检索，不影响核心功能） |
| 4 核 8G | ✅ 流畅，推荐 |

> 省钱技巧：2 核 4G 时，把 `docker-compose.prod.yml` 里 elasticsearch 服务注释掉即可，知识库检索自动降级为数据库 SQL 搜索。

### 1.0b 重置/重装系统时选什么镜像

**选「系统镜像」的纯净 Linux，不要选「应用镜像」（宝塔、WordPress 等）**——应用镜像预装不需要的软件，会和 ITSM 冲突、还占资源。

| 镜像类型 | 具体 | 结论 |
|---|---|---|
| ✅ 系统镜像 | Ubuntu 22.04 LTS（64 位） | 首选 |
| ✅ 系统镜像 | Debian 11/12 | 也行 |
| ⚠️ 系统镜像 | CentOS 7.9 / Stream 9 | 能跑但 CentOS 7 已停止维护 |
| ❌ 应用镜像 | 宝塔面板 / WordPress | 不要选 |

> 入口：控制台 → 重置系统 → 镜像 → 选「系统镜像」标签页 → Ubuntu 22.04。

### 1.1 选购参数（新手照填）

登录阿里云 → 控制台 → 云服务器 ECS → 创建实例，按下面选：

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 地域 | 国内（如华东1杭州） | 核心数据落国内 |
| 实例规格 | 2 核 4G（ecs.c7.large） | 最低，建议 4 核 8G |
| 镜像 | Ubuntu 22.04 64 位 | 用公共镜像 |
| 系统盘 | 高效云盘 40G | 数据量大可加数据盘 |
| 带宽 | 按量或 5M | 按固定带宽更省心 |
| 登录凭证 | 密钥对（推荐）或密码 | 密钥对更安全 |

### 1.2 关键：安全组（购买时/后配置）

ECS → 安全组 → 配置规则 → **入方向**，只放行以下端口：

| 端口 | 协议 | 用途 | 是否必须 |
|---|---|---|---|
| 22 | TCP | SSH 远程登录 | 必须 |
| 80 | TCP | HTTP（重定向到 HTTPS） | 建议 |
| 443 | TCP | HTTPS | 建议 |
| 8080 | TCP | 前端生产入口（nginx） | 必须（本方案） |

> **切勿放行**：5433（PostgreSQL）、6379（Redis）、9200（ES）、8000（后端）——数据库/后端只在服务器内网访问，对公网开放会被扫库攻击。

## 二、服务器操作系统初始配置

### 2.1 SSH 登录

```bash
# Windows 用 PowerShell / 终端，或 Xshell/Putty
ssh root@你的公网IP
```

### 2.2 更新系统 + 装基础工具 + 设时区

```bash
# 更新软件源与系统
apt update && apt upgrade -y

# 装常用工具
apt install -y curl wget git vim unzip net-tools

# 设置时区为上海（重要：影响定时工单时间）
timedatectl set-timezone Asia/Shanghai
date    # 确认时间正确

# 设置主机名
hostnamectl set-hostname itsm-server
```

### 2.3 创建普通用户（可选，更安全）

```bash
adduser itsm
usermod -aG sudo itsm
```

### 2.4 配置 Swap（2核4G 建议加，防内存不足被杀）

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 三、安装软件环境

### 3.1 安装 Docker + Docker Compose（一键）

```bash
curl -fsSL https://get.docker.com | bash
systemctl enable --now docker
docker --version        # 验证
docker compose version   # 验证
```

### 3.2 安装 Python 3

```bash
apt install -y python3 python3-pip python3-venv
python3 --version
```

### 3.3 安装 Node.js 20

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v
```

### 3.4 安装 Nginx（生产反向代理 + HTTPS）

```bash
apt install -y nginx
systemctl enable --now nginx
```

## 四、安装数据库

### 4.1 方式 A：自建容器数据库（本方案默认，用项目 docker-compose）

ITSM 自带 `docker-compose.prod.yml`，已含 PostgreSQL / Redis / Elasticsearch，**无需单独安装**，第五步上传代码后直接 `docker compose up` 即可拉起。

### 4.2 方式 B：阿里云 RDS PostgreSQL（生产推荐）

若要高可用 + 自动备份，用云数据库替代自建：

1. 控制台 → 云数据库 RDS → 创建 PostgreSQL 实例（版本 16，规格按需）。
2. 创建数据库 `itsm` 和账号 `itsm`。
3. **RDS 与 ECS 放同一 VPC**，RDS 白名单加入 ECS 内网 IP。
4. 把后端 `DATABASE_URL` 改成 RDS 内网地址：
   ```
   postgresql+psycopg://itsm:密码@rm-xxxxx.pg.rds.aliyuncs.com:5432/itsm
   ```

> 用 RDS 时，`docker-compose.prod.yml` 里的 postgres 服务可移除或保留但不用（后端通过 `DATABASE_URL` 直连 RDS）。

## 五、上传软件与导入数据

### 5.1 上传代码（二选一）

**方式 A：Git 拉取（推荐）**

```bash
cd /opt
git clone 你的仓库地址 ITSM
cd ITSM
```

**方式 B：本地 scp 上传**

```bash
# 在本地电脑执行（把整个 ITSM 目录传到服务器）
scp -r ITSM root@你的公网IP:/opt/
```

### 5.2 导入已有数据（从本地迁移到云端）

**① 本地导出数据库**

```bash
# 本地电脑，ITSM 目录下
bash scripts/backup.sh
# 生成 backups/itsm_时间戳.dump
```

**② 上传备份到服务器**

```bash
scp backups/itsm_xxx.dump root@你的公网IP:/opt/ITSM/backups/
```

**③ 服务器导入（在容器数据库启动后执行）**

```bash
cd /opt/ITSM
bash scripts/restore.sh backups/itsm_xxx.dump
```

### 5.3 全新初始化（无历史数据时）

```bash
cd /opt/ITSM
cp .env.production.example .env.production   # 填 SECRET_KEY、POSTGRES_PASSWORD
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec backend alembic upgrade head
docker compose -f docker-compose.prod.yml exec backend python -m app.db.seed
```

## 六、配置端口与安全组

### 6.1 安全组（控制台，最终防线）

入方向只留：**22、80、443、8080**。其余全部拒绝。

### 6.2 服务器防火墙（可选，第二道防线）

```bash
# Ubuntu 用 ufw
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8080/tcp
ufw enable
ufw status
```

### 6.3 端口对照（生产）

| 服务 | 端口 | 对外 |
|---|---|---|
| nginx 前端 | 8080 | ✅ 公网 |
| 后端 | 8000 | ❌ 仅内网 |
| PostgreSQL | 5432（容器内网） | ❌ |
| Redis | 6379 | ❌ |
| Elasticsearch | 9200 | ❌ |

## 七、配置协议

### 7.1 HTTP（先跑通）

启动生产环境后，直接访问 `http://你的公网IP:8080` 即可（nginx 前端）。

### 7.2 HTTPS（绑定域名 + 证书）

**① 域名解析**：域名控制台添加 A 记录，指向服务器公网 IP。

**② 申请免费证书（Let's Encrypt / certbot）**

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d itsm.example.com
# 按提示输入邮箱、同意条款，自动签发并配置 HTTPS
```

**③ 验证自动续期**

```bash
certbot renew --dry-run
```

### 7.3 自定义 nginx 反代（无域名、纯 IP + 端口时）

项目 `frontend/nginx.conf` 已内置：SPA 回退 + `/api` 反代 backend + `/uploads` 反代照片。

若需把 8080 换成 80，改 `docker-compose.prod.yml` 的 `WEB_PORT`。

## 八、一键部署生产环境

```bash
cd /opt/ITSM

# 1. 准备环境变量（务必填强随机 SECRET_KEY + 数据库密码）
cp .env.production.example .env.production
vim .env.production
#   SECRET_KEY=<用 python3 -c "import secrets;print(secrets.token_urlsafe(32))" 生成>
#   POSTGRES_PASSWORD=<强密码>

# 2. 构建并启动全部服务（backend + nginx 前端 + postgres + redis + es）
POSTGRES_PASSWORD=<同上强密码> docker compose -f docker-compose.prod.yml up -d --build

# 3. 等待数据库就绪后迁移 + 种子
docker compose -f docker-compose.prod.yml exec backend alembic upgrade head
docker compose -f docker-compose.prod.yml exec backend python -m app.db.seed

# 4. 访问 http://公网IP:8080
```

## 九、调试与验证

### 9.1 逐层验证

```bash
# 1. 容器是否都健康
docker compose -f docker-compose.prod.yml ps

# 2. 后端健康检查（服务器内执行）
curl http://localhost:8000/api/v1/health

# 3. 前端（nginx）是否响应
curl http://localhost:8080

# 4. 从公网验证（本地电脑执行）
curl http://公网IP:8080/api/v1/health
```

### 9.2 看日志

```bash
docker compose -f docker-compose.prod.yml logs -f backend      # 后端日志
docker compose -f docker-compose.prod.yml logs -f frontend     # nginx 日志
docker compose -f docker-compose.prod.yml logs -f postgres     # 数据库日志
```

### 9.3 登录验证

浏览器打开 `http://公网IP:8080`，账号 `admin`，密码为 seed 输出。

## 十、故障处置手册

| 现象 | 排查 | 解决 |
|---|---|---|
| 公网访问不通 | 安全组是否放行 8080；`curl localhost:8080` 是否通 | 放行端口 / 确认 nginx 容器 healthy |
| SSH 连不上 | 安全组 22 是否放行；IP 是否正确 | 放行 22；用正确公网 IP |
| 数据库连不上 | `docker compose ps` 看 postgres 是否 healthy；DATABASE_URL 是否对 | 等容器启动；检查密码/地址 |
| 后端 500 | `logs -f backend` 看报错 | 多为环境变量缺失（SECRET_KEY/DATABASE_URL） |
| seed 报「数据库不存在」 | 迁移未执行 | 先 `alembic upgrade head` 再 seed |
| 证书申请失败 | 域名未解析到服务器 | 先加 A 记录再 certbot |
| 内存不足被杀 | 2核4G 且无 swap | 加 swap；升级到 4核8G |
| ES 起不来 | 内存不够 | 调 `ES_JAVA_OPTS` 更小；或注释掉 ES 服务（系统自动降级） |
| Redis 起不来 | 端口/配置 | 系统自动降级内存缓存，不阻塞 |
| 端口被占用 | `ss -tlnp` 查占用 | 换端口或 kill 占用进程 |
| 时间不对 | 时区未设 | `timedatectl set-timezone Asia/Shanghai` |

### 通用排查三连

```bash
docker compose -f docker-compose.prod.yml ps              # 看状态
docker compose -f docker-compose.prod.yml logs -f <服务>   # 看日志
curl -v http://localhost:8000/api/v1/health               # 看接口
```
