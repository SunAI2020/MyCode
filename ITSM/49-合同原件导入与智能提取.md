# 步骤 49 · 合同原件导入与智能提取

## 目标

合同管理页新增「合同原件」导入能力：上传 PDF/Word 原件 → 加密存档 → 智能识别内容并
自动提取合同要素 → 弹窗表格展示、供人工修改补充 → 确认后自动生成「客户 → 合同 →
服务对象 → 服务项目」全链路。

## 关键决策（用户已确认）

1. **文件存储**：原件用 Fernet 对称加密后存本地磁盘 `uploads/contracts/`，数据库只存
   元数据（哈希 / 加密文件名 / 大小 / 提取字段），不存 BLOB。
2. **确认后落地**：自动生成全链路（客户 → 合同 → 服务对象 → 服务项目）。

## 交互流程

```
合同管理页「导入存档」按钮
  → 打开文件选择框（.pdf / .docx）
  → POST /contract-archives/upload（multipart）
       1) 校验类型/大小 → 读字节 → 算 SHA-256
       2) 抽文本（pypdf / python-docx）
       3) LLM 抽取 14 个字段（未配置 LLM 则降级为纯文本 + 空字段）
       4) 文件 Fernet 加密写盘；建 ContractArchive(status=待确认)
  → 返回 archive_id + 抽取字段 → 前端弹窗「表格形式」展示，可编辑
  → 用户修改补充后点「确认导入」
  → POST /contract-archives/{id}/confirm（body = 编辑后的字段）
       1) 解析/匹配客户（客户ID 或按名称精确匹配，否则新建）
       2) 建 Contract（标量字段）
       3) 建 CmdbCi（服务对象列表）
       4) 建 ContractItem（服务项目 + 频次 + 价格，关联服务对象）
       5) 归档行置 status=已确认，绑定 contract_id / customer_id
  → 返回新建合同 → 前端刷新列表
```

## 抽取字段（14 项）

| 字段 | 落点 | 说明 |
|---|---|---|
| 客户名称 | Customer.name | 精确匹配复用，否则新建 |
| 合同号 | Contract.no | |
| 合同签署日期 | Contract.sign_date（**新增列**） | |
| 合同金额 | Contract.amount | 客户侧脱敏 |
| 服务对象 | CmdbCi（多） | 名称列表 |
| 服务项目 | ContractItem.project（多） | 每条含 project/frequency/unit/price |
| 服务频次 | ContractItem.frequency + unit | 随服务项目 |
| 是否驻场服务 | Contract.has_onsite | bool |
| 人员要求 | Contract.staff_requirement（**新增列**） | |
| 服务期限 | Contract.start_date/end_date | 从「起 至 止」文本解析，解析失败留空并保留原文 |
| 验收标准 | Contract.accept_standard（**新增列**） | |
| 交付文档 | Contract.delivery_docs（**新增列**） | |
| 验收报告格式 | Contract.acceptance_report_format（**新增列**） | |

LLM 返回 JSON 契约（服务项目可选 `service_object` 关联服务对象，未关联则归到首个服务对象，
无服务对象则建「默认服务对象」）：

```json

  "customer_name": "XX公司",
  "contract_no": "HT-2026-001",
  "sign_date": "2026-01-01",
  "amount": 120000,
  "has_onsite": true,
  "service_period": "2026-01-01 至 2026-12-31",
  "staff_requirement": "2名驻场工程师",
  "accept_standard": "按SLA考核",
  "delivery_docs": "月度报告、年度报告",
  "acceptance_report_format": "PDF验收报告",
  "service_objects": ["OA系统", "数据库服务器"],
  "service_items": [
    {"project": "漏洞扫描", "frequency": 1, "unit": "月", "price": 5000, "service_object": "OA系统"}
  ]

```

## 变更内容

### 后端

1. **依赖** `requirements.txt`：新增 `pypdf`（PDF 抽文本）、`python-docx`（.docx 抽文本）。
2. **加密** `app/services/archive_crypto.py`（新）：
   - 密钥来自持久化密钥文件 `uploads/contracts/.archive.key`（首次生成、跨重启稳定，
     避免 `SECRET_KEY` 每次启动随机导致已存文件不可解密）；可选环境变量
     `ARCHIVE_ENC_KEY` 覆盖。
   - `encrypt_bytes / decrypt_bytes`（Fernet）。
3. **模型** `app/models/contract.py`：
   - `Contract` 新增 5 列：`sign_date`(Date)、`staff_requirement`(Text)、
     `accept_standard`(Text)、`delivery_docs`(Text)、`acceptance_report_format`(Text)。
   - 新增 `ContractArchive`（表 `contract_archive`）：contract_id、customer_id、
     original_filename、stored_name、file_hash、file_size、mime_type、
     extracted(Text, JSON)、status、created_by、created_at。
4. **抽取服务** `app/services/contract_extract_service.py`（新）：
   `extract_text` / `extract_contract_fields`（LLM+降级）/ `parse_period`。
5. **API** `app/api/v1/contract_archives.py`（新）：
   - `POST /contract-archives/upload`：上传→抽文本→LLM 抽取→加密写盘→建待确认行。
   - `POST /contract-archives/{id}/confirm`：按编辑后字段生成全链路 + 归档。
   - `GET /contract-archives`：列表（行级隔离 + 金额脱敏）。
   - `GET /contract-archives/{id}/download`：解密下载原件。
6. **迁移** `alembic/versions/0022_contract_archive.py`。
7. **路由注册** `app/api/v1/router.py`。

## 安全说明

- **加密传输**：生产由 nginx 终止 TLS；开发环境前端↔后端为 localhost HTTP。文件落盘前
  已用 Fernet 加密（**传输+静态双重**，静态加密覆盖开发/直连场景）。
- **脱敏**：提取结果中的金额等敏感字段对客户侧角色按既有 `mask_sensitive` 规则脱敏。
- **行级隔离**：归档按 `customer_id` 隔离；待确认行（customer_id 为空）仅在本次上传会话
  可见，不进入客户侧列表。
- **类型/大小**：仅 `.pdf`/`.docx`，上限 20MB；`.doc` 提示另存为 `.docx`。
