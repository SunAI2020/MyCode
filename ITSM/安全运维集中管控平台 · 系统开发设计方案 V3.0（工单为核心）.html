1项目概述与总体架构

1.1 核心设计理念

本版本将系统重心从「风险台账」重构为「以工单为核心」——一切业务围绕工单展开：接单、派单、跟踪、发现问题、整改、交付、绩效考核，全部挂接在工单主线上，形成可追溯、可量化、可考核的闭环。

1.2 核心业务流程

接单→派单→工单执行跟踪→发现问题→整改（多轮）→整改效果→项目交付→绩效考核

1.3 模块划分（九大核心模块）

模块说明
① 接单模块商务/销售录入客户需求，沉淀合同与验收标准
② 派单模块项目经理指派运维人员，确定派单价格与服务时间
③ 工单管理（核心）工单全生命周期跟踪、状态流转、超时提醒
④ 问题发现与整改问题录入、多轮整改、效果确认
⑤ 项目交付四类报告（运维/问题/整改/验收）
⑥ 绩效考核工作量 + 价格 + 质量 + 评价 加权计算
⑦ 客户与资产管理客户档案、资产清单、运维项目
⑧ 报告中心分客户/分项目归档
⑨ 系统管理权限、字典、审计、水印、脱敏

2接单模块

接单是业务的起点，由商务/销售人员（或客户门户自助）录入客户需求，生成待派的工单。

2.1 接单表单字段

字段类型说明
来源单选客户报障 / 商务拓展 / 巡检发现 / 安全事件 / 客户续约
用户名称文本/关联客户名称（关联客户档案）
资产名称关联客户运维系统/资产（关联资产清单）
运维项目下拉选择漏洞扫描/渗透测试/应急演练/安全加固/安全培训/代码审计/基线核查/安全巡检/安全评估/应急处置/重保值守/攻防演练/安全防护/设备巡检/等级保护测评/故障排查
合同价格数字合同约定金额（元）
甲方联系人文本客户对接人姓名
甲方联系电话电话客户联系电话（脱敏展示）
服务时间日期区间起止日期
验收标准富文本与客户约定的验收条件
说明：接单完成后生成一条「待派单」状态的工单，携带合同价格、验收标准等原始信息，作为后续派单与验收的依据。

3派单模块

项目经理在接单基础上，指派具体运维人员并确定派单价格与服务时间。

3.1 派单表单字段

字段类型说明
运维人员人员选择指派执行人（可单人/多人）
用户名称关联客户名称（继承自接单）
资产名称关联运维资产（继承自接单）
运维项目下拉选择同接单的运维项目枚举
派单价格数字派给运维人员的结算价格（用于绩效）
服务时间日期区间起止日期（含 SLA 时限）
验收标准富文本对该次派单的验收要求
关键点：「合同价格」（接单）与「派单价格」（派单）分离，二者差额即项目毛利；派单价格直接进入绩效加权计算。

4工单管理（核心）

工单是系统主线，统一承载接单、派单、执行、跟踪、整改、交付、考核。

4.1 工单状态机

待派单 → 已派单/进行中 → 计划中 ↔ 进行中 → 待验收 → 已完成
                ↓
          （超时预警/催办）

4.2 工单状态定义（含进度细分）

状态说明
计划中已排期未开始
正在进行 XX年第X次·漏洞扫描执行中的具体服务项（动态拼接服务名）
正在进行 XX年第X次·渗透测试同上，按运维项目动态生成
…（其余 14 类项目）故障排查 等，均显示「正在进行 + 项目名」
已完成服务执行完毕
已交付 / 已验收 / 已关闭交付报告、客户验收、结案
动态状态：工单的「进行中」状态动态拼接服务项名称（如「正在进行 2026 年第 3 次·漏洞扫描」），而非固定枚举，便于一眼看清当前在做什么。

5问题发现与整改闭环

5.1 发现问题

运维人员在执行工单过程中记录发现的问题，挂接在工单之下：问题类型、严重等级、描述、截图/日志附件。

5.2 整改情况（多轮）

整改状态说明
第 1 轮整改中…首轮整改进行中
第 N 轮整改中…整改不通过后的后续轮次
整改完成本轮整改完成，待验证效果
整改不通过效果未达标，自动发起下一轮

5.3 整改效果

  • 效果描述采用具体成果式：XX 漏洞已修复 XX 问题已修复
  • 效果验证三态：通过 / 不通过 / 部分完成继续整改

6项目交付

工单完成后，产出标准化交付物，统一归入报告中心。

6.1 四类核心交付报告

报告类型内容
运维报告本次运维执行过程、服务内容汇总
发现问题报告执行中发现的全部问题清单
整改报告多轮整改过程、措施、效果
验收报告验收标准、验收结论、客户签字

另支持：漏洞扫描报告、渗透测试报告、应急演练报告、安全评估报告、基线核查报告、等保测评报告等按项目类型生成。

7运维人员绩效考核

绩效考核以加权公式自动计算每个运维人员的绩效分。

7.1 绩效构成要素

要素说明
工作量完成工单/服务项的数量、投入工时
派单价格该单的派单价格（结算金额）
工作质量管理者/安全专家打分（如 0.6~1.2 系数）
用户评价客户满意度评价（如 0.8~1.2 系数）

7.2 绩效计算公式

绩效分 = Σ ( 工作量 × 派单价格 × 工作质量系数 × 用户评价系数 )
说明：工作量与派单价格构成「创收基数」，工作质量与用户评价作为乘数系数调节，既鼓励多干活，又保证干得漂亮、客户满意。

7.3 统计维度

  • 按人员、按客户、按运维项目、按时间（日/周/月/季/年）
  • 产出：个人绩效报表、团队排名、成本毛利核算依据

8工单进度与超时提醒

8.1 提醒机制

  • 工单设置 SLA 时限（服务时间截止）
  • 即将超时（如剩余 24h / 4h）时，系统自动触发提醒
  • 提醒对象：运维人员（执行人）+ 管理员（项目经理）

8.2 提醒渠道

渠道说明
站内消息系统消息中心红点提醒
移动端推送小程序/App 推送通知
短信/企微/飞书/钉钉可选第三方渠道

8.3 提醒等级

等级触发条件颜色
预警剩余 24h黄色预警
紧急剩余 4h红色紧急
已超时超过截止时间超时告警 + 升级通知管理员

9数据模型设计

9.1 实体关系（工单为核心）

接单(order_receive) 1—1 工单(work_order) 1—1 派单(order_dispatch)
工单 1—N 问题(issue) → 1—N 整改(rectification) → 1—N 整改记录(多轮)
工单 1—N 交付物(delivery)
工单/问题/整改/交付 → 绩效(performance)
客户 1—N 项目/资产 → 关联工单

9.2 核心表清单

表名关键字段
order_receive 接单id, source, customer_id, asset_id, project(运维项目), contract_price, contact_name, contact_phone, service_start/end, accept_standard
order_dispatch 派单id, work_order_id, engineer_id, customer_id, asset_id, project, dispatch_price, service_start/end, accept_standard
work_order 工单id, no, receive_id, dispatch_id, customer_id, asset_id, project, status(计划中/进行中xx/已完成...), sla_deadline, progress
issue 问题id, work_order_id, type, level, description, attachments
rectification 整改id, issue_id, plan, deadline, assignee, status
rectification_record 整改记录id, rectification_id, round_no, action, executor, effect(通过/不通过/部分完成)
delivery 交付id, work_order_id, customer_id, report_type(运维/问题/整改/验收), report_id, sign
performance 绩效id, user_id, work_order_id, workload, dispatch_price, quality_score, customer_score, perf_score
reminder 提醒id, work_order_id, level, to_user_id, channel, sent_at
customer/asset_system客户档案 / 资产清单

10权限、安全与技术选型

10.1 角色权限

角色权限
商务/销售接单录入
项目经理/管理员派单、工单跟踪、绩效审核、超时督办
运维人员执行工单、问题录入、整改、打卡
安全专家质量打分、整改审核、验收
客户评价、验收签字、查看本客户报告

10.2 安全要求

  • 数据脱敏（联系方式、IP、密码等）
  • 全程 HTTPS 加密传输，敏感数据加密存储
  • 屏幕 + 打印隐藏数字水印，防拍照防截屏
  • 操作审计日志全留痕

10.3 技术选型

层次推荐
前端Vue3 + Ant Design / Element Plus
移动端uni-app / 微信小程序（GPS+拍照+推送）
后端Java Spring Boot / Go / Python FastAPI
数据库MySQL / PostgreSQL
缓存/检索Redis + Elasticsearch
消息提醒站内 + 移动推送 + 企微/飞书/钉钉/短信
对象存储MinIO / OSS（加密）

11实施路线

阶段内容周期（估）
一期客户/资产管理 + 接单 + 派单 + 工单状态跟踪 + 超时提醒8-10 周
二期问题发现 + 多轮整改 + 整改效果4-6 周
三期项目交付（四类报告）+ 报告中心 + 客户评价4-6 周
四期绩效考核加权计算 + 移动端 + 安全水印/脱敏 + 数据看板4-6 周
MVP 建议：一期先跑通「接单→派单→工单跟踪→超时提醒」，这是新架构的主干闭环，快速验证后逐步叠加整改、交付、绩效。
