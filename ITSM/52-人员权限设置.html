52-人员权限设置（角色权限矩阵 · 落地生效）

需求：人员管理页面增加「人员权限设置」
落地形态：角色权限矩阵（角色→权限点）+ 真正参与接口/菜单鉴权（落地生效）
性质：设计文档（本文档先行，评审通过后再编码）

一、背景与现状

平台按「七级 RBAC」设计（见《IT运维集中管控平台_软件设计方案》§5.1），数据模型早已预留 sys_permission（权限点）与 sys_role_permission（角色→权限点）两张表， 但当前实现只走到「用户 → 角色」一层：

环节现状
权限点表 sys_permission空表，零数据、零 API、零使用
角色权限表 sys_role_permission空表，零使用
后端接口鉴权写接口 require_role("sys_admin", ...) 硬编码角色白名单
前端菜单裁剪MainLayout.vue 的 MENU_ITEMS 硬编码 roles 白名单
前端按钮裁剪几乎为零（仅 Contracts/WorkOrders 各一两处硬编码）
读接口大量「仅登录」+ 行级隔离（customer_scope_of）兜底

缺口：角色是权限的唯一载体，无法按「权限点」粒度配置；权限点不参与鉴权，改动需改代码。

二、设计目标

  1. 补齐 RBAC 缺失的「权限点」一环：权限点可枚举、可配置。
  2. 落地生效：写接口按权限点鉴权、菜单按权限点裁剪。
  3. 零行为变化：角色默认权限矩阵逐条翻译现有白名单。
  4. 最小侵入：读接口保持现状，无独立页面的模块保持现状。

五、后端改造

5.1 依赖新增（app/core/deps.py）

  • permission_codes_of(user, db)：user → roles → sys_role_permission → sys_permission.code。
  • require_permission(*codes)：仿 require_role；sys_admin 短路放行，否则权限点集合求交集，空则 403。

5.2 写接口鉴权改造（require_role → require_permission）

users / customers / contracts(+archives) / work_orders / issues / compliance / kb / workflows / services(sla) / approvals 的写接口分别改为对应 xxx:write / xxx:delete 权限点。

保持现状：所有 GET 读接口、工单状态流转（五角色）、外包/交付/绩效/驻场/变更/升级/打卡/上传/AI/日历/门户。

5.3 权限管理 API（新增 app/api/v1/permissions.py）

  • GET /permissions 权限点清单
  • GET /roles 角色清单
  • GET /roles/{code}/permissions 角色权限点
  • PUT /roles/{code}/permissions 更新角色权限矩阵（仅 role:write；sys_admin 不可移除 role:write 防自锁；落审计）

六、种子与迁移

  • app/db/seed.py：新增 28 权限点 + 角色默认矩阵（幂等）。
  • alembic/versions/0029_permission_tables.py：create_all 幂等补建两张权限表（防旧库缺失）。

七、前端改造

  • auth 接口 UserOut 增 permissions；/auth/me、/auth/login 返回。
  • api/index.ts：+ listPermissions / listRoles / getRolePermissions / updateRolePermissions。
  • stores/auth.ts：缓存 permissions，新增 hasPermission(code)。
  • MainLayout.vue：菜单由 roles 白名单改为按 menu 权限点裁剪。
  • Personnel.vue：新增「权限设置」抽屉/弹窗（角色×权限点矩阵，勾选保存）。

八、按钮级裁剪（后续阶段）

本批落地「写接口 + 菜单」两层强制生效；按钮级裁剪（8 页面 40+ 写按钮）复用 hasPermission 后续补齐。

九、验证

  • backend/tests/test_permissions.py：种子幂等、require_permission 鉴权、矩阵更新、审计、自锁防护。
  • 回归 pytest backend/tests；前端 npm run build。
  • 手动：admin → 人员管理 → 权限设置 → 改角色权限 → 该角色账号登录验证菜单/写接口变化。
