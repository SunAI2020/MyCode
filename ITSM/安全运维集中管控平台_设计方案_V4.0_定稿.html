1项目概述与总体架构

1.1 核心设计理念

本版本将系统重心从「风险台账」重构为「以工单为核心」——一切业务围绕工单展开，并以 AI 增强 + 流程自动化 提效，形成可追溯、可量化、可考核、可自动化的闭环。

1.2 核心业务流程

接单→派单→工单执行跟踪→发现问题→整改（多轮）→整改效果→项目交付→绩效考核
定期工单自动生成→服务启动提醒→SLA 分级预警→AI 智能辅助→自动化流转

1.3 模块划分（十四大核心模块）

模块说明
① 接单模块商务/销售录入客户需求，沉淀合同、验收标准、服务频率
② 派单模块项目经理指派 + 智能派单建议、定价、服务时间/频率
③ 工单管理（核心）工单全生命周期、状态机、超时/SLA 跟踪
④ 问题发现与整改问题录入、多轮整改、效果确认
⑤ 项目交付四类报告 + 各类专项报告
⑥ 绩效考核工作量 + 价格 + 质量 + 评价 加权计算
⑦ 客户与资产管理客户档案、资产清单、资产依赖
⑧ 报告中心分客户/分项目归档、数据看板
⑨ 服务频率与定期工单升级周期拆分、定期工单自动生成
⑩ 服务提醒与 SLA 引擎升级服务启动提醒、分级预警、SLA 契约 + 升级链
⑪ AI 智能增强新增智能分类、智能派单建议、工单摘要、相似推荐
⑫ 工作流编排新增审批流、状态流转规则、自动化动作
⑬ 知识库与自助门户新增知识库、自助报障、自助查询
⑭ 系统管理权限、字典、审计、水印、脱敏

2接单模块

接单是业务的起点，由商务/销售人员（或客户门户自助）录入客户需求，生成待派的工单。

2.1 接单表单字段

字段类型说明
来源单选客户报障 / 商务拓展 / 巡检发现 / 安全事件 / 客户续约
用户名称文本/关联客户名称（关联客户档案）
资产名称关联客户运维系统/资产（关联资产清单）
运维项目下拉选择漏洞扫描/渗透测试/应急演练/安全加固/安全培训/代码审计/基线核查/安全巡检/安全评估/应急处置/重保值守/攻防演练/安全防护/设备巡检/等级保护测评/故障排查
服务频率数字 + 单位如「4 次/月」「1 次/周」「52 次/年」，定义服务频次，作为定期工单生成与提醒基准
合同价格数字合同约定金额（元）
甲方联系人文本客户对接人姓名
甲方联系电话电话客户联系电话（脱敏展示）
服务时间日期区间起止日期
验收标准富文本与客户约定的验收条件
说明：接单完成后生成一条「待派单」状态的工单，携带合同价格、验收标准、服务频率等原始信息。接单时 AI 智能分类 可依据描述自动推荐运维项目与优先级。

3派单模块（含智能派单）

项目经理在接单基础上，指派具体运维人员并确定派单价格、服务时间与服务频率；系统提供智能派单建议。

3.1 派单表单字段

字段类型说明
运维人员人员选择指派执行人（可单人/多人，支持智能推荐）
用户名称关联客户名称（继承自接单）
资产名称关联运维资产（继承自接单）
运维项目下拉选择同接单的运维项目枚举
服务频率数字 + 单位继承自接单，项目经理可调整
派单价格数字派给运维人员的结算价格（用于绩效）
服务时间日期区间起止日期（含 SLA 时限）
验收标准富文本对该次派单的验收要求

3.2 智能派单建议 AI

系统根据运维人员的技能矩阵（擅长的运维项目、行业、客户）、当前负载（在办工单数、工时）、历史绩效与客户评价，自动推荐最合适的执行人并给出理由，项目经理可一键采纳或人工调整。

关键点：「合同价格」与「派单价格」分离（差额即毛利）；智能派单规则作为辅助建议，最终派单决策仍由项目经理确认，保证可控。

4工单管理（核心）

工单是系统主线，统一承载接单、派单、执行、跟踪、整改、交付、考核。

4.1 工单状态机

待派单 → 已派单/进行中 → 计划中 ↔ 进行中 → 待验收 → 已完成
                ↓
          （SLA 预警 / 催办 / 升级）

4.2 工单状态定义（含进度细分）

状态说明
计划中已排期未开始
正在进行 XX年第X次·漏洞扫描执行中的具体服务项（动态拼接服务名 + 当前次数）
正在进行 XX年第X次·渗透测试同上，按运维项目动态生成
…（其余 14 类项目）故障排查 等，均显示「正在进行 + 项目名」
已完成服务执行完毕
已交付 / 已验收 / 已关闭交付报告、客户验收、结案

4.3 状态流转规则（工作流） 自动化

状态流转通过工作流引擎（第 11 章）配置：如「整改全部通过 → 自动进入待验收」「客户验收签字 → 自动关闭并计入绩效」，减少人工流转。

5问题发现与整改闭环

5.1 发现问题

运维人员在执行工单过程中记录发现的问题，挂接在工单之下：问题类型、严重等级、描述、截图/日志附件。系统提供问题相似度推荐，自动关联历史同类问题及既往整改方案。

5.2 整改情况（多轮）

整改状态说明
第 1 轮整改中…首轮整改进行中
第 N 轮整改中…整改不通过后的后续轮次
整改完成本轮整改完成，待验证效果
整改不通过效果未达标，自动发起下一轮

5.3 整改效果

  • 效果描述采用具体成果式：XX 漏洞已修复 XX 问题已修复
  • 效果验证三态：通过 / 不通过 / 部分完成继续整改

6项目交付

工单完成后，产出标准化交付物，统一归入报告中心。

6.1 四类核心交付报告

报告类型内容
运维报告本次运维执行过程、服务内容汇总
发现问题报告执行中发现的全部问题清单
整改报告多轮整改过程、措施、效果
验收报告验收标准、验收结论、客户签字

另支持：漏洞扫描报告、渗透测试报告、应急演练报告、安全评估报告、基线核查报告、等保测评报告等按项目类型生成。报告可由 AI 摘要 辅助撰写草稿。

7运维人员绩效考核

绩效考核以加权公式自动计算每个运维人员的绩效分。

7.1 绩效构成要素

要素说明
工作量完成工单/服务项的数量、投入工时（按服务周期次数累计）
派单价格该单的派单价格（结算金额）
工作质量管理者/安全专家打分（如 0.6~1.2 系数）
用户评价客户满意度评价（如 0.8~1.2 系数）

7.2 绩效计算公式

绩效分 = Σ ( 工作量 × 派单价格 × 工作质量系数 × 用户评价系数 )
说明：工作量与派单价格构成「创收基数」；按服务频率拆分后，每次服务周期单独计入工作量。可扩展「客户续约率/回款率」等经营指标。

7.3 统计维度

  • 按人员、按客户、按运维项目、按时间（日/周/月/季/年）
  • 产出：个人绩效报表、团队排名、成本毛利核算依据

8服务频率与定期工单 升级

依据接单/派单中的服务频率，将服务时间自动拆分为若干服务周期，并自动生成定期（循环）工单，杜绝漏单、忘单。

8.1 周期拆分规则

频率示例拆分逻辑
X 次/周2 次/周每周均匀生成 2 个服务周期（如周一、周四）
X 次/月4 次/月每月均匀生成 4 个（如每周 1 次）
X 次/年4 次/年每季度 1 次
X 次/天1 次/天每个工作日/自然日 1 次
定期工单：系统按周期自动生成对应工单（带「第 X 次」编号），而非仅靠人工记忆；周期工单继承原工单的客户、资产、项目、派单信息与执行人。

8.2 周期工单生成时机

  • 进入周期前 N 天（可配，默认 1 天）预生成 计划中 工单
  • 周期开始时自动置为 进行中 并触发启动提醒

9服务提醒与 SLA 契约引擎 升级

9.1 服务启动提醒

触发内容
进入本次服务周期时「第 X 次服务已启动，请及时处理！」（如「第 3 次服务已启动，请及时处理！·漏洞扫描」）

9.2 服务周期分级预警

预警基准：本次服务周期结束日。

等级触发条件颜色
黄色预警距周期结束日 ≤ 7 天（1 周）黄色
橙色预警距周期结束日 ≤ 3 天橙色
红色紧急距周期结束日 ≤ 1 天红色

9.3 SLA 契约引擎 升级

在简单超时提醒基础上，升级为契约化 SLA：

  • 多级 SLA：按客户等级（金牌/银牌/普通）或项目紧急度定义不同响应/解决时限
  • 工作日历：支持工作日/节假日历，SLA 计时自动跳过非工作时段
  • 升级链（Escalation）：超时自动逐级上报——执行人 → 项目经理 → 部门负责人，避免无人响应

9.4 提醒对象与渠道

  • 提醒对象：运维人员（执行人）+ 管理员（项目经理）；超时升级时逐级追加
  • 渠道：站内消息 / 移动端推送 / 短信·企微·飞书·钉钉
两类提醒区分：「服务频率提醒」管周期性服务的按次启动与周期截止；「SLA 超时」管工单整体时限，含升级链。二者互补、可同时触发。

10AI 智能增强 新增

对标 Freshservice Freddy AI / ServiceNow Now Assist，引入轻量 AI 能力（可接本地 LLM 或云 API），提升效率。

10.1 AI 能力清单

能力应用场景
智能分类根据接单/报障描述自动推荐运维项目、优先级、严重等级
智能派单建议基于技能矩阵 + 负载 + 绩效推荐执行人（见 3.2）
工单摘要自动生成工单执行过程摘要，辅助交付报告
问题相似推荐新问题自动匹配历史相似问题与整改方案（见 5.1）
知识问答运维人员/客户自助问答（依托知识库 RAG）
落地原则：AI 均以「建议 + 人工确认」方式落地，不替代关键决策；敏感数据（渗透测试细节、漏洞详情）走本地化/脱敏 LLM，满足数据安全要求。

11工作流编排与审批 新增

对标 ServiceNow Flow / ConnectWise 自动化，引入轻量工作流引擎，让状态流转、审批、自动化动作可配置、可追溯。

11.1 典型流程

流程说明
审批流派单价格超阈值需上级审批；报告交付客户验收审批
状态自动流转整改全部通过 → 自动「待验收」；客户签字 → 自动「已关闭」+ 计绩效
自动化动作超时自动升级、周期工单自动生成、提醒自动发送

11.2 实现

  • 规则引擎：定义「事件 + 条件 + 动作」三段式规则，可视化配置
  • 全量留痕：每次自动流转记录触发规则、时间、操作人（系统/人员）

12知识库与自助门户 新增

沉淀运维经验，提供客户与内部员工自助能力，降低重复工单。

12.1 知识库

  • 沉淀：漏洞库、整改方案库、常见故障排查手册、标准操作流程（SOP）
  • 检索：全文检索 + RAG 问答，运维人员与客户可按权限访问
  • 闭环：高频问题 → 自动沉淀为知识条目 → 供下次自助解决

12.2 自助门户

  • 客户自助报障（自动生成接单工单）、自助查询工单进度、下载报告
  • 内部员工自助查知识、自助打卡核对工作量

接单(order_receive) 1—1 工单(work_order) 1—1 派单(order_dispatch)
工单 1—N 服务周期(service_cycle) → 1—N 定期工单 → 1—N 服务提醒(service_reminder)
工单 1—N 问题(issue) → 1—N 整改(rectification) → 1—N 整改记录(多轮)
工单 1—N 交付物(delivery)

工单/问题/整改/交付 → 绩效(performance)
客户 1—N 项目/资产 → 关联工单

14.2 安全要求

  • 数据脱敏（联系方式、IP、密码等）；全程 HTTPS，敏感数据加密存储
  • 屏幕 + 打印隐藏数字水印，防拍照防截屏
  • 操作审计日志全留痕（含 AI 建议与自动动作）
  • AI 数据本地化/脱敏，禁止敏感数据外流
