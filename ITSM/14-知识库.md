# 步骤十四：知识库（阶段四 · FR-19）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §4.18 / §6.2
> 范围：知识条目 CRUD + 分类 + 全文检索 + 浏览计数（RAG 问答后置）。

## 1. 目标

实现知识库：沉淀漏洞、整改方案、故障手册、SOP、驻场操作规范等条目，支持分类检索与关键词全文检索；浏览计数支撑「高频问题 → 知识条目 → 自助解决」闭环。RAG 问答与自助门户服务目录后置（阶段五）。

## 2. 表（1 张，依据 §6.2）

`kb_article` 知识条目：`id, title, category, content, tags, status, author_id, view_count, created_at, updated_at`

## 3. 业务规则

- **分类** `category`：漏洞 / 整改方案 / 故障手册 / SOP / 驻场规范 / 其他。
- **全文检索**：`q` 关键词对 `title` / `content` 不区分大小写子串匹配（MVP 用 ilike，跨库兼容；Elasticsearch 后置）。
- **状态** `status`：草稿 / 已发布。
- **浏览计数** `view_count`：`POST /kb-articles/{id}/view` 自增，支撑高频统计。
- **工单转知识**：高频问题/整改方案沉淀为知识条目（`author_id` 关联 sys_user），RAG 问答后置。

## 4. 文件清单

- `app/models/kb.py` — `KbArticle`
- `alembic/versions/0008_kb.py` — 迁移
- `app/schemas/kb.py` — 请求/响应模型
- `app/services/kb_service.py` — 检索 + 浏览计数
- `app/api/v1/kb.py` — 路由
- `tests/test_kb_service.py` — 单测

## 5. API

- `GET /kb-articles?q=&category=&status=` 列表/检索
- `POST /kb-articles`、`GET/PUT/DELETE /kb-articles/{id}`
- `POST /kb-articles/{id}/view` 浏览计数

## 6. 角色

知识库属平台域：读/写 `sys_admin / sys_ops / ticket_mgr`，删除 `sys_admin / sys_ops`。客户侧自助可见后置。
