# 步骤五：核心算法（周期拆分 / 定期工单 / 换岗分摊 / SLA 预警 + 单测）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §9.2 关键测试点
> 范围：合同履约四个核心算法 + APScheduler 定时任务 + pytest 单测。

## 1. 目标

实现步骤四 CRUD 之上的业务算法层：周期拆分、定期工单幂等生成、换岗分摊、SLA 分级预警、服务提醒，全部可单测。

## 2. 算法清单

| 算法 | 文件 | 说明 |
|---|---|---|
| 周期拆分 | `services/cycle_service.py` | `split_cycles(start,end,frequency,unit)` 均匀拆成 `(cycle_no, start, end)`；不定期返回空 |
| 周期生成（幂等） | `cycle_service.generate_cycles` | 落 `service_cycle`，靠 `UNIQUE(contract_item_id, cycle_no)` 防重 |
| 定期工单 | `scheduler/jobs.py` | 每日扫描到期子项 → cycle + 工单 + 启动提醒，幂等 |
| 换岗分摊 | `services/dispatch_service.py` | 旧执行人 `is_active=false` + `actual_hours/ended_at`；新执行人续接继承比例 |
| SLA 预警 | `services/sla_service.py` | 距周期结束 ≤7/3/1 天 → 黄/橙/红；超时红 |
| 服务提醒 | `services/reminder_service.py` | 落 `service_reminder` |

## 3. 周期拆分规则

单位：`天`(1天) / `周`(7天滚动) / `月` / `季度`(3月) / `半年`(6月) / `年`(12月)。逐段推进、每段按 `frequency` 等分，`cycle_no` 单调递增，跨月/跨年自然覆盖，无重复无遗漏。

## 4. 新增端点

- `POST /contract-items/{id}/cycles/generate` — 按合同周期生成服务周期（幂等）
- `POST /work-orders/{id}/assignees/transfer` — 换岗分摊

## 5. 单测（tests/，对应 §9.2）

| 测试 | 断言 |
|---|---|
| 2次/周 跨月 | 周期数正确、cycle_no 无重复、时间无遗漏 |
| 季度 1次 | 每年 4 期、到点只生成 1 次（幂等） |
| 换岗 60/40 | 旧执行人 inactive+actual_hours，新执行人续接，active 比例合计 100 |
| SLA 分级 | ≤7 黄 / ≤3 橙 / ≤1 红 / 超时红 |
| 定期工单幂等 | 连跑两次，第二次生成 0 |
