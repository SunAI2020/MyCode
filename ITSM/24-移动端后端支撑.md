# 步骤二十四：移动端后端支撑（阶段六 · uni-app 前置）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §8.6 阶段六 · §6.3/6.4 移动端
> 范围：签到打卡（GPS + 拍照留证）+ 图片上传 + 静态挂载，为 uni-app 移动端提供后端接口。

## 1. 目标

为移动端补齐后端能力：

1. **签到打卡**：`CheckIn` 模型 + 签到/签退端点（GPS 经纬度 + 地址 + 照片）。
2. **图片上传**：multipart 上传 → 本地 `uploads/` 存储 + 静态访问 `/uploads`。
3. **今日状态**：`/checkins/today` 供移动端判断今日是否已签到。

> 人脸识别登录务实方案：移动端复用 JWT 登录（`POST /api/v1/auth/login`），人脸/指纹用设备级生物识别（uni-app SOTER）保护本地 token；后端不建人脸库（需人脸 SDK + 库，超出本项目范围）。

## 2. 文件清单

| 文件 | 说明 |
|---|---|
| `models/checkin.py` | `CheckIn` 模型（GPS + 照片） |
| `alembic/versions/0011_checkin.py` | 迁移（create_all 幂等建表） |
| `schemas/checkin.py` | `CheckInCreate` / `CheckInOut` |
| `api/v1/checkins.py` | 签到/签退 + 今日状态 + 我的记录 |
| `api/v1/uploads.py` | 图片上传（类型/大小校验） |
| `main.py` | 挂载 `/uploads` 静态目录 |
| `core/config.py` | `UPLOAD_DIR` |
| `frontend/nginx.conf` | `/uploads` 反代（移动端访问照片） |
| `tests/test_checkin.py` / `test_upload.py` | 回归测试 |

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/checkins` | 签到/签退（同类型每日一次，重复 400） |
| GET | `/api/v1/checkins` | 我的签到记录（分页） |
| GET | `/api/v1/checkins/today` | 今日签到状态 |
| POST | `/api/v1/uploads` | 图片上传 → `{url}` |

## 4. 验证


## 5. 说明

- 上传限 jpg/png/webp、≤5MB；文件落 `UPLOAD_DIR`（默认 `backend/uploads/`）。
- 下一步（步骤二十五）在 `mobile/` 建 uni-app 前端对接以上端点。
