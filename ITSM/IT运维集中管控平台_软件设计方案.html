1方案概述

1.1 项目背景与定位

安全服务团队 / MSSP 的核心痛点：一份合同包含多个服务对象、多个服务项、多个服务频率，履约义务零散分布在合同文本、Excel、邮件与人的记忆里，导致漏做、重做、超期无人知、绩效算不清、换岗交接混乱、外包不可控。

本平台定位为面向安服团队 / MSSP 的「合同履约 + 工单 + 服务」一体化集中管控平台，以「合同 → 子项 → 工单」为主轴，统一承载客户合同履约、内部任务、外包协作、问题整改、交付、绩效、SLA 提醒、AI 增强与知识沉淀。

目标：可追溯、可量化、可考核、可自动化的完整交付闭环。

1.2 核心设计理念（融合前沿方法论）

理念来源在本平台的落地
CMDB 为核心ServiceNow / 嘉为蓝鲸服务对象升级为完整 CMDB（配置项 + 依赖拓扑 + 影响分析），工单/变更/问题均挂接 CI
SLO / 错误预算Google SRESLA 契约引擎升级为 SLO 管理，分级预警 + 升级链 + 超时统计

2需求分析

2.1 目标用户与角色

平台分「平台侧」与「客户侧」两大域，共七级角色：平台侧（系统管理员、系统运维人员、工单管理人员、客服人员、安服人员）；客户侧（客户系统管理员、客户服务管理人员）。

2.2 核心业务场景

  • 多合同多子项履约：一个客户同时有安全服务合同 + 设备升级合同，各自拆解多个子项，独立排期、提醒、验收。
  • 定期工单自动生成：OA 系统「漏洞扫描 1 次/季度」→ 每季度自动生成工单 → 派单 → 执行 → 交付。
  • 驻场服务：派驻 X 人，驻场人员每日填报日报，汇总月报，异常转整改。
  • 外包协作：能力/时间不足时外包，外包人员接单、汇报、验收、结算，数据强隔离。
  • 换岗分摊：执行到一半换人，按「各人实际承担工作量」自动重算绩效。
  • 整改闭环：发现安全问题（漏洞、配置缺陷、基线不合规、风险隐患等）→ 多轮整改 → 效果验证通过 → 归档交付。

4核心业务模块详细设计

4.1 客户与合同管理

客户档案：名称/简称、行业/规模、客户等级（金牌/银牌/普通，关联 SLA）、联系人/电话（脱敏）、服务对象清单。

合同登记：合同类型、名称/编号、金额、周期、服务对象、合同子项、是否含驻场、状态（草稿/执行中/已到期/已续约）。

多合同模型：一个客户可同时有多个并行合同，系统按合同独立管理履约、结算与绩效。

4.2 合同子项与服务对象

服务对象（= CMDB 配置项 CI）：名称、类型（业务系统/网络设备/服务器/机房/数据库）、IP/位置、依赖关系（影响分析）。

合同子项：服务对象、运维项目、服务频率（数值+单位）、SLA、验收标准、子项价格。

关键：服务频率从「工单级」下放到「子项级」，同合同不同系统、不同服务项各自独立排期、提醒、验收。

4.3 接单模块

来源：客户报障 / 商务拓展 / 巡检发现 / 安全事件 / 续约 / 临时新增。

临时工作快速开单：外出检查、应付抽检、处置舆情等，支持快速模板一键开单，可不挂合同/子项。

4.4 派单模块（智能派单 + 换岗分摊）

智能派单建议（AI）：基于 技能矩阵 + 当前负载 + 历史绩效与评价 推荐执行人并给出理由。

个人绩效 = Σ ( 工作量 × 派单价格 × 分摊比例 × 质量系数 × 评价系数 )
分摊比例 = 个人实际承担工作量 / 工单总工作量
换岗机制：中途换岗时按「各人实际承担时长 × 派单价」自动重算，结算与绩效精确到人。

4.5 工单管理（核心）

工单类型：客户工单 / 驻场工单 / 内部任务 / 外包工单（统一工单池）。

状态机：

待派单 → 已派单/进行中 → 计划中 ↔ 进行中 → 待验收 → 已完成
                ↓
          (SLA 预警 / 催办 / 升级)

状态流转由工作流引擎驱动：整改通过 → 自动「待验收」；客户签字 → 自动「已关闭」+ 计绩效；外包验收通过 → 自动结算。

4.6 驻场服务模块

驻场配置（客户/人数/人员/周期/工作项）+ 驻场日报（逐项记录 → 汇总周/月报），异常一键转「问题」进入整改闭环。

4.7 内部任务模块

统一工单池：内部任务与客户工单共用状态机、SLA、提醒机制，员工一个视图处理所有待办。

4.8 外包管理模块

内部工单→发起外包→外包派单→外包接单→工作汇报→验收→结算
权限隔离（安全）：外包账号仅见被指派的外包工单，数据脱敏，禁止访问其他合同/工单/内部数据，全程审计。

4.9 问题发现与整改闭环

发现问题（安全问题：安全漏洞、配置缺陷、基线不合规、风险隐患等，记录类型/等级/描述/截图，支持相似推荐）→ 多轮整改（第 N 轮 → 整改完成待验证 / 不通过自动下一轮）→ 效果验证（通过/不通过/部分完成）。

4.10 项目交付

四类核心报告：运维报告 / 发现问题报告 / 整改报告 / 验收报告。另生成漏洞扫描/渗透测试/应急演练/等保测评/驻场月报等专项报告。

4.11 绩效考核（换岗分摊）

构成：工作量、派单价格、工作质量（0.6~1.2）、用户评价（0.8~1.2）。维度：人员/客户/合同/子项/项目/时间，外包成本纳入毛利核算。

4.12 CMDB 与资产管理（增强）

能力说明
配置项（CI）建模服务对象/设备/服务器/数据库/机房等 CI 类型
依赖拓扑CI 间依赖关系（影响分析）
变更联动工单/变更自动更新 CI 属性
冲突检测多变更涉及同一 CI 或同一窗口实时预警
资产生命周期新增 → 在用 → 变更 → 下线

4.13 变更管理（增强）

借鉴 ServiceNow / 蓝鲸：变更风险评估（问卷+分值→高/中/低）+ 变更日历 + CAB 审批 + 回滚跟踪 + 审计留痕，与 CMDB 联动全程可追溯。

4.15 服务提醒与 SLA 契约引擎

服务启动提醒：「第 X 次服务已启动，请及时处理！」

SLA 契约引擎：多级 SLA + 工作日历（跳过非工作时段）+ 升级链（执行人 → 项目经理 → 部门负责人）。渠道：站内/移动推送/企微/飞书/钉钉/短信。

4.16 AI 智能增强（AIOps）

能力应用场景原则

工单摘要自动生成执行摘要自动

落地原则：AI 均为「建议 + 人工确认」；涉敏数据走本地化/脱敏 LLM；决策可解释、证据可追溯。

4.17 工作流编排与审批（低代码）

借鉴优云/蓝鲸「低代码五大引擎」：表单 / 流程 / 决策 / 视图 / 报表。典型流程：审批流、状态自动流转、自动化动作，全量留痕。

4.18 知识库与自助门户（服务目录）

知识库（漏洞库/整改方案库/故障手册/SOP）+ 全文检索 + RAG 问答 + 高频问题 → 知识条目 → 自助解决闭环；自助门户支持客户报障/查进度/看履约，员工查知识，外包提交汇报。

4.19 报告中心与数据看板

报告归档 + 数据看板（工单总数/进行中/即将超时/待验收/待结款/安全事件）+ 成本毛利 + 履约率 + SLA 达成率 + 绩效排名。

5权限与安全设计

5.1 七级 RBAC 模型

序号角色域权限范围
1系统管理员平台最高权限：用户/角色/权限/配置/字典/审计/全数据
2系统运维人员平台监控、备份/恢复、日志、服务启停（不碰业务数据）
3工单管理人员平台接单、派单、催单、变更时限/服务人员/价格
4客服人员平台只读：仪表盘、工单进度、联系服务人员
5客户系统管理员客户查看/管理己方合同工单进度；不可改履约中价格
6客户服务管理人员客户追加合同/系统/工单、临时工单、调时限、评价/投诉
7安服人员平台查看本人工单、接收任务与催单、填表单/日志

5.2 多租户与数据隔离

隔离层级机制
行级隔离客户侧角色 customer_id 过滤（应用层 + PG RLS 双重保障）
字段级权限合同价格/联系方式按角色控制可读/可写/脱敏
外包隔离外包账号仅见指派工单，跨合同/客户强隔离
可选物理隔离高合规客户独立 Schema / 独立实例

5.3 数据安全（脱敏 + 加密 + 水印 + 审计）

类型字段脱敏方式
联系方式电话/手机138****1234
IP 地址资产 IP10.1.*.*
凭证/密码系统口令不可逆哈希，永不展示
金额合同/派单价低权限遮蔽或占位

加密：TLS 1.2+ 全链路；PostgreSQL 强制 SSL 连接；密钥管理系统（KMS）信封加密；pgcrypto 敏感列加密；TDE + 对象存储 SSE；备份加密。

6.3 关键 DDL 示例（PostgreSQL）

CREATE TABLE contract_item (
  id            BIGSERIAL PRIMARY KEY,
  contract_id   BIGINT NOT NULL REFERENCES contract(id),
  ci_id         BIGINT REFERENCES cmdb_ci(id),      -- 服务对象
  project       VARCHAR(64) NOT NULL,               -- 运维项目枚举
  frequency     INT NOT NULL DEFAULT 1,             -- 频率数值
  unit          VARCHAR(16) NOT NULL DEFAULT '月',  -- 天/周/月/季度/半年/年/不定期
  sla_policy_id BIGINT REFERENCES sla_policy(id),
  accept_standard TEXT,
  price         NUMERIC(14,2),
  created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE service_cycle (
  id             BIGSERIAL PRIMARY KEY,
  contract_item_id BIGINT NOT NULL REFERENCES contract_item(id),
  cycle_no       INT NOT NULL,
  service_start  DATE NOT NULL,
  service_end    DATE NOT NULL,
  status         VARCHAR(16) DEFAULT 'pending',
  auto_generated BOOLEAN DEFAULT true,
  UNIQUE(contract_item_id, cycle_no)
);

CREATE TABLE work_order (
  id            BIGSERIAL PRIMARY KEY,
  no            VARCHAR(32) UNIQUE NOT NULL,
  type          VARCHAR(16) NOT NULL,
  contract_id   BIGINT REFERENCES contract(id),
  contract_item_id BIGINT REFERENCES contract_item(id),
  ci_id         BIGINT REFERENCES cmdb_ci(id),
  status        VARCHAR(16) DEFAULT '待派单',
  priority      VARCHAR(8) DEFAULT '中',
  sla_deadline  TIMESTAMPTZ,
  current_cycle_no INT
);

CREATE TABLE work_order_assignee (
  id            BIGSERIAL PRIMARY KEY,
  work_order_id BIGINT NOT NULL REFERENCES work_order(id),
  user_id       BIGINT NOT NULL REFERENCES sys_user(id),
  workload_ratio NUMERIC(5,2) DEFAULT 100,
  actual_hours  NUMERIC(8,2),
  started_at    TIMESTAMPTZ,
  ended_at      TIMESTAMPTZ,
  is_active     BOOLEAN DEFAULT true
);

10测试与质量保障

9.1 测试策略

层工具覆盖目标
单元测试JUnit 5 / pytest核心逻辑 ≥ 80%（派单分摊、周期拆分、状态机）
集成测试Testcontainers + PG关键链路（接单→派单→工单→验收）
接口测试Postman + REST Assured全部 API
前端测试Vitest + Playwright核心页面 + 关键交互
性能测试JMeter并发 500，P95 < 500ms
安全测试OWASP ZAP + 渗透等保三级

9.2 关键测试用例

  1. 周期拆分：2 次/周 跨月是否均匀、重复/遗漏
  2. 换岗分摊：A(60%)→B(40%) 换岗后绩效是否精确归属
  3. 定期工单：季度频率到点只生成 1 次（幂等防重）
  4. 权限隔离：客户侧角色只能访问本客户数据（行级）
  5. SLA 升级链：超时逐级上报（执行人→经理→负责人）
  6. 外包隔离：外包账号不能访问其他客户工单（应禁止）
