# 步骤二十三：性能压测 + 安全测试 + 等保测评（阶段六收尾）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §8.6 阶段六 · §9 测试与质量保障 · §10.2 验收标准
> 范围：JMeter 压测脚本、OWASP ZAP 扫描清单、等保 2.0 三级对照表、测试方案与验收标准。

## 1. 目标

补齐阶段六第 4 项「性能压测 + 安全测试 + 等保测评」，形成可执行的测试资产与对照文档。

| 维度 | 工具/产物 | 验收标准 |
|---|---|---|
| 性能 | JMeter（`perf/itsm-load.jmx`） | 并发 500 稳定，P95 < 500ms |
| 安全 | OWASP ZAP（`security/owasp-zap-checklist.md`） | OWASP Top 10 全覆盖 |
| 等保 | 对照表（`security/等保三级对照.md`） | 等保 2.0 三级逐项对应 |

## 2. 文件清单

| 文件 | 说明 |

## 3. 压测场景（JMeter）

| 场景 | 接口 | 说明 |
|---|---|---|
| 登录 | `POST /api/v1/auth/login` | 提取 token，供后续请求 |
| 工单列表 | `GET /api/v1/work-orders` | 高频列表（行级隔离 + 分页） |
| 客户列表 | `GET /api/v1/customers` | 脱敏列表 |
| 合同列表 | `GET /api/v1/contracts` | 关联查询 |
| 门户概览 | `GET /api/v1/portal/overview` | 多表聚合 |
| 知识库检索 | `GET /api/v1/kb-articles?q=登录` | ES/SQL 检索 |

目标：线程组 500 并发、30s 爬坡、循环 2 次，聚合报告 P95 < 500ms、错误率 0。

## 4. 安全测试（OWASP ZAP）

- 主动扫描目标：登录、认证、RBAC 越权、行级隔离、IDOR、注入、脱敏、审计。
- 关键断言：客户侧角色不得访问他人客户数据（403/404）；敏感字段（电话/IP/金额）响应须脱敏；审计含 IP。
- 详见 `security/owasp-zap-checklist.md`。

## 5. 等保三级对照

- 安全物理环境 / 通信网络 / 区域边界 / 计算环境 / 管理中心 / 管理制度 / 人员 / 建设 / 运维，九大类逐项对照系统实现与证据。
- 详见 `security/等保三级对照.md`。

## 6. 验证

```bash
cd backend && python -m pytest -q   # 89 passed（回归）
# 压测：JMeter GUI 打开 perf/itsm-load.jmx 或 jmeter -n -t perf/itsm-load.jmx
# ZAP：按 security/owasp-zap-checklist.md 配置对 http://localhost:8080 扫描
```

## 7. 说明

- 压测/安全测试资产为「执行模板」，需在部署环境（`docker compose -f docker-compose.prod.yml up`）落地运行；本步骤交付脚本与对照文档，不替代真实压测/渗透执行记录。
- 移动端（uni-app）单独开阶段，不在本步骤范围。
