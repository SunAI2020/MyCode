47-合同履约链路修正（服务对象→服务项目）

背景

原数据模型主从链路不完整：

  • 客户 → 合同：已有（Contract.customer_id）。
  • 合同 → 服务对象：缺失，CmdbCi 只挂 customer_id。
  • 服务对象 → 服务项目：错位，ContractItem 挂的是 contract_id，ci_id 可空。

修正为目标链路：

客户 → 1+ 合同 → 1+ 服务对象(CI) → 1+ 服务项目(原"合同子项"，含服务频次、价格) → 1+ 频次/周期

工单为聚合模型（1 客户 + 多服务对象 + 多服务项目 + 多频次，可勾选默认全选），作为后续独立步骤，本次不实现。

后端

模型 backend/app/models/contract.py

  • CmdbCi：新增 contract_id（FK→contract.id，NOT NULL，index）；保留 customer_id（冗余，创建时由合同派生，供 scope_filter 直接过滤）。
  • ContractItem：ci_id 由可空改为必填（挂服务对象）；保留 contract_id（冗余，由 ci.contract_id 派生，供 scope_filter / cycle_service 使用）。

Schema backend/app/schemas/contract.py

  • CmdbCiCreate：加 contract_id（必填），去掉 customer_id（派生）。
  • CmdbCiUpdate：加 contract_id: int | None。
  • CmdbCiOut：加 contract_id。
  • ContractItemCreate：ci_id 改必填，去掉 contract_id（派生）。
  • ContractItemUpdate：加 ci_id: int | None。

API backend/app/api/v1/contracts.py

  • create_ci：校验合同存在（400「合同不存在」），customer_id = 合同.customer_id。
  • update_ci：传 contract_id 时校验并重派生 customer_id。
  • create_item：校验服务对象存在（400「服务对象不存在」），contract_id = ci.contract_id。
  • update_item：传 ci_id 时校验并重派生 contract_id。
  • list_items：新增 ci_id 查询参数，支持按服务对象筛选。

前端 frontend/src/views/Contracts.vue

  • 标签页顺序：合同 → 服务对象 → 服务项目；「合同子项」改名「服务项目」，「服务对象(CI)」改名「服务对象」。
  • CI 弹窗：客户ID 文本输入 → 合同下拉；CI 列表「客户名称」列 → 「合同名称」列。
  • 服务项目弹窗：合同ID 文本输入 → 服务对象下拉；列表增加「服务对象」列。
  • 服务项目筛选下拉：选择合同 → 选择服务对象。

数据库

重置（用户已确认）：DROP SCHEMA public CASCADE + alembic upgrade head + app.db.seed。

验证

重置库后，建客户 → 建合同 → 建服务对象(选合同) → 建服务项目(选服务对象) → 生成周期，各列表父级名称正确显示。
