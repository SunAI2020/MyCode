步骤四：合同履约主干 API

客户 → 合同 → 子项 → CI → 接单 → 派单 → 工单 → SLA → 周期 → 提醒 全链路 CRUD

1. 目标

在步骤三认证底座上，落地主干资源的增删改查与关键动作（创建工单、派单、状态流转），全部写接口挂 require_role + 审计，列表接口挂 customer_scope_of 行级隔离。

2. API 面

资源方法路径角色
客户GET/POST/customers读：登录即可（隔离）；写：sys_admin/sys_ops
GET/PUT/DELETE/customers/{id}写：sys_admin/sys_ops；删：sys_admin
（合同 / 子项 / CI 与客户同构，略）

4. 关键设计

  • 行级隔离：deps.scope_filter(q, model, scope)——客户侧用户仅见本客户数据。
  • 工单号：WO-YYYY-NNNN 按年递增。
  • 派单校验：执行人 workload_ratio 合计须为 100%。
  • 状态机：硬编码合法迁移表，非法迁移 400。
  • 统一错误：沿用步骤三 HTTPException 处理器。
