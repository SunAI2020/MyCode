步骤十三：变更单（阶段四 · FR-14）

依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §4.13 / §6.2
范围：变更登记 + 风险评估 + 冲突检测 + 回滚计划 + 审批状态机。

1. 目标

实现变更管理：变更工单挂接配置项（CI），登记风险等级、回滚计划；同一 CI 存在多个活跃变更时自动标记冲突（conflict_flag）；走「草稿 → 待审批 → 已批准 → 实施中 → 已完成/已回滚」状态机。

2. 表（1 张，依据 §6.2）

change_order 变更：id, work_order_id, ci_id, risk_level, conflict_flag, rollback_plan, status

3. 业务规则

  • 风险评估 risk_level：高 / 中 / 低（MVP 手动登记；问卷评分后置）。
  • 冲突检测：创建/更新时，若同一 ci_id 存在其他「待审批/已批准/实施中」变更，conflict_flag 置真。
  • 状态机 status：
    草稿 → 待审批 / 已取消
待审批 → 已批准 / 已拒绝
已批准 → 实施中 / 已取消
实施中 → 已完成 / 已回滚
  • 回滚计划 rollback_plan：变更失败的回退方案。

4. 文件清单

  • app/models/change_order.py
  • alembic/versions/0007_change_order.py
  • app/schemas/change_order.py
  • app/services/change_service.py — 冲突检测 + 状态机
  • app/api/v1/change_orders.py
  • tests/test_change_service.py

5. API

  • GET/POST /change-orders、GET/PUT/DELETE /change-orders/{id}
  • PUT /change-orders/{id}/status 状态流转

6. 角色

变更管理属平台域：读/写 sys_admin / sys_ops / ticket_mgr，删除 sys_admin / sys_ops。
