# 步骤十一：驻场服务（阶段四 · FR-07）

> 依据：《IT运维集中管控平台_软件设计方案.html》V1.0 定稿 · §4.6 / §6.2
> 范围：驻场配置 + 驻场日报 + 周/月报聚合，异常关联问题整改。

## 1. 目标

实现驻场服务管理：登记驻场客户/合同/人数/周期/工作项，驻场人员每日填报日报，按日期范围聚合周报/月报；日报发现的异常可关联「问题」进入整改闭环（`issue_ref` 指向 issue.id）。

## 2. 表（2 张，依据 §6.2）

| 表 | 关键字段 |
|---|---|
| `onsite_service` 驻场配置 | id, contract_id, customer_id, headcount, period_start, period_end, work_items, status |
| `onsite_daily_report` 日报 | id, onsite_id, user_id, report_date, work_type, content, issue_ref |

## 3. 业务规则

- **驻场配置**：绑定客户/合同（`customer_id` 行级隔离锚点）、驻场人数、驻场周期、工作项（设备巡检/日志分析/漏洞打补丁/资产梳理/故障处置…）。
- **驻场日报**：逐项记录当日工作（`report_date` + `work_type` + `content`）；发现异常时 `issue_ref` 关联问题单进入整改闭环。
- **周/月报聚合**：按 `onsite_id` + 日期范围聚合日报，按 `work_type` 汇总条数，输出周/月报统计。
- **行级隔离**：`onsite_service` 有 `customer_id` 直接隔离；日报经 `onsite_id → onsite_service.customer_id` 隔离。客户侧仅见本客户驻场数据。

## 4. 文件清单

- `app/models/onsite.py` — `OnsiteService` / `OnsiteDailyReport`
- `alembic/versions/0005_onsite.py` — 迁移
- `app/schemas/onsite.py` — 请求/响应模型
- `app/services/onsite_service.py` — 日报聚合 `summarize_reports`
- `app/api/v1/onsite.py` — 路由
- `tests/test_onsite_service.py` — 单测

## 5. API

- `GET/POST /onsite-services`、`GET/PUT/DELETE /onsite-services/{id}`
- `GET/POST /onsite-daily-reports?onsite_id=&start=&end=`、`GET/PUT/DELETE /onsite-daily-reports/{id}`
- `GET /onsite-daily-reports/summary?onsite_id=&start=&end=` 周/月报聚合（按 work_type 计数）

## 6. 角色

- 写：`sys_admin / sys_ops / ticket_mgr`
- 读：`get_current_user` + 行级隔离（客户侧可见本客户驻场）
