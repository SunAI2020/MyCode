### 2026年7月28日 — 需求分析与方案设计

#### 2.1 需求理解

**用户输入**: `@星海EASM1.docx @星海EASM2.docx 参考这两个文档，对暴露面监测系统进行优化`

**执行过程**:
1. 读取两份星海EASM产品Word文档（docx）
2. 启动3个Explore Agent并行分析：
   - Agent 1: 提取docx文档核心内容（企业关联关系重构、4级股权穿透、AI评分、1小时评估）
   - Agent 2: 分析ASM项目代码结构和模块关系
   - Agent 3: 识别差距（10/15维度为URL占位符，缺股权穿透/ICP/WHOIS等）
3. 进入Plan模式，启动Plan Agent设计7阶段方案
4. 编写优化方案到 `修改方案.md`（1311行）

**关键决策**:
- 保持Python+Tkinter+SQLite技术栈不变
- 采用7阶段渐进式实施（数据层→引擎层→AI层→评估层→GUI层→报告层→性能层）
- 优先使用免费公开API，降低运营成本

## 四、技术架构总览

```
GUI层:     8个面板 (Tkinter + 深色主题 #00143C)
             Dashboard / Org / Scan(3Tab) / Asset / Risk(2Tab) / Report / Map / Settings

引擎层:     12个核心引擎
             AISearchEngine(15维+7因子)    RapidAssessor(4阶段并行)
             EnrichmentEngine(10+API)      EquityChainEngine(BFS+12标识符)
             LeakDetector(14模式)          ShadowDetector(5维聚类)
             ScanManager(TCP扫描)          RiskManager(CVE匹配)
             CacheManager(SQLite+TTL)      RateLimiter(TokenBucket)
             OrgManager(16表+45CRUD)       ReportManager(5种报告)

数据层:     SQLite WAL (16张表, 3个索引)
              organizations / exposures / enterprise_profiles / subsidiaries
              enterprise_relations / identifier_index / icp_records / whois_records
              network_ranges / site_fingerprints / leak_evidence / rapid_assessments
              name_change_history / org_timeline_index / scan_tasks / system_settings
```
