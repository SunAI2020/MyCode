# 人在环浏览器登录/验证兜底 — 实现方案

> 目标：当股权穿透 / 发散搜索依赖的天眼查、爱企查等凭证失效、触发登录或验证码/滑块时，
> 系统主动弹窗引导用户在**应用内嵌浏览器**完成人工操作，自动捕获登录态并加密落库，然后自动重试原请求。

## 1. 背景与问题

`core/equity_chain_engine.py` 通过两个 chokepoint 获取企业数据：

- `_tyc_api_get`（第 128-142 行）：天眼查开放平台 API，`Authorization: {token}` 认证。
- `_aiqicha_get`（第 182-194 行）：爱企查（百度），`Cookie: {aiqicha_cookie}` 认证。

**现状缺陷**：两个方法都是 `try/except → return {}`，把"鉴权失败/凭证过期/风控"与"无数据"混为一谈，既不记日志、也不区分，用户无感知、无法修复。凭证靠用户在设置面板手动粘贴 cookie/token。

**改造目标**：把"登录态"当作一个**可检测、可刷新、可持久化**的资源，在鉴权失效时进入"人在环"兜底流程。

### 合规边界（必须遵守）

本机制**仅用于用户授权的目标组织的少量精确查询**；强制限流避免批量爬取；数据结果标注来源；以国家企业信用信息公示系统（gsxt.gov.cn）为最终依据。不将其用于大规模自动化抓取。

### 渠道适用性矩阵（诚实边界）

| 渠道 | 认证方式 | 浏览器登录能否直接产出可用凭证 |
|---|---|---|
| 爱企查（百度） | 登录态 Cookie | ✅ 完全适用，抓 Cookie 即用 |
| 天眼查**网页版**静态抓取 | 登录态 Cookie | ✅ 适用（`_fetch_from_tianyancha` 走网页） |
| 天眼查**开放平台 API** | API token | ⚠️ token 需在开放平台后台申请/购买，浏览器登录网页**拿不到 API token**；只能弹窗引导用户去后台复制 token 粘贴 |
| 国家企业信用公示系统 gsxt | 滑块验证码 + Cookie | ✅ 适用（Cookie + 人工滑块） |

## 2. 总体架构

```
scan_panel（股权穿透/发散搜索按钮）
   └─ equity_engine.discover_subsidiaries / full_divergent_search（后台线程）
        └─ _query_investments → _tyc_api_get / _aiqicha_get（chokepoint）
             ├─ 凭证有效 ──────────────► 正常返回数据
             └─ 检测到鉴权失效 ────────► _request_login(source, reason)
                  │                          │ need_login_cb（引擎线程内阻塞等待）
                  ▼                          ▼
           LoginCoordinator ◄────────── BrowserLoginDialog（主线程弹窗）
           （threading.Event）              │ 提示打开站点登录/验证
                  ▲                         ▼
                  │                    BrowserLoginManager（Playwright 有头）
                  │                    .open_login() → 用户操作 → .capture()
                  │                         ▼
                  └────────── CredentialStore.set_cookie(加密落库)
                                            ▼
                               need_login_cb 返回 True ──► 引擎重试原请求（一次）
```

## 3. 已确认决策

- **浏览器形态**：内嵌 Playwright **有头**浏览器，自动捕获登录态。
- **凭证存储**：`cryptography.Fernet` 对称加密后落库。

## 5. 凭证加密存储设计

**密钥管理**：`data/secret.key` 存 Fernet 密钥（32 字节 urlsafe base64）。首次运行生成：
```python
from cryptography.fernet import Fernet
key = Fernet.generate_key()          # 首次
# 后续读取 data/secret.key
```
> 打包注意：`data/secret.key` 与 DB 一样**不打入 exe**，运行时首次生成（与既有 `packaging-deploy-recipe` 记忆一致）。

**存储位置**：复用 `org_manager.system_settings` 表（`key TEXT PRIMARY KEY, value TEXT`），**不新建表**——已有 `api_key:aiqicha_cookie` 先例，且凭证是单值 KV，不适合进带 TTL 的 `cache_manager`。

**键与值**：
| key | value | 说明 |
|---|---|---|
| `browser_cookie:aiqicha` | `enc(Fernet, "name1=v1; name2=v2; ...")` | 浏览器 cookie 字符串（供 requests 用） |
| `browser_cookie:tianyancha` | 同上 | 网页版登录 cookie |
| `browser_cookie:gsxt` | 同上 | 滑块通过后的 cookie |
| `browser_state:{site}` | `enc(Fernet, json(storage_state))` | Playwright 完整 storage_state（可选，供无头复用） |

**CredentialStore 接口**（`core/credential_store.py`）：
```python
class CredentialStore:
    def __init__(self, org_mgr, key_path=None): ...
    def set_cookie(self, site, cookie_str) -> None        # 加密落库
    def get_cookie(self, site) -> str                     # 解密读取，失败返回 ""
    def set_storage_state(self, site, state_dict) -> None
    def get_storage_state(self, site) -> dict | None
    def _encrypt(self, s: str) -> str
    def _decrypt(self, s: str) -> str
```
`org_manager` 加两个薄封装（与 `set_setting/get_setting` 同风格）：
```python
def set_browser_cookie(self, site, cookie_str): ...   # 走 CredentialStore
def get_browser_cookie(self, site): ...
```

## 6. 浏览器会话管理设计（`core/browser_login.py`）

复用项目已有 Playwright 依赖（`requirements.txt` 已含 `playwright>=1.40.0`），参考 `core/browser_probe.py` 的 `sync_playwright` 用法，但改为**有头 + 持久化**。

```python
class BrowserLoginManager:
    def __init__(self, credential_store, profile_dir=None):
        self.store = credential_store
        self.profile_dir = profile_dir or os.path.join(DATA_DIR, "browser_profiles")
        self.site = None
        self._pw = None; self._ctx = None

    def open_login(self, site, url):
        """后台线程：启动有头浏览器打开登录页。"""
        self.site = site
        self._pw = sync_playwright().start()
        self._ctx = self._pw.chromium.launch_persistent_context(
            os.path.join(self.profile_dir, site),
            headless=False,
            args=["--disable-blink-features=AutomationControlled"])
        self._ctx.new_page()
        self._ctx.pages[0].goto(url)

    def capture(self):
        """登录完成后：抓 cookie 字符串 + storage_state，加密落库。"""
        cookies = self._ctx.cookies()
        cookie_str = "; ".join(f"{c['name']}={c['value']}" for c in cookies)
        self.store.set_cookie(self.site, cookie_str)                 # 供 requests 复用
        self.store.set_storage_state(self.site, self._ctx.storage_state())

    def close(self):
        if self._ctx: self._ctx.close()
        if self._pw: self._pw.stop()
```

**关键桥接**：用户在 Playwright 里登录得到浏览器 Cookie → `ctx.cookies()` 拼成 `"k=v; k2=v2"` 字符串 → `CredentialStore.set_cookie` 落库 → `equity_chain_engine._aiqicha_get` 下次用 `requests` 直接读该字符串塞 `Cookie` 头。这是"浏览器登录态 → requests 凭证"的唯一桥梁。

**失败降级**：`HAS_PLAYWRIGHT` 为 False 时，`BrowserLoginDialog` 显示提示让用户手动复制 Cookie 粘贴（回退到现有 `settings_panel` 手动模式）。

## 7. equity_chain_engine 接入点（核心改造）

只改 5 处 + 1 个异常类，覆盖全部业务方法（`discover_subsidiaries`、`full_divergent_search`、`extract_enterprise_profile`、`search_by_*` 都经两个 chokepoint）。

### 7.1 新增异常
```python
class CredentialExpired(Exception):
    def __init__(self, source, reason=""):
        self.source = source   # 'aiqicha' | 'tianyancha' | 'gsxt'
        self.reason = reason
```

### 7.2 扩展回调签名（第 28 行）
```python
def set_callbacks(self, log_cb=None, need_login_cb=None):
    self._log_cb = log_cb
    self._need_login_cb = need_login_cb   # 新增：登录兜底回调
```
`need_login_cb(source, reason) -> bool`：在引擎**后台线程内被调用**，负责弹窗+等待用户登录+落库，返回是否成功（引擎据此决定是否重试一次）。

### 7.3 鉴权检测与重试（第 128-142、182-194 行）

**天眼查 `_tyc_api_get`**：解析 `error_code`，区分"token 失效/欠费/风控"与"无数据"：
```python
def _tyc_api_get(self, endpoint_key, query, _retry=True):
    token = self._get_tyc_token()
    if not token or not HAS_REQUESTS: return {}
    ...
    data = r.json()
    ec = data.get("error_code", 0)
    if ec != 0:
        if self._is_tyc_auth_error(ec):                 # token 失效类错误码
            self._log(f"[天眼查] 凭证失效 error_code={ec}")
            if _retry and self._request_login("tianyancha", f"error_code={ec}"):
                return self._tyc_api_get(endpoint_key, query, _retry=False)
        return {}
    return data.get("result") or {}
```

**爱企查 `_aiqicha_get`**：检测登录态失效（HTTP 401/403 或返回 JSON 的登录态字段/重定向登录页）：
```python
def _aiqicha_get(self, url, _retry=True):
    r = requests.get(url, timeout=15, headers={...})
    if r.status_code in (401, 403) or self._is_login_redirect(r):
        if _retry and self._request_login("aiqicha", f"HTTP {r.status_code}"):
            return self._aiqicha_get(url, _retry=False)
        return {}
    return r.json() or {}
```

### 7.4 登录兜底转发（新增私有方法）
```python
def _request_login(self, source, reason):
    if not self._need_login_cb: return False
    try: return bool(self._need_login_cb(source, reason))
    except Exception: return False
```

### 7.5 引入 requests.Session（可选，推荐）
`__init__` 里 `self._session = requests.Session()`；`_aiqicha_get` 改用 `self._session.get(...)`，登录落库后同步 `self._session.cookies`，减少反爬触发、保持会话稳定。

### 7.6 限流（可选，防风控）
`gui/main_window.py` 已实例化 `RateLimiter` 但未注入。接入时 `EquityChainEngine(..., rate_limiter=self.rate_limiter)`，在 chokepoint 前 `wait_and_acquire("aiqicha")`/`wait_and_acquire("tianyancha")`，降低触发风控→反复登录的概率。

## 8. 弹窗交互点设计（`gui/dialogs.py` 新增 `BrowserLoginDialog`）

仿 `OrgDialog` 骨架（`transient + grab_set + result`），但**非阻塞等待用户完成**。

### 交互文案（核心体验）
> 「系统将打开【爱企查/天眼查/国家企业信用信息公示系统】，需要您登录账号（或输入验证码、拖动图片滑块验证）。请在浏览器中完成操作后，点击下方【我已登录，继续】按钮。」

### 类骨架
```python
class BrowserLoginDialog(tk.Toplevel):
    def __init__(self, parent, source, url, login_manager, on_done=None):
        super().__init__(parent); self.title("人工登录/验证")
        self.transient(parent); self.grab_set()
        self.result = None
        # 文案 + 状态标签("正在打开浏览器…" / "请完成登录后点击确定")
        # 按钮：["我已登录，继续"] → self._ok()；["取消"] → self.destroy()
        self.after(0, self._launch)         # 启动浏览器（线程）

    def _launch(self):
        threading.Thread(target=self.login_manager.open_login,
                         args=(self.source, self.url), daemon=True).start()
        self.status_lbl.configure(text="浏览器已打开，请完成登录/验证")

    def _ok(self):
        self.status_lbl.configure(text="正在捕获登录态…")
        threading.Thread(target=self._capture_and_finish, daemon=True).start()

    def _capture_and_finish(self):
        try:
            self.login_manager.capture()     # 抓 cookie + storage_state，加密落库
            self.result = {"ok": True}
        except Exception as e:
            self.result = {"ok": False, "error": str(e)}
        self.after(0, self.destroy)
```

### 线程协作（与 scan_panel 既有范式一致）

`scan_panel` 里股权/发散线程启动前，构造一个 `threading.Event` 协调"引擎线程等待"与"主线程弹窗"：
```python
def _start_equity(self):
    ...
    login_evt = threading.Event(); login_ok = {}
    def need_login(source, reason):
        # 本函数在 equity_engine 的后台线程内被调用
        def show():
            dlg = BrowserLoginDialog(self.frame, source, LOGIN_URLS[source],
                                     self.app.browser_login,
                                     on_done=lambda res: (login_ok.update(res), login_evt.set()))
        self.frame.after(0, show)          # 弹窗调度回主线程
        login_evt.wait(timeout=600)        # 阻塞等用户完成（≤10 分钟）
        return login_ok.get("ok", False)
    self.app.equity_engine.set_callbacks(log_cb=self.equity_log.log, need_login_cb=need_login)
    ...
```
> `LOGIN_URLS = {"aiqicha": "https://aiqicha.baidu.com/", "tianyancha": "https://www.tianyancha.com/", "gsxt": "https://www.gsxt.gov.cn/"}` 放 `config/settings.py`。

## 9. 数据流（端到端）

1. 用户点「股权穿透」→ `scan_panel._start_equity`（后台线程）。
2. `equity_engine.discover_subsidiaries` → `_query_investments` → `_aiqicha_get`。
3. `_aiqicha_get` 检测到 Cookie 失效 → `_request_login("aiqicha", "HTTP 403")` → `need_login_cb`。
4. `need_login_cb`（引擎线程内）：`frame.after` 把弹窗投回主线程 → `login_evt.wait()` 阻塞。
5. 主线程弹 `BrowserLoginDialog`，后台线程启动 Playwright 有头浏览器打开爱企查登录页。
6. 用户登录/过滑块 → 点「我已登录，继续」→ `capture()`：`ctx.cookies()` 拼字符串 → `CredentialStore.set_cookie("aiqicha", ...)` 加密落库。
7. `login_evt.set()` → 引擎线程醒来，`need_login_cb` 返回 True → `_aiqicha_get(..., _retry=False)` 重试成功。
8. 后续查询直接命中已存 Cookie，不再弹窗，直到再次失效。

## 10. 实施步骤（分阶段，每阶段可独立验证）

1. **Phase 1 — 凭证加密存储**：新增 `core/credential_store.py` + `org_manager` 封装；`requirements.txt` 加 `cryptography`。验证：加密/解密往返、落库读取。
2. **Phase 2 — 浏览器会话管理**：新增 `core/browser_login.py`（`BrowserLoginManager`）。验证：`open_login("aiqicha", url)` 能开有头浏览器、`capture()` 能产出 cookie 字符串。
3. **Phase 3 — 引擎改造**：`equity_chain_engine.py` 加 `CredentialExpired`、扩展 `set_callbacks`、改 `_tyc_api_get`/`_aiqicha_get`、引入 Session。验证：mock 鉴权失败时 `need_login_cb` 被调用并触发重试。
4. **Phase 4 — GUI 接入**：`gui/dialogs.py` 加 `BrowserLoginDialog`；`scan_panel` 挂 `need_login_cb`；`settings_panel` 爱企查 Cookie 行加"引导登录"按钮。验证：手工把 Cookie 置空 → 点股权穿透 → 弹窗 → 登录 → 自动重试成功。
5. **Phase 5 — 限流与打包**：注入 `RateLimiter`；确认 Playwright Chromium 随 exe 捆绑（`ecc:generating-python-installer` 技能）。

## 11. 验证方式

- **单元**：`CredentialStore` 加解密往返；`_tyc_api_get`/`_aiqicha_get` 对"鉴权失效 vs 无数据"的区分（mock `requests`）。
- **手工端到端**：设置面板填入一个无效的爱企查 Cookie → 点「股权穿透」→ 应弹「人工登录/验证」窗口 → 浏览器登录 → 点「继续」→ 自动重试并返回数据 → 再次查询不弹窗（Cookie 已缓存）。
- **回归**：确认无凭证/无 Playwright 时优雅降级（提示手动粘贴，不崩溃）。
- **安全**：确认 `data/secret.key` 与 DB 都不打入 exe；`system_settings` 里 cookie 为密文（非明文）。

## 12. 明确不做的（Out of Scope）

- 不自动破解验证码/滑块（仅人工完成）。
- 不做大规模批量爬取；不把浏览器登录用于任何未授权目标。
- 不改 ai-vuln 等兄弟项目。
