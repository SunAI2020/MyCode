## 一、项目概述

### 1.1 项目背景

"睿思慧眼互联网资产管理系统"由山西有信网安科技有限公司自主研发，是一款面向政府机构与企事业单位的AI驱动外部攻击面管理（EASM）平台。系统以"仅需输入企业名称，即可自动构建完整外部资产图谱"为核心设计理念，集成了4级股权穿透、12类标识符发散搜索、7因子AI置信度评分、影子资产5维聚类检测、1小时快速评估等创新功能。

### 1.2 项目目标

| 目标 | 描述 | 达成度 |
|------|------|--------|
| 全维度资产发现 | 从单一企业名称出发，自动完成15维度互联网资产发现 | 100% |
| 智能关联分析 | 股权链路穿透、标识符交叉关联、影子资产识别 | 100% |
| 高效评估交付 | 1小时内完成从输入到报告生成的全流程 | 100% |
| 极低成本运营 | 优先使用免费/公开API，降低外部服务依赖成本 | 90% |

### 1.3 适用范围

- **政府机构**: 各级政府部门、事业单位，支持机构改革更名历史追踪
- **集团企业**: 多层级控股结构，子公司自动穿透
- **金融机构**: 供应链风险排查、第三方合作方资产审计
- **教育/医疗**: 下属单位资产管理、暴露面定期巡检
- **安全服务商**: 为客户提供资产暴露面评估报告

### 1.4 技术路线

系统采用Python全栈实现，以Tkinter为桌面GUI框架，SQLite WAL模式为数据存储引擎，集成10+外部公开数据源，通过ThreadPoolExecutor实现15维度的并行资产搜索，运用7因子贝叶斯加权模型进行AI置信度评分。

## 二、研发背景与需求分析

### 2.1 市场驱动

2024年中国攻击面管理（ASM）市场规模达到 **10.2亿元人民币**，同比增长13.5%<sup>[1]</sup>。全球ASM市场预计2034年将突破 **50亿美元**，CAGR约21%<sup>[2]</sup>。随着数字化转型加速和HVV攻防演练常态化，数据资产暴露面排查正从"可选安全服务"升级为"必选安全基础设施"。

Gartner将攻击面管理演进路径定义为：**传统漏洞管理 → ASM → EASM/CAASM → CTEM → 统一暴露管理平台（AI驱动）**<sup>[5]</sup>。

### 2.2 市场格局

中国ASM市场竞争格局中，绿盟科技（18.3%）与360数字安全（17.1%）为市场双龙头，前五厂商合计占据64.8%市场份额<sup>[3]</sup>。亚信安全星海EASM作为新兴势力，以"四级控股穿透"和"1小时快速评估"形成差异化<sup>[10]</sup>。

### 2.3 核心痛点分析

参考亚信安全《星海EASM》产品文档<sup>[10]</sup>，当前组织面临的主要暴露面安全痛点：

| 痛点类别 | 具体问题 | 业务影响 | 严重程度 |
|---------|---------|---------|---------|
| 资产不可见 | 仅维护已知资产清单，未知影子资产不可见 | 攻击面盲区，易被攻击者利用 | 严重 |
| 关联不完整 | 缺少股权穿透，无法发现子公司/关联企业资产 | 集团企业存在大量未被管理的边缘资产 | 严重 |
| 数据已泄露 | 代码仓库、文库文档、云存储中散落敏感信息 | 架构图、密码、API密钥等已在互联网上公开 | 严重 |
| 名称变更 | 政府/事业单位机构改革频繁更名 | 历史名称遗留大量未迁移资产 | 高危 |
| 人工效率低 | 传统方式需数周完成资产盘点 | 无法满足应急响应和快速评估需求 | 高危 |
| 供应链盲区 | 无法发现供应商/合作伙伴的暴露面 | 通过第三方间接攻击 | 中危 |

### 2.4 核心需求定义

基于上述痛点，系统定义7项核心需求：

1. **仅输入企业名称**，自动完成全维度资产发现——无需手动指定IP或域名
2. **4级股权穿透**，自动识别≥30%控股的子公司与关联企业
3. **12类标识符发散搜索**：企业全称、简称、曾用名、法人、股东、实际受益人、实际控制人、关联企业、股东上下游、邮箱、电话、手机号码
4. **15维度资产发现**：域名、子域名、IP、云资产、SSL证书、代码仓库、文档、APP、微信公众号/小程序、邮箱、供应链、社交信息、端口服务、数据泄露、网络设备
5. **7因子AI置信度评分**，自动区分"确认资产""待确认资产""疑似影子资产"
6. **1小时快速评估模式**，满足应急响应与HVV备战需求
7. **政府/事业单位更名历史追踪**，自动追溯机构改革沿革

## 四、AI技术应用与技术亮点

### 4.1 多源数据融合引擎

系统通过 **10+外部数据源** 的实时查询与交叉验证，实现从单一企业名称到全量资产图谱的自动构建。

```
输入: "某集团有限公司"
  |
  +-- [DNS] dnspython 全量枚举 -> A/AAAA/MX/NS/TXT/CNAME/SOA
  +-- [crt.sh] 证书透明度日志 -> 子域名 + 证书SAN关联
  +-- [WHOIS] python-whois -> 注册人/邮箱/NS服务器
  +-- [ICP备案] 工信部备案 -> 法人/电话/域名绑定
  +-- [BGPView] ASN/IP段映射 -> ISP/地理位置
  +-- [Shodan] 端口服务暴露 -> 开放端口/服务/OS
  +-- [AlienVault OTX] 被动DNS -> 历史DNS解析记录
  +-- [GitHub API] 代码仓库搜索 -> 密钥/配置/备份文件泄露
  +-- [天眼查/企查查] 企业信息 -> 法人/股东/控股关系
  +-- [Hunter.io] 邮箱发现 -> 企业邮箱枚举
```

**并行优化**: 采用 `ThreadPoolExecutor` 线程池（max_workers=6-8），15维度×5名称变体可在2-5分钟内完成（串行需30分钟以上）。

### 4.2 7因子AI置信度评分模型

系统采用多因子贝叶斯加权置信度模型，对每个发现资产进行量化可信度评估：

| 因子 | 权重 | 验证方式 | 技术原理 |
|------|------|---------|---------|
| DNS解析验证 | 0.25 | 实时DNS查询 | 资产域名是否可解析到有效IP |
| 证书CN/SAN匹配 | 0.20 | SSL证书文本匹配 | 证书主体/备用名是否包含组织名 |
| 名称相似度 | 0.15 | 编辑距离 + 汉字共现 | 资产名与企业名双维度比对 |
| 多源交叉验证 | 0.15 | 来源计数归一化 | ≥3个独立数据源确认则满分 |
| ICP备案确认 | 0.10 | ICP数据库查询 | 域名到企业备案绑定验证 |
| 网站指纹匹配 | 0.10 | favicon/header/tech_stack | 与已知指纹库对比 |
| WHOIS注册人匹配 | 0.05 | WHOIS数据库查询 | 注册人是否匹配组织名 |

**置信度分级标准**:
- ≥85%: **高可信度-确认资产** — 多源交叉验证通过，可直接纳入资产管理
- ≥65%: **中可信度-待确认** — 部分因子确认，建议人工复核
- ≥40%: **低可信度-疑似影子资产** — 仅少量因子匹配，高度关注
- <40%: **需人工研判** — 无法自动确认归属，需安全分析师介入

**实测效果**: 对191条资产的自动评分结果：
- 高置信确认资产: 72条（38%）
- 低置信待确认: 63条（33%）
- 疑似影子资产: 56条（29%）

### 4.3 影子资产5维聚类检测

| 维度 | 方法 | 原理 | 置信度贡献 |
|------|------|------|-----------|
| SSL证书SAN聚类 | `cert_san_clustering()` | 共享SSL证书的域名属于同一组织 | +1信号 |
| IP段/24聚合 | `ip_range_clustering()` | 同网段IP高度可能属于同一组织 | +1信号 |
| MX/NS记录关联 | `mx_ns_correlation()` | 共享邮件/DNS服务器的域名关联 | +1信号 |
| Favicon Hash匹配 | `favicon_hash_correlation()` | 相同网站模板/系统指纹关联 | +1信号 |
| 编辑距离相似度 | `detect_shadow_assets()` | 域名命名模式与企业名匹配 | +1信号 |

**判定规则**: 3+独立信号交叉验证 → 高置信影子资产。实际检测中从191条资产识别出22个疑似影子资产。

### 4.4 数据泄露模式检测

基于14种正则模式的自动化泄露检测：

- **凭证泄露**（9种模式）: 数据库连接串(JDBC/MySQL/PostgreSQL/MongoDB/Redis)、密码赋值语句、API Key、AWS AKIA密钥、RSA/EC私钥头、数据库连接字符串、JWT Token、配置文件(.env/settings.py/web.config)、备份文件(.sql.gz/.bak)
- **架构文档泄露**（5种模式）: 网络拓扑图关键词、端口安全清单、设备型号、IP规划文档、项目方案文档

### 4.5 12类标识符发散搜索算法

```
企业名称 "XX科技集团有限公司"
  |
  +-- Step 1: 企业档案提取（国家企业信用信息公示系统/爱企查/天眼查/企查查/启信宝/ICP）
  |    提取: 全称、简称、曾用名、法人、股东(持股比例)、
  |          实际受益人、实际控制人、高管、邮箱、电话、手机
  |
  +-- Step 2: 建立 bidirectional identifier_index
  |    每个标识符 -> 关联企业 org_id + profile_id
  |
  +-- Step 3: 每类标识符作为独立搜索种子
  |    +-- 法人 "张三" -> 天眼查反查名下所有企业
  |    +-- 股东 "李四"(40%) -> 向上追溯(谁投资了李四)
  |    +-- 股东 "王五"(25%) -> 向下扩展(王五还投资了谁)
  |    +-- 实际控制人 -> 控制链上下游追溯
  |    +-- 邮箱 hr@xx.com -> WHOIS反查 + GitHub提交者搜索 + 泄露库碰撞
  |    +-- 电话 010-xxx -> ICP反查(同电话备案多个域名)
  |    +-- 手机 138xxx -> 天眼查反查 + 微信/APP/社交平台关联
  |    +-- 简称 "XX科技" -> 全维度资产搜索
  |    +-- 曾用名 "XX软件" -> 历史资产追溯
  |
  +-- Step 4: 递归发现 (max_depth=3)
  |    Step 3发现的每个新企业 -> 回到 Step 1
  |    visited 集合去重防循环
  |
  +-- Step 5: 合并去重 + AI置信度评分
       输出: 企业关系图谱 + 全量资产列表 + 标识符关联链路
```

```
MainWindow.__init__()

  +-- CacheManager()                         # 缓存层
  +-- RateLimiter()                          # 限流层
  +-- EnrichmentEngine(org_mgr, cache)       # 富化引擎
  +-- EquityChainEngine(org_mgr, enrichment) # 股权穿透
  +-- LeakDetector(org_mgr, enrichment)      # 泄露检测
  +-- ShadowDetector(org_mgr)                # 影子检测
  +-- AISearchEngine(org_mgr, enrichment,    # AI搜索
  |      leak_detector, shadow_detector, cache)
  +-- RapidAssessor(org_mgr, enrichment,     # 快速评估
  |      equity, ai, leak, shadow, report)
  +-- ScanManager(org_mgr)                   # 端口扫描

  +-- ReportManager(org_mgr)                 # 报告生成
```
