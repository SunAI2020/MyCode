## 二、默认设计决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 新依赖 pymysql/redis/pymongo/openpyxl/APScheduler | 全部**可选**，import 守卫，缺库如实返回"不支持" | 遵循"优雅降级"原则，与 paramiko 一致 |
| psycopg2-binary | 已在 requirements.txt | PostgreSQL 弱口令检测直接可用 |
| RDP 认证 | xfreerdp 子进程（`+auth-only`） | 无成熟纯 Python RDP 客户端 |
| Telnet | 纯 socket（stdlib） | `telnetlib` 已从 Python 3.13 移除 |
| 调度器 | stdlib threading + heapq 优先队列 | 避免硬依赖，APScheduler 可后续替换 |
| 风险评分 | 乘法模型 | 资产价值 × 威胁 × 脆弱性 |

## 三、各项实施详情

### 3.1 弱口令协议扩充（weak_password_scanner.py）

**新增 6 个 handler**：

| Handler | 协议 | 客户端 | 可用性 |
|---------|------|--------|--------|
| MySQLHandler | mysql | pymysql（可选） | 缺库不可用 |
| PostgreSQLHandler | postgresql | psycopg2 | 缺库不可用 |
| RedisHandler | redis | redis-py（可选） | 缺库不可用 |
| MongoDBHandler | mongodb | pymongo（可选） | 缺库不可用 |
| RDPHandler | rdp | xfreerdp（可选） | 无客户端不可用 |
| TelnetHandler | telnet | 纯 socket | 始终可用 |

**改动要点**：
- `SUPPORTED_PROTOCOLS` 从 4 个扩充到 10 个。
- `SERVICE_PROTOCOL_MAP` 增加 `mysql/postgres/postgresql/redis/mongodb/mongod/ms-wbt-server/rdp/telnet` 映射。
- `HANDLER_REGISTRY` 注册 6 个新 handler。
- `scan()` 可用性检查通用化：`if not getattr(handler, 'available', True)`，替代原 `if protocol == 'ssh' and not PARAMIKO_AVAILABLE` 硬编码。
- `requirements.txt` 可选增强区追加 pymysql/redis/pymongo/openpyxl。

**保守策略**：Telnet 仅在明确 shell 提示符（`$`/`#`）时判命中；HTTP Basic 需先 401 挑战确认（P0 已修）。

### 3.2 多因子风险评分（risk_scoring.py）

**公式**：`risk_score = 资产价值系数 × 威胁系数 × 脆弱性系数 × 100`（0–100）。

- 资产价值：CRITICAL 1.0 / HIGH 0.8 / MEDIUM 0.6 / LOW 0.4 / INFO 0.2。
- 威胁：KEV=1.0 > EPSS(0–1) > 严重度兜底。
- 脆弱性：CVSS/10 > 严重度兜底。
- `risk_level()`：≥80 CRITICAL、≥60 HIGH、≥40 MEDIUM、≥20 LOW、其余 INFO。

**API**：`RiskScorer.score(vuln, asset_importance)`、`RiskScorer.score_many(vulns, importance)`。

### 3.3 漏洞相似度去重（vuln_dedup.py）

- 指纹：`(cve_id, host, service)`；版本取 major.minor 前缀。
- `similarity(a, b)`：指纹一致 + 版本一致 → 1.0；版本缺失 → 0.9；版本不一致 → 0.0。
- 阈值 0.9（保守，避免误删独立漏洞）。
- `VulnDeduplicator.deduplicate(vulns)` → `{'unique', 'duplicates'}`，按优先级（风险评分 > 置信度 > CVSS）降序保留最优。

### 3.4 资产批量导入 + 标签（asset_importer.py + api）

**asset_importer.py**：
- `parse_csv(text)` / `parse_excel(bytes)`（openpyxl 可选）→ `(assets, errors)`，行级容错。
- `parse_tags(str)`：逗号/分号/中文逗号分隔，去重去空。
- 表头别名归一化（中英文均可）。
- `import_assets(db, assets)` → `{inserted, duplicate, failed}`。

**API**（api/routers/assets.py）：
- `POST /assets/import`：接收 `{format, data, tags}`（CSV 文本 或 base64 Excel），逐条入库。
- `GET /assets/tags`：聚合全部标签（去重排序）。
- `GET /assets?tags=...`：标签过滤。

**database.py**：`get_asset_tags()` + `get_assets` 增加 `tags` 过滤。

### 3.5 扫描任务调度（scheduler.py）

- `ScheduledTask`：`task_id/target/priority/scan_type/ports/run_at/interval_seconds/func`。
- `ScanScheduler`：`heapq` 优先队列（critical/high/medium/low）+ 后台轮询线程（1s 粒度）。
- 支持一次性定时（`run_at`）与周期任务（`interval_seconds`）。
- API：`add_task/cancel/get_queue/run_once_now/start/stop`。

### 3.6 报告模板化（report_templates.py + report_generator.py）

**5 类模板**：`standard`（标准）、`compliance`（等保 2.0）、`high_risk`（高危专报）、`executive`（管理简报）、`technical`（技术详报）。

- `render_report(scan_data, template)` → `{title, template, vulns, sections}`。
- `high_risk` 仅保留 CRITICAL/HIGH；`executive` 输出摘要；`compliance` 输出条款映射。
- `generate_scan_report(..., template='standard')` 向后兼容新增参数，模板标题/章节注入 HTML。
