# 移动漏洞扫描系统功能完善清单

**山西有信网安科技有限公司 · 研发中心**

**版本**: v1.0 | **日期**: 2026年8月24日 | **密级**: 内部

---

## 1. 背景与现状

随着安全服务外勤化、等保测评现场化、渗透测试驻场化的普及，漏洞扫描系统越来越多地被安装在**笔记本电脑**上，由安全工程师携带至客户现场作业。移动扫描场景与固定机房部署存在本质差异：

| 差异维度 | 固定部署 | 移动（笔记本）部署 |
|---------|---------|-------------------|
| 网络环境 | 稳定、固定网段 | 多变、客户内网/隔离网/无外网 |
| 外网访问 | 可在线更新 | 常处涉密网/无外网环境 |
| 设备安全 | 机房物理可控 | 笔记本易丢失、被盗 |
| 资源 | 服务器级 CPU/内存 | 笔记本 CPU/电池受限 |
| 交付方式 | 定时任务 + 集中报告 | 现场即时出报告 |
| 客户管理 | 单一网络 | 多客户、多项目并行 |

当前系统（v2.1.0）为"联网单机工具"定位，在**离线能力、现场作业、数据加密、多客户隔离、合规检查**五方面存在明显短板。本清单系统梳理移动化需完善的功能，并按优先级排序。

## 2. 功能完善清单

### 2.1 离线与便携能力（最高优先级，移动刚需）

| 序号 | 功能 | 现状问题 | 完善方案 | 优先级 |
|------|------|---------|---------|--------|
| 1 | 离线漏洞库 | 依赖 NVD API 在线更新，涉密网/无外网无法更新 | CVE 库离线打包、U 盘/文件导入导出、增量更新包 | P0 |
| 2 | 离线 AI 回退 | 依赖 Claude Code CLI 或 Anthropic API，均需联网/已装 Claude | 本地小模型回退；无 AI 时明确降级为"仅规则扫描"并提示 | P0 |
| 3 | 绿色便携版 + 环境自检 | 需安装环境，无运行前检查 | 免安装启动、首次运行自动检测 Nmap/依赖/网络、输出能力清单 | P0 |

### 2.2 现场作业能力

| 序号 | 功能 | 现状问题 | 完善方案 | 优先级 |
|------|------|---------|---------|--------|
| 4 | 一键本网段发现 | 需手动输入 CIDR | 自动识别当前网段（IP/掩码/网关），一键扫描本网段 | P0 |
| 5 | 多网卡/多网段 Profile | 无网络环境配置管理 | 有线/无线/USB 网卡切换；保存多套"目标网段+策略+白名单"模板 | P1 |
| 6 | 断点续扫/暂停恢复 | 扫描中断即丢（拔网线/休眠/换场地） | 扫描进度持久化，下次继续 | P0 |
| 7 | 现场报告即时生成 | 报告偏内部风格 | PDF/Word 一键交付、盖章级格式、客户 logo 定制 | P0 |

### 2.3 数据安全（移动设备易丢失，合规红线）

| 序号 | 功能 | 现状问题 | 完善方案 | 优先级 |
|------|------|---------|---------|--------|
| 8 | 数据库与报告加密 | SQLite 明文存储 | SQLCipher 加密、报告/缓存加密 | P0 |
| 9 | 启动鉴权 + 锁屏 + 审计 | 仅有 RBAC，无设备级保护 | 登录密码/双因素、闲置自动锁定、完整操作审计 | P0 |
| 10 | 多客户数据隔离与脱敏 | 全局资产/结果混合存储 | 按客户物理隔离，导出报告一键脱敏（隐去内网 IP/口令） | P1 |

### 2.4 多客户/多项目管理

| 序号 | 功能 | 现状问题 | 完善方案 | 优先级 |
|------|------|---------|---------|--------|
| 11 | 项目（客户）维度管理 | 无项目实体，多客户无法区分 | 引入"项目/客户"实体，资产/扫描/报告/情报按项目归集 | P0 |
| 12 | 扫描策略模板库 | 无策略模板 | 政务/金融/制造等差异化策略一键套用 | P1 |

### 2.5 性能与资源适配

| 序号 | 功能 | 现状问题 | 完善方案 | 优先级 |
|------|------|---------|---------|--------|

## 3. 优先级总览与实施建议

### 3.1 优先级分级

- **P0（近期必做，移动化可用性基础）**：离线漏洞库、离线 AI 回退、绿色便携版、一键本网段发现、断点续扫、现场报告、数据库加密、设备级鉴权、项目（客户）管理、等保合规（战略项）。
- **P1（中期增强）**：多网卡 Profile、数据脱敏、策略模板库、资源自适应节流、回中心同步、备份恢复。
- **P2（长期演进）**：旁路被动发现。

### 3.2 实施路线

```
第一阶段（P0 基础可用）
  离线漏洞库 + 离线 AI 回退 + 绿色便携版
  一键本网段发现 + 断点续扫 + 现场报告
  数据库加密 + 设备级鉴权 + 项目（客户）管理

第二阶段（P1 体验增强）
  多网卡 Profile + 数据脱敏 + 策略模板
  资源自适应节流 + 回中心同步 + 备份恢复

第三阶段（P2 差异化）
  旁路被动发现 + 等保合规引擎（与 P0 战略项并行）
```

---

## 4. 核心结论

作为移动扫描系统，最该补的短板依次是：

1. **离线化**（漏洞库 + AI）—— 解决"无外网无法作业"的根本痛点；
2. **现场作业**（本网段发现/断点续扫/现场报告）—— 贴合外勤交付节奏；
3. **数据加密与多客户隔离** —— 移动设备丢失的合规红线；
4. **等保合规** —— 等保测评机构现场作业的强需求，也是相对绿盟 RSAS 的最大短板。

本质目标：从"联网单机工具"升级为"**可独立在隔离现场交付的便携作业平台**"。
