# 漏洞相似度去重 + evidence/remediation 结构化展示 升级报告

| 项目 | 内容 |
|------|------|
| 版本 | 2.1.0 |
| 日期 | 2026-08-20 |
| 模块 | 漏洞扫描流水线 / 报告生成 / GUI 展示 / 数据持久化 |
| 关联需求 | 检测覆盖率与误报控制、漏洞处置可追溯性 |

---

## 一、概述

本次升级解决扫描流水线的两个结构性缺口：

1. **漏洞相似度去重未接入** —— `vuln_dedup.py` 的去重器此前已实现并有测试，但从未被扫描流水线调用，导致同一主机同一服务上同一 CVE 经多路搜索词重复匹配出的记录被重复上报、重复计分、重复消耗 AI 核验 token。
2. **evidence/remediation 未结构化** —— 漏洞字典缺少结构化「证据」字段；「修复方案」此前是报告层硬编码 service 映射生成的自由文本，与 AI 核验后追加的单行 `ai_remediation` 割裂，未统一、未结构化、未持久化。

改造后：去重接入引擎层（AI 核验之前），每条漏洞生成结构化 `evidence` 与 `remediation`，并在 HTML 报告、GUI 悬浮提示、SQLite 数据库三处结构化落地。

---

## 二、改动内容

### 1. 新增 `vuln_enrich.py`（evidence/remediation 结构化富化）

核心纯函数，供报告/GUI/数据库统一消费：

| 函数 | 作用 |
|------|------|
| `SERVICE_REMEDIATION` | 服务 → 修复步骤集中映射（自 `report_generator._generate_risk_analysis` 内联字典迁移） |
| `build_evidence(vuln)` | 生成结构化证据（host/port/protocol/service/version/product/cve_id/cvss/severity/kev/references/matched_by/summary） |
| `build_remediation(vuln)` | 生成结构化修复（summary/steps/source/urgency/references），优先级 AI > 规则库 > 通用回退 |
| `enrich_vulnerabilities(vulns)` | 批量富化：evidence 缺失时填充，remediation 每次重算（AI 核验后重跑即刷新为 `source='ai'`） |
| `evidence_dict(vuln)` / `remediation_dict(vuln)` | 安全获取结构化字段，兼容 DB 反序列化（JSON 字符串 → dict） |

**结构化结构定义（合成示例）**

```json
// evidence
{
  "host": "192.0.2.10", "port": 80, "protocol": "tcp",
  "service": "http", "version": "Apache/2.4.49", "product": "Apache",
  "cve_id": "CVE-2021-41773", "cvss_score": 7.5, "severity": "HIGH",
  "kev": false, "matched_by": "version+service",
  "references": ["https://nvd.nist.gov/vuln/detail/CVE-2021-41773"],
  "summary": "192.0.2.10 的 http Apache/2.4.49 服务开放于端口 80，命中 CVE-2021-41773"
}
```

```json
// remediation
{
  "summary": "升级Web服务器到最新版本",
  "steps": ["升级Web服务器到最新版本", "配置WAF防护", "实施安全头(HSTS, CSP等)", "定期安全扫描"],
  "source": "rule",
  "urgency": "紧急修复 (24小时内)",
  "references": ["https://nvd.nist.gov/vuln/detail/CVE-2021-41773"]
}
```

### 2. `scanner_engine.py` — 去重 + 富化接入

`VulnScanner.scan_target` 在设备专项检测（FR-11）之后、返回之前：

```python
from vuln_dedup import VulnDeduplicator
from vuln_enrich import enrich_vulnerabilities
dedup = VulnDeduplicator().deduplicate(vulnerabilities)
vulnerabilities = enrich_vulnerabilities(dedup['unique'])
```

- 返回结果新增 `dedup_stats: {'before', 'unique', 'duplicates'}`。
- 去重发生在 AI 核验**之前**，直接减少重复 CVE 的 AI token 消耗。
- `summary` 基于去重后的漏洞列表重算，计数自动准确。

### 3. `database.py` — 持久化

- `scan_results` 表新增 `remediation` 列（`evidence` 列此前已存在但未写入），并以 `try/except ALTER TABLE` 兼容旧库。
- `add_scan_result` INSERT 增加 `evidence`/`remediation` 两列，以 `json.dumps(..., ensure_ascii=False)` 序列化写入。

### 4. `report_generator.py` — 结构化展示

- 风险卡新增 **「证据 (Evidence)」** 区块（`.mini-table` 键值表 + 一句话证据摘要）。
- 「修复方案」区块改为结构化渲染：编号步骤 `<ol>` + 来源徽标（`AI`/`规则库`/`通用`）+ 修复紧急度 + 参考链接。
- 文本报告每个漏洞新增「证据」「修复方案」两行。
- 报告摘要区（HTML info-grid 与文本报告）新增「相似度去重」统计行。
- `_generate_risk_analysis` 内联 `service_remediation` 字典移除，改用 `SERVICE_REMEDIATION`，消除双份维护。

### 5. `main_window.py` — GUI 展示

- 新增模块级 `_build_vuln_tooltip(vuln)`：从结构化 evidence/remediation 拼接多行悬浮提示。
- `_on_scan_finished` 与 `_load_last_scan_result`：为结果表每行单元格设置结构化 tooltip；`_on_scan_finished` 另输出去重统计日志。
- `_on_ai_scan_finished`：AI 核验完成后重跑 `enrich_vulnerabilities(verified)`，把 remediation 来源刷新为 AI。

### 6. 新增 `tests/test_vuln_enrich.py`

覆盖：evidence 字段结构、remediation 三级优先级（ai > rule > generic）、enrich 幂等性、AI 核验后 remediation 重算刷新、DB JSON 字符串归一化。

## 四、设计原则遵循

- **AI-first**：evidence/remediation 结构化后，AI 核验结果（`ai_remediation`）与规则库/通用回退在统一结构下分级合并。
- **保守安全**：去重仅在高相似度（阈值 0.9）下合并，版本缺失时仍保留一条，不误删真实独立漏洞；富化失败降级为原始字段，不丢数据。
- **优雅降级**：`vuln_enrich` 导入失败时扫描流水线跳过去重/富化（`dedup_stats` 记录 before=unique），不影响主流程。
- **单一数据源**：`SERVICE_REMEDIATION` 集中管理，报告层与富化层复用同一份映射。
