## 一、背景

AI 代码审计包含两个 AI 密集阶段：

1. **AI 安全核验**（`claude_security`）：对正则扫描出的候选漏洞逐条调用 Claude 核验，耗时。
2. **深度代码质量/设计审计**（`enable_quality_review`）：对每个文件调用 Claude 深度分析，耗时。

此前只有一个「停止」按钮，点击后只能整体中止，无法分别控制两个阶段。本次拆分为三个停止按钮，支持**独立中止任一阶段**。

## 三、实现机制

### 双独立中断事件（`AIAuditThread`）

```python
def __init__(self, ...):
    ...
    self._stop_security_event = threading.Event()
    self._stop_quality_event = threading.Event()

def stop_security(self):  # 请求停止 AI 安全核验
    self._stop_security_event.set()

def stop_quality(self):   # 请求停止代码质量/设计审计
    self._stop_quality_event.set()
```

`run()` 中将两个事件分别透传给 `scan_directory`：

```python
result = self.analyzer.scan_directory(
    self.target,
    progress_callback=...,
    enable_quality_review=self.enable_quality_review,
    stop_security=self._stop_security_event.is_set,
    stop_quality=self._stop_quality_event.is_set,
)
```

### 单参数拆分为双参数（`ai_analyzer.py`）

`scan_directory()` 将原来的 `should_stop` 拆分为 `stop_security` / `stop_quality`：

| 回调 | 透传目标 |
|---|---|
| `stop_security` | `_ai_verify_issues(...)` — AI 安全核验 |
| `stop_quality` | `AICodeReviewer.review_project(...)` — 质量审计 |

### AI 安全核验支持中断（`_ai_verify_issues`）

新增 `should_stop` 参数，在**每批次**与**每条候选漏洞**前检查中断：

```python
for batch_start in range(0, total, batch_size):
    if should_stop and should_stop():
        break  # 中止核验，保留已完成结果
    ...
    for i, issue in enumerate(batch):
        if should_stop and should_stop():
            break
        result = self.ai_verifier.verify_issue(issue, content)
```

## 四、停止方法（`main_window.py`）

| 方法 | 行为 |
|---|---|
| `_stop_audit_security()` | 调用线程 `stop_security()`，仅中止安全核验 |
| `_stop_audit_quality()` | 调用线程 `stop_quality()`，仅中止质量审计 |
| `_stop_audit()` | 同时调用 `stop_security()` + `stop_quality()` + `requestInterruption()`，并保留 5 秒 `terminate()` 兜底 |

点击「停止安全审计」或「停止质量审计」后，对应阶段在下一检查点**优雅中止**并保留已完成结果，不再依赖 `terminate()`。
