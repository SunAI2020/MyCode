# 代码修改报告 — 0day漏洞专项扫描功能

**项目：** AI-VULN 下一代智能漏洞扫描系统 Pro（v2.1.0）
**日期：** 2026-08-22
**修改范围：** 「漏洞扫描」模块新增 0day 漏洞专项扫描功能

---

## 一、需求背景

0day 漏洞（含 CISA KEV「已知被利用漏洞目录」中正被攻击者活跃利用的漏洞）是网络安全防护最重要的防护点。按需求要求，在「漏洞扫描」模块新增 **0day漏洞专项扫描** 功能，对 CISA KEV 目录做全量产品级交叉比对，重点提示最高优先级的 0day/在野利用漏洞。

## 二、修改概述

| 文件 | 修改内容 |
|------|---------|
| `scanner_engine.py` | `VulnScanner.scan_target()` 新增 `zero_day_focus` 参数；新增 `_flag_zero_day_focus()` 专项比对方法及辅助方法（`_collect_scanned_products`、`_product_matches_kev`、模块级 `_GENERIC_PRODUCT_TOKENS`/`_has_specific_token`） |
| `main_window.py` | 扫描配置区新增「0day漏洞专项扫描」复选框（默认开启）；`ScanThread` 与 `_do_scan()` 透传 `zero_day_focus` 参数 |

## 三、详细修改内容

### 3.1 scanner_engine.py

#### （1）`VulnScanner.scan_target()` 签名扩展

```python
def scan_target(self, target: str, ports: str = None,
               scan_type: str = 'quick', weak_pass: bool = False,
               zero_day_focus: bool = False) -> Dict[str, Any]:
```

- 新增关键字参数 `zero_day_focus`，默认 `False`，向后兼容（现有调用不受影响）。
- 在原有 `_flag_zero_day()`（对已匹配 CVE 做 KEV 精确 CVE-ID 标记）之后，当 `zero_day_focus=True` 时追加调用 `_flag_zero_day_focus()`，并将返回的新增数量累加进 `zero_day_count`：

```python
zero_day_count = self._flag_zero_day(vulnerabilities)
if zero_day_focus:
    zero_day_count += self._flag_zero_day_focus(scan_result, vulnerabilities)
```

#### （2）新增 `_flag_zero_day_focus()` — 0day 专项比对

```python
def _flag_zero_day_focus(self, scan_result: Dict, vulnerabilities: List[Dict]) -> int:
    """0day漏洞专项扫描 — 全量比对 CISA KEV 目录（最高优先级，重点提示）。"""
```

核心逻辑：

1. 通过 `self.db.get_kev_list(limit=2000)` 读取 CISA KEV 全量目录；
2. 调用 `_collect_scanned_products()` 聚合探测到的服务/产品/版本（按主机、保留端口）；
3. 跳过已通过常规 CVE 匹配 + `_flag_zero_day` 标记过的 `cve_id`（去重）；
4. 对每条 KEV 记录，用 `_product_matches_kev()` 判断探测产品名与 KEV 名称是否构成可信匹配——采用**整串包含 + 特异性**双重要求，避免 `windows`/`microsoft` 等通用产品名与数百条 KEV 记录误匹配导致结果刷屏；
5. 命中后追加一条 `severity=CRITICAL`、`is_0day=True`、`kev=True` 的新发现，描述含 CISA 收录日期与处置要求（`required_action`）；
6. 设 30 条安全上限，避免异常数据导致结果爆炸。

#### （3）新增 `_collect_scanned_products()` — 探测产品聚合

```python
@staticmethod
def _collect_scanned_products(scan_result: Dict) -> Dict[str, List[Tuple[str, str]]]:
    """聚合探测到的服务/产品/版本为小写字符串（按主机分组，保留端口）。"""
```

- 遍历 `scan_result['hosts']` 的存活主机与 `open` 端口；
- 对 `product`/`service`/`version` 三个字段做小写归一化，长度 ≥ 3 才纳入；
- 不做版本拆分——版本拆分会产出 `microsoft windows` 这类过于通用的产品名导致误匹配，版本处理交由 `_product_matches_kev` 内部完成。

#### （4）新增 `_product_matches_kev()` + `_has_specific_token()` — 可信产品级匹配

```python
@staticmethod
def _product_matches_kev(prod: str, name: str) -> bool:
    """整串包含 + 特异性双重要求，避免通用产品名刷屏。"""
```

- 候选串（完整值或其去版本主体）长度 ≥ 6，且**整串**出现在 KEV 名称中（非逐 token 子串匹配）；
- `_has_specific_token()` 要求候选串含至少一个长度 ≥4 的**非通用**令牌（依据模块级 `_GENERIC_PRODUCT_TOKENS` 集合，覆盖 windows/microsoft/linux/chrome 等厂商与操作系统词），从根上阻断通用产品名与数百条 KEV 记录的误匹配。

## 四、0day 专项扫描算法

```
端口扫描 + 服务识别
        │
        ▼
常规 CVE 匹配（VulnMatcher / 数据库搜索）
        │
        ▼
_flag_zero_day()  ── 对已匹配 CVE 做 KEV 精确 CVE-ID 标记
        │
        ▼ （zero_day_focus 开启时）
_flag_zero_day_focus()  ── 全量 KEV 目录产品级交叉比对
        │                    整串包含 + 特异性过滤（防刷屏）
        ▼
结果表深红高亮 + ⚠ 0DAY + zero_day_count 重点提示
```

**与常规扫描的区别：**
- 常规扫描仅对「已匹配到 CVE」的结果做 KEV 精确 CVE-ID 标记；
- 专项扫描额外对 KEV 目录中每条在野利用漏洞做**产品名级**比对，即使目标服务的版本无法被 CVE 数据库精确命中（版本缺失/产品名差异），也能捕捉到「目标正在运行存在已知在野利用漏洞的产品」这一高风险信号。

**防误报设计：** 产品级匹配无法精确到版本，天然存在「同一产品有多个在野利用 CVE」的过度报告风险。因此采用「整串包含 + 特异性」双重过滤——只有特异性产品名（如 `FortiOS SSL VPN`、`OpenSSH`）才会命中，通用产品名（如 `Microsoft Windows 10`、`Linux`）被 `_GENERIC_PRODUCT_TOKENS` 拦截，避免数百条无关 KEV 刷屏，守住「行业最低误报率」定位。

## 五、验证结果

1. **语法检查**：`python -m py_compile scanner_engine.py main_window.py` 通过。
2. **单元级冒烟测试**（`_flag_zero_day_focus` + 辅助方法）：
   - 输入：`FortiOS SSL VPN 7.0.1`（443） + `OpenSSH 8.2`（22）的目标指纹；
   - KEV 目录含 `CVE-2024-21762`（Fortinet FortiOS SSL VPN）与 `CVE-2026-50751`（Check Point VPN）；
   - 输出：正确命中 `CVE-2024-21762` → 追加 `is_0day=True, CRITICAL`，端口 443；`CVE-2026-50751` 未误报。
3. **防刷屏验证**：目标产品为通用 `Microsoft Windows 10`，KEV 目录含多条 Windows 类条目 → 命中 **0 条**（通用产品名被特异性过滤拦截，避免结果刷屏）。
4. **向后兼容**：`zero_day_focus` 默认 `False`，未开启时行为与改动前完全一致。

## 六、影响范围与兼容性

| 影响面 | 说明 |
|--------|------|
| 调用方 | 仅 `main_window.py` 的 `ScanThread` 调用 `scan_target()`，已同步透传；其余调用（API/调度）走默认 `False`，无影响 |
| 数据库 | 仅读 `cisa_kev` 表（通过 `Database.get_kev_list()`），无 schema 变更 |

| 报告 | 复用现有 `kev`/`is_0day` 展示逻辑（红底白字 + 「在野利用」徽章 + CISA KEV 链接） |
