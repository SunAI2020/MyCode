## 一、项目概述

### 1.1 项目背景

随着网络攻击面持续扩大，传统漏洞扫描工具面临三大挑战：

1. **误报率高**：基于正则匹配和版本号比对的传统方法产生大量误报，安全团队疲于人工核验
2. **威胁情报滞后**：CVE 数据更新不及时，无法第一时间感知全球威胁态势
3. **分析效率低**：大量扫描结果靠人工分析，缺少智能化辅助决策

本项目旨在构建一套 **AI 驱动的下一代智能漏洞扫描系统**，将大模型能力深度融入漏洞发现、核验、分析全流程，实现"扫描→验证→分析→报告"的自动化闭环。

### 1.2 核心创新

| 创新点 | 说明 |
|---|---|
| **AI 原生架构** | 默认通过 Claude Code CLI 调用大模型，无需配置 API Key，开箱即用 |
| **智能误报过滤** | AI 批量核验 CVE 匹配准确性，版本预过滤 + AI 上下文分析双重验证 |
| **CC SWITCH 集成** | 模型切换自动生效，用户可通过 Claude Code 自由切换底层模型 |
| **多维度仪表盘** | 8 张图表卡片实时展示安全态势，饼状图/柱状图/折线图直观呈现 |
| **全生命周期管理** | 资产发现 → 漏洞扫描 → AI 核验 → 代码审计 → 威胁情报 → 报告生成 |

## 三、核心功能详解

### 3.1 系统仪表盘

8 张图表卡片实时展示安全态势：

| 卡片 | 图表类型 | 数据维度 |
|---|---|---|
| CVE 漏洞库 | 饼状图（突出最大块） | CRITICAL/HIGH/MEDIUM/LOW 分布 |
| 扫描任务 | 饼状图 | 快速扫描/完整扫描/自定义扫描 |
| 今日扫描工作 | 饼状图 | 已完成/进行中/计划中/失败 |
| 漏洞发现 | 柱状图 + 折线图 | 近 30 天各严重等级趋势 |
| 代码审计发现 | 柱状图 + 折线图 | 近 30 天风险等级趋势 |
| 今日威胁情报 | 饼状图 | KEV/EPSS/IOC/威胁行为者/攻击模式 |
| 资产总数 | 饼状图 | 按资产类型分布 |
| 高危/严重漏洞 | 饼状图 | CRITICAL vs HIGH 比例 |

- 60 秒自动刷新
- matplotlib 嵌入 PyQt5，中文完美显示
- 趋势图每 5 天标注日期，避免拥挤

### 3.2 AI 增强漏洞扫描

**工作流程**：

```
网络扫描 -> 端口/服务/版本识别 -> CVE 匹配
    -> 版本预过滤（快速排除明显不匹配）
    -> AI 批量核验（并行 3 批次，每批 4 个漏洞）
    -> AI 风险重评（超越 CVSS 数值）
    -> AI 安全分析报告
```

**AI 核验能力**：
- 检测 7 类常见误报：产品不匹配、版本不匹配、服务类型错误、通用描述误匹配、已修复版本、OS不匹配、组件不存在
- 版本范围预过滤引擎：解析 CVE 描述中的版本约束，与目标版本比对
- 并行批次处理：`ThreadPoolExecutor` 3 线程并发，提速 2-3x
- 超时保护：单批次 300 秒，避免死锁

### 3.3 AI 代码安全审计

**支持语言**：Python、JavaScript、TypeScript、Java、Go、PHP、Ruby、C/C++、HTML

**检测能力**（10 类漏洞，40+ 正则模式）：

| 类别 | 严重度 | 检测模式 |
|---|---|---|
| SQL 注入 | CRITICAL | 字符串拼接、f-string、format()、%s 格式化 |
| 命令注入 | CRITICAL | os.system、subprocess shell=True、eval/exec |
| XSS 漏洞 | HIGH | innerHTML、document.write、response.write |
| 路径遍历 | HIGH | ../、..\、目录穿越 |
| 硬编码密钥 | HIGH | password/secret/key/token = "..." |
| 不安全反序列化 | CRITICAL | pickle.loads、yaml.load、marshal.loads |
| 弱加密算法 | MEDIUM | MD5、SHA1、DES、ARC4 |
| 不安全随机数 | LOW | random.randint、Math.random |
| 信息泄露 | MEDIUM | print/log 中输出密码/密钥 |
| SSRF 漏洞 | HIGH | requests.get 拼接用户输入 |

**AI 验证**：Claude 对每个候选漏洞进行上下文分析（前后各 5 行代码），识别误报类型（参数化查询、检测规则定义、LIKE 通配符、白名单验证等）。

## 四、AI 能力集成架构

### 4.1 设计理念

> **AI 能力默认加持，无需配置 API Key**

系统默认通过本机 Claude Code CLI 调用大模型，CC SWITCH 切换的模型自动生效。API Key 仅为可选回退方案。

### 4.2 AIClient 统一接口

```
class AIClient:
    """优先级: Claude Code CLI > Anthropic API"""
    def query(user_message, system_prompt=None) -> str
```

**技术特点**：
- stdin pipe 传递 prompt（无命令行长度限制）
- encoding='utf-8' + errors='replace'（Windows GBK 兼容）
- 自动检测 CLI 可用性
- 超时 300 秒，支持复杂分析场景
- Markdown 代码块自动剥离

### 4.3 AI 调用流程

```
用户操作
  +-- 漏洞扫描 -> AIScanEnhancer -> 批量 verify_vulnerabilities()
  |                                   +-- 版本预过滤 (rule-based)
  |                                   +-- AI核验 (Claude CLI, 并行3批次)
  |                                        +-- generate_ai_analysis()
  +-- 代码审计 -> AIAnalyzer -> scan_directory()
  |                               +-- 正则匹配 (10类漏洞)
  |                               +-- AIVerifier -> verify_issue() x N
  |                                    +-- 上下文分析 (前后5行)
  +-- 安全分析 -> AISecurity -> 安全态势AI评估
```

## 五、性能优化

### 5.1 并行化策略

| 模块 | 优化前 | 优化后 | 提速 |
|---|---|---|---|
| 端口扫描 | 单线程 | ThreadPoolExecutor(30) | ~15x |
| CVE 匹配 | 串行 | ThreadPoolExecutor(8) | ~5x |
| AI 漏洞核验 | 串行批次 | 并行 3 批次 | ~2.5x |
| 漏洞库回填 | 单线程 | 保留单线程（NVD 限流瓶颈） | — |

### 5.2 数据库优化

- WAL 模式（Write-Ahead Logging），读写并发不阻塞
- temp_store=2（临时表使用内存，不写磁盘）
- wal_autocheckpoint=1000（WAL 超 1MB 自动合并）
- 运行时临时文件定向到 D 盘（避免 C 盘满导致 I/O 错误）
- 分页加载（漏洞库首页 500 条，按需翻页）

### 5.3 网络健壮性

- NVD API 请求指数退避重试（2s->4s->8s->16s->32s，最多 5 次）
- SSL 错误 / 连接断开 / 读取超时 自动重试
- 429 限流自动等待
- 超时拆分：连接 10s + 读取 60s
