## 3. 详细修改内容

### 3.1 移植 16 类自包含检测项（`web_vuln_scanner.py`）

从 deep-eye（https://github.com/zakirkun/deep-eye）移植以下零新依赖检测能力，均遵循现有 `_check_*` 模式与统一 finding 结构：

| 检测项 | 键名 | 关键逻辑 |
|--------|------|---------|
| 二次/存储型 XSS | `stored_xss` | 注入唯一 token 后重取 sink URL 检测持久化回显 |
| HTTP 参数污染 | `hpp_pollution` | baseline/probe/polluted 差分（重复参数解析差异） |
| HTTP 方法覆盖绕过 | `http_method_override` | 真实 DELETE/PUT/PATCH 被拒后用覆盖头在 GET/POST 重放 |
| 批量赋值 | `mass_assignment` | 注入 `role=admin` 等特权字段，回显即命中 |
| 原型污染 | `prototype_pollution` | JSON 注入 `__proto__`/`constructor.prototype` |
| Host 头深检测 | `host_header_deep` | 8 向量（X-Forwarded-Host/X-Host/Forwarded 等） |
| CRLF 注入深检测 | `crlf_header_inject_deep` | 双重编码 + 自定义头注入，响应头回显标记 |
| 开放重定向深检测 | `open_redirect_deep` | 扩展参数名 + `//evil`/`javascript:`/`@` 混淆 payload |
| API BOLA 深检测 | `api_bola_deep` | `/api/` 路径 ID 突变，200 且内容差异明显 |
| 邮件头注入 | `email_injection` | contact/mail 路径注入换行头 |
| GraphQL 深检测 | `graphql_deep` | introspection + 批量查询探测 |
| 缓存投毒 | `cache_poisoning` | 未键控头 + cache-buster 注入重取 |
| 缓存欺骗 | `cache_deception` | 路径/后缀欺骗下缓存页含私有标记 |
| PHP Webshell/LFI | `php_webshell` | `php://filter`/`phar://`/`expect://` wrapper |
| SSE 注入 | `sse_injection` | event-stream 端点标记回显 |
| 竞态条件 | `race_condition` | 状态变更端点并发探测，状态码不一致 |

**排除项（理由）**：`http_smuggling`（raw socket 越权）、`h2_smuggle`（纯启发式）、`log4shell`（无 OOB 回连时噪声极高）、`websocket`（仅 stub）、`template_engine`（需 PyYAML）、browser/cve_intelligence/login_replay/openapi_ingest（第三方依赖）。

**支持性改动**：`SafeHTTPClient` 新增 `delete()/put()/patch()`；16 个新键加入 `enabled_checks` 默认列表与 `scan()` 分段 dispatch。

### 3.2 接入 AI 误报控制管线

- **`ai_scan_enhancer.py`** 新增 `WEB_VERIFY_SYSTEM_PROMPT`（聚焦 Web 误报规则：反射≠可利用、安全头缺失=加固建议、CORS 无凭据≠高危、指纹≠漏洞等）与 `verify_web_findings()` 方法，复用现有批处理/并行基础设施。
  - **成本预过滤**：仅核验 `category == 'web_vuln'` 且 `severity ∈ {CRITICAL/HIGH/MEDIUM}` 的活跃检测项，指纹/安全头/目录等确定性发现直接跳过。
  - 结果注解：确认项写 `ai_verified/ai_confidence/ai_reasoning/ai_remediation`，排除项写 `excluded_reason`。
- **`web_scanner.py`**：`WebSecurityScanner.__init__` 新增 `ai_enabled`，`scan()` 在 `_aggregate_findings` 后调用 `_ai_verify`；修复 `_persist` 丢弃 `remediation` 的问题。
- **`database.py`**：`web_scan_results` 新增 `remediation/ai_verified/ai_confidence/ai_reasoning/excluded_reason` 5 列（`ALTER TABLE` 兼容旧库），`add_web_scan_result` 同步扩展 INSERT。
- **API**：`WebScanRequest` 新增 `ai_enabled`，`/webscan` 透传到扫描编排器。

### 3.3 主窗口新增 Web 扫描页签（`main_window.py`）

- 新增 `WebScanThread(QThread)`，包装 `WebSecurityScanner.scan(...)`，带 `progress/finished/error` 信号与协作式 `stop()`。
- 新增 `_create_web_scan_tab()`：目标 URL 输入 + 检测项选项（目录枚举/ZAP/主动检测/AI误报核验）+ 启停按钮 + 进度条 + 结果表（6 列，含「AI判定」列）+ 日志区。
- 在 `_init_ui` 注册页签（置于「漏洞扫描」之后），并修正 `_on_tab_changed` 硬编码索引（漏洞库 3→4、审计 5→6、报告 7→9）。
- 新增 `_start_web_scan/_stop_web_scan/_on_web_scan_progress/finished/error` 及 `_populate_web_result_table/_load_last_web_scan_result`，日志统一走 `_safe_log('web_scan_log', ...)`。

### 3.4 AI 核验速度与 token 消耗优化

- `VERIFY_VULN_SYSTEM_PROMPT` 由 ~30 行精简为 ~12 行要点。
- `_build_vuln_description`：省略空字段（`cvss_score/affected_versions/cwe` 缺失不输出），`description` 截断 400→200 字符。
- `BATCH_SIZE` 4 → 6（子进程启动次数与 system prompt 重复传输减半）。
- 保守保留策略不变：AI 失败仍保留 finding。

### 3.5 修复停止 AI 核验闪退

**根因**：`_stop_ai_verify` 对阻塞在 `subprocess.run()`（Claude Code CLI，默认 300s）中的 `AIScanEnhanceThread` 调用 `terminate()`，`requestInterruption()` 未被 `run()` 检查，强杀原生线程导致主线程/子进程管道竞态闪退，且 `claude` 子进程孤儿化。

**修复**：
- `ai_client.py`：`query()` 改为 `subprocess.Popen` + stdout/stderr 重定向临时文件（避免管道死锁）+ `poll()` 轮询检查 `stop_event`/超时，命中即 `terminate()→kill()` 子进程并抛 `RuntimeError`；新增 `_run_claude()`/`_terminate_proc()`。
- `ai_scan_enhancer.py`：`AIScanEnhancer.__init__` 新增 `stop_event`，透传给所有 `client.query()` 调用。
- `main_window.py`：`AIScanEnhanceThread` 新增 `_stop_event` 与 `stop()`；`_stop_ai_verify` 先 `stop()` → `wait(8000)`，**删除 `terminate()` 分支**。

### 3.6 Web 扫描报告自动保存

- **`report_generator.py`** 新增 `render_web_scan_html(result)`（自包含 HTML 报告：目标/严重度统计 chips/AI 核验统计/指纹识别/高危路径/目录枚举/ZAP 告警/漏洞明细含「AI判定·证据·修复建议」列）与 `generate_web_scan_report(result, output_dir)`（写入文件并返回路径）。
- **`main_window.py`**：Web 扫描页签新增「保存报告」按钮；`_on_web_scan_finished` 写入 `self.last_web_scan_result` 后调用 `_auto_save_web_scan_report()`，自动生成报告并 `db.save_report(..., type='web_scan', ...)` 登记到报告中心；新增 `_save_web_scan_report`（手动另存）与 `_web_scan_report_summary`。
