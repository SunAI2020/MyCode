### 2.2 架构设计说明书（SAD）核心设计

- **架构风格**：微服务（资产/扫描/漏洞/报告/AI/情报/通知/认证 8 服务）
- **技术栈**：Go/Gin + Python/FastAPI + React/Vue + PostgreSQL + Redis + Elasticsearch + Kafka + MinIO + K8s
- **插件体系**：Plugin SDK（scan/verify/remediate 三接口）+ 沙箱 + 版本管理
- **数据架构**：UUID 主键 / JSONB / 树状资产结构 / 多租户隔离
- **部署**：K8s HA + 边缘扫描节点（数据不出域）
- **安全**：纵深防御 5 层（WAF→MFA→RBAC/ABAC→TLS/AES→审计）

## 四、架构差异分析（SAD vs 实际）

| 维度 | SAD 设计 | 实际实现 | 差距评级 |
|------|---------|---------|---------|
| 架构风格 | 微服务 8 服务 | 单体（PyQt5 GUI + FastAPI 同进程） | 🔴 严重 |
| 后端框架 | Go/Gin + Python/FastAPI | Python/FastAPI（已落地） | 🟢 已满足 |
| 前端框架 | React 18 / Vue 3 / Flutter | React 18 脚手架（未完成，无构建产物） | 🟠 中等 |
| 数据库 | PostgreSQL 14+ | SQLite 运行期；PG 迁移工具未接线 | 🔴 严重 |
| 缓存 | Redis 7+ | 无 | 🔴 严重 |
| 搜索 | Elasticsearch 8.x | SQLite LIKE | 🔴 严重 |
| 消息队列 | Kafka 3.x | FastAPI BackgroundTasks + 进程内 _jobs | 🔴 严重 |
| 对象存储 | MinIO | 本地文件系统 | 🟠 中等 |
| 容器编排 | K8s | 无（无 Dockerfile/docker-compose） | 🔴 严重 |
| 监控告警 | Prometheus+Grafana | 无（仅 /api/health） | 🔴 严重 |
| API 网关 | Kong/Ingress | FastAPI CORS 直连 | 🟠 中等 |
| 插件体系 | SDK + 沙箱 + 市场 | 无 | 🔴 严重 |
| 多租户 | Tenant 隔离 | 无 | 🔴 严重 |

**架构结论**：功能模块已基本对齐需求，但架构层仍为单机单体，与 SAD 微服务/云原生设计存在结构性鸿沟。这是通往企业级产品的主要障碍。
