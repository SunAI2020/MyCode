## 一、目标与范围

本次升级在 P0（测试体系 + FastAPI API 层 + 双后端配置）基础上，聚焦两大方向：

| 编号 | 方向 | 内容 | 优先级 |
|------|------|------|--------|
| 改进1 | Web 应用安全扫描 | OWASP ZAP 被动扫描、自定义 HTTP 探测、Web 指纹识别、目录枚举 + 备份文件检测 | 核心 |
| 改进2 | P1 核心能力补齐 | 弱口令检测、漏洞处置工作流、用户+RBAC、React Web 前端 | 核心 |

**设计原则**（延续项目既有约定）：
1. **保守安全**：ZAP 不可用 / 探测失败 → 明确降级为内置引擎，绝不丢真实漏洞。
2. **零强依赖**：全部核心功能用标准库 + 已装依赖（`requests`/`fastapi`）实现，`paramiko`/`zaproxy` 等为可选增强。
3. **数据主权**：前端 SPA 由 FastAPI 本地托管，无 CDN 外链。
4. **线程安全**：所有新扫描模块支持 `progress_callback`，走既有消息缓冲模式。
5. **测试先行**：每个新模块配 pytest 用例，保证零回归。

## 二、改进1：Web 应用安全扫描

### 2.1 模块架构

```
web_scanner.py
  ├── WebFingerprinter      # Web 指纹识别（CMS/框架/中间件）
  ├── HTTPProber            # 自定义 HTTP 请求探测
  ├── DirectoryEnumerator   # 目录枚举 + 备份文件检测
  ├── ZAPScanner            # OWASP ZAP 被动扫描（REST API，可选）
  └── WebSecurityScanner    # 编排：指纹 → 探测 → 目录 → ZAP
```

### 2.2 Web 指纹识别

- **中间件**：`Server`/`X-Powered-By`/`X-AspNet-Version` 响应头 → nginx/apache/IIS/Tomcat 等。
- **CMS/框架**：响应体特征库（`wp-content`、`wp-includes`、`wp-json` → WordPress；`X-Drupal-Cache`/`drupal` → Drupal；`__VIEWSTATE` → ASP.NET；`csrfmiddlewaretoken` → Django；`Set-Cookie: laravel_session` → Laravel；`X-Powered-By: Express` → Node/Express）。
- **版本提取**：正则匹配 `Server: Apache/2.4.49`、`X-AspNet-Version: 4.0` 等。
- **输出**：`{product, category, version, confidence, evidence}` 列表，可对接既有 CVE 匹配。

### 2.3 自定义 HTTP 请求探测

- 支持自定义 `method/headers/body/path/timeout/follow_redirects`。
- 返回 `status/headers/body/preview/elapsed`，用于手写 PoC 验证与响应指纹比对。
- 内建常见高危路径探测（`/.git/config`、`/.env`、`/actuator/env`、`/server-status` 等）。

### 2.4 目录枚举 + 备份文件检测

- 内置常见目录词表（`admin`、`backup`、`config`、`test`、`upload`、`logs` 等）+ 备份后缀（`.bak`、`.old`、`~`、`.swp`、`.sql`、`.zip`、`.tar.gz`、`.7z`、`.orig`、`.save`）。
- 按状态码分类：`200/301/403` 命中，`404` 跳过；对备份文件输出独立告警。
- 并发受控（默认 10 线程），支持 `progress_callback` 与限速。

### 2.5 OWASP ZAP 被动扫描

- 通过 ZAP REST API（`http://<host>:<port>/JSON/...`，默认 `127.0.0.1:8080`）对接，**零新 pip 依赖**（复用 `requests`）。
- 流程：`context` → 打开目标 URL → `spider`（可选）→ `passiveScan` → 拉取 `alerts`。
- ZAP 未启动 → 捕获异常返回 `{'available': False, 'reason': ...}`，上层降级到内置引擎，**不抛异常中断扫描**。
- 告警映射到统一 `severity` 分级（High/Medium/Low/Informational → CRITICAL/HIGH/MEDIUM/LOW/INFO）。

## 三、改进2：P1 核心能力补齐

### 3.1 弱口令检测模块（`weak_password_scanner.py`）

| 组件 | 说明 |
|------|------|
| `WeakPasswordScanner` | 编排器：按协议分发到对应 handler，聚合结果 |
| `HTTPBasicAuthHandler` | HTTP Basic 认证爆破（标准库） |
| `FTPHandler` | FTP 登录（`ftplib`，标准库） |
| `SSHHandler` | SSH 登录（`paramiko`，可选 import） |
| `GenericSocketHandler` | 通用 TCP banner/响应比对（用于 SMTP/POP3/IMAP 等服务识别） |

- **字典来源**：复用 `threat_intel.db` 的 `weak_passwords` 表（`ThreatIntelDB.get_weak_passwords()`），可扩展用户自定义字典。
- **集成**：作为扫描流水线独立阶段（Phase：端口扫描 → 服务识别 → **弱口令检测** → CVE 匹配 → AI 验证）。
- **节流与安全**：每目标每服务默认限速、失败重试上限、支持 `cancel` 标志，避免对生产目标造成影响。

### 3.2 漏洞处置工作流（`workflow.py`）

状态机（管理闭环）：

```
                  ┌────────────── FALSE_POSITIVE (终态)
                  │
OPEN ──► CONFIRMED ──► IN_PROGRESS ──► FIXED ──► VERIFIED ──► CLOSED (终态)
  │                         │            │
  └────── DUPLICATE (终态)   └──► REOPENED（回退）
```

- 合法状态：`OPEN / CONFIRMED / IN_PROGRESS / FIXED / VERIFIED / CLOSED / FALSE_POSITIVE / DUPLICATE / REOPENED`。
- 非法流转（如 `FALSE_POSITIVE → CONFIRMED`）被状态机拒绝，记录原因。
- 每条处置记录支持：`assignee`（指派）、`note`（备注）、`reopen_reason`（重开原因）、时间戳全链路审计。

### 3.3 用户 + RBAC 系统（`auth_rbac.py`）

| 组件 | 说明 |
|------|------|
| 密码哈希 | `hashlib.pbkdf2_hmac`（标准库，10 万次迭代 + 随机盐），兼容未来 `bcrypt` 替换 |
| 会话令牌 | HMAC-SHA256 签名 token（标准库），带过期时间与角色声明 |
| 角色 | `admin`（全权）/ `analyst`（扫描+处置）/ `auditor`（只读审计）/ `viewer`（只读） |
| RBAC 依赖 | FastAPI `require_role(...)` 依赖，装饰式授权 |

- 默认账号：`admin / admin123`（首次登录强制提示修改，`must_change_password` 标记）。
- 端点：`POST /api/v1/auth/login`、`GET /api/v1/auth/me`、`POST /api/v1/users`、`GET/PUT/DELETE /api/v1/users/{id}`（admin 专属）。

### 3.4 React Web 前端（多用户访问）

- **技术栈**：React 18（本地静态资源）+ 原生 Fetch + 无构建步骤，由 FastAPI `StaticFiles` 托管。
- **页面**：登录 / 仪表盘 / 资产 / 扫描任务 / Web 扫描 / 弱口令 / 漏洞处置 / 用户管理 / CVE 查询。
- **认证**：登录后保存 HMAC token 到 `localStorage`，所有请求携带 `Authorization: Bearer`。
- **响应式**：桌面 + 平板自适应，暗色主题。
- **生产迁移**：预留 Vite 构建迁移路径（`frontend/package.json` 说明），当前零构建保证离线可用。

## 六、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| ZAP 未部署 | 被动扫描缺失 | 优雅降级到内置引擎，返回 `available: false` |
| 弱口令爆破影响生产目标 | 业务中断 | 默认低并发 + 限速 + 明确授权提醒 |
| 新增表破坏既有数据库 | 回归 | 全部 `CREATE TABLE IF NOT EXISTS`，不改既有表结构 |
| token 泄露 | 越权 | HMAC 签名 + 过期时间 + 审计日志 |
| React 无构建步骤的规模限制 | 大型应用性能 | 预留 Vite 迁移路径，当前规模（<10 页面）足够 |
