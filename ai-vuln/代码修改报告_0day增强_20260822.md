## 一、需求背景

上一版已落地「0day 漏洞专项扫描」，对 CISA KEV 目录做产品级交叉比对，标记 `is_0day` 并在结果表深红高亮。本版在其基础上补齐 4 项 0day 风险增强，进一步扩大在野利用识别覆盖、突出「最高优先级立即处置」清单：

1. 0day 专项扫描结果在「AI 安全报告」中**单独成节**，突出「最高优先级立即处置」清单；
2. 接入 **EPSS 高分（>0.9）** 作为 0day 风险的第二判据，扩大在野利用识别覆盖；
3. 对 **known_ransomware**（已知勒索软件利用）标记的 KEV 条目追加更醒目的红色警示；
4. 《下一代智能漏洞扫描系统 Pro - 安全扫描报告》汇总项增加 **0day 漏洞数量**，详情部分标注「0day 漏洞」。

### 3.1 database.py — 数据访问层

#### （1）`ThreatIntelDB.get_kev_by_cve()` 新增

```python
def get_kev_by_cve(self, cve_id):
    """按 CVE 编号查询单条 KEV 记录（含 known_ransomware / required_action / due_date）。"""
    c = self.conn.cursor()
    c.execute('SELECT * FROM cisa_kev WHERE cve_id=?', (cve_id,))
    r = c.fetchone()
    return dict(r) if r else None
```

#### （2）`Database` 门面暴露 EPSS 与单条 KEV 查询


### 3.2 scanner_engine.py — 0day 双判据 + 勒索软件标记

#### （1）`_flag_zero_day()` 重写为双判据

```python
def _flag_zero_day(self, vulnerabilities: List[Dict]) -> int:
    """0day/高危利用风险标记（最高优先级，重点提示）。

    采用双判据识别在野/高危利用风险：
    判据一：CISA KEV（正被攻击者活跃利用）；
    判据二：EPSS 利用概率 > 0.9（高分，扩大在野利用识别覆盖）。
    任一命中即标记 is_0day 并将严重度提升至 CRITICAL；对 KEV 中
    known_ransomware 标记的条目追加更醒目的「已知勒索软件利用」警示。
    """
    if not self.db:
        return 0
    flagged = 0
    for v in vulnerabilities:
        cve_id = v.get('cve_id')
        if not cve_id:
            continue

        is_kev = False
        kev_rec = None
        epss_score = None
        try:
            if hasattr(self.db, 'is_kev'):
                is_kev = bool(self.db.is_kev(cve_id))
        except Exception:
            is_kev = False

        if is_kev:
            try:
                kev_rec = self.db.get_kev_by_cve(cve_id) if hasattr(self.db, 'get_kev_by_cve') else None
            except Exception:
                kev_rec = None
        else:
            try:
                ep = self.db.get_epss(cve_id) if hasattr(self.db, 'get_epss') else None
                epss_score = ep.get('epss_score') if ep else None
            except Exception:
                epss_score = None

        epss_high = epss_score is not None and epss_score > 0.9
        if not is_kev and not epss_high:
            continue

        v['is_0day'] = True
        v['kev'] = bool(is_kev)
        v['epss_high'] = epss_high
        if epss_score is not None:
            v['epss_score'] = epss_score

        ransomware = False
        if kev_rec:
            ransomware = bool(kev_rec.get('known_ransomware'))
            v['known_ransomware'] = ransomware
            v['kev_due_date'] = kev_rec.get('due_date') or ''
            v['kev_required_action'] = kev_rec.get('required_action') or ''

        if v.get('severity') not in ('CRITICAL',):
            v['severity'] = 'CRITICAL'

        # 前缀按最高优先级来源生成（勒索软件 > KEV 在野利用 > EPSS 高分）
        if is_kev and ransomware:
            prefix = '【已知勒索软件利用】'
        elif is_kev:
            prefix = '【0day/活跃利用】'
        else:
            prefix = '【0day/高危利用概率(EPSS)】'
        if not (v.get('description') or '').startswith(prefix):
            v['description'] = prefix + (v.get('description', '') or '')
        flagged += 1
    return flagged
```

**核心变化：**

1. **EPSS 第二判据**：原仅 `is_kev` 命中才标记，现当 `EPSS > 0.9` 也标记 `is_0day`、`epss_high=True`，并写入 `epss_score`，扩大在野利用识别覆盖（捕获未被 KEV 收录但极可能被利用的 CVE）。
2. **勒索软件警示**：KEV 命中时读取 `known_ransomware`，命中者描述前缀升级为 `【已知勒索软件利用】`，并附带 `known_ransomware`/`kev_due_date`/`kev_required_action` 字段供报告展示。
3. **查询优化**：KEV 命中走 `get_kev_by_cve`（顺带取勒索标记），未命中才查 EPSS，避免双查；`hasattr` 防御，向后兼容旧门面。

## 四、0day 风险识别算法

```
常规 CVE 匹配（VulnMatcher / 数据库搜索）
        │
        ▼
_flag_zero_day()  双判据标记
        ├─ 判据一：CISA KEV 命中（is_kev）
        │           └─ known_ransomware=1 → 【已知勒索软件利用】红警
        │           └─ 否则 → 【0day/活跃利用】
        ├─ 判据二：EPSS 利用概率 > 0.9 → 【0day/高危利用概率(EPSS)】
        ▼
_flag_zero_day_focus()（zero_day_focus 开启时）
        产品级 KEV 交叉比对 → 追加 known_ransomware 标记
        ▼
结果表深红高亮 + ⛔勒索软件 / ⚠EPSS高危 / ⚠0DAY
        ▼
AI 安全报告「0day/在野利用专项」章节 + 扫描报告「0day漏洞」汇总/徽章
```

**双判据设计**：EPSS > 0.9 捕获「未被 CISA KEV 收录、但利用概率极高」的 CVE（如新近披露、PoC 已公开但尚未进入 KEV 目录），与 KEV 形成互补，扩大在野利用识别覆盖；两者均标记 `is_0day`、提升 CRITICAL，统一纳入 `zero_day_count`。

**误报控制**：EPSS 阈值取 0.9（而非 0.5 等更宽阈值），只在高利用概率区间才升级为 0day，避免 EPSS 中等分值批量误标，守住「行业最低误报率」定位。

## 五、验证结果

1. **语法检查**：`python -m py_compile database.py scanner_engine.py main_window.py report_generator.py ai_security.py` 通过。
2. **单元测试**：`tests/test_database.py` + `tests/test_report_render.py` + `tests/test_risk_scoring.py`（101 项）全绿；`tests/test_scanner_ai.py`（23 项）全绿。
3. **`_flag_zero_day()` 双判据单测**（桩 DB）：
   - `CVE-KEV-RANSOM`（KEV + known_ransomware=1）→ `is_0day=True, kev=True, known_ransomware=True`，前缀 `【已知勒索软件利用】`；
   - `CVE-KEV`（仅 KEV）→ 前缀 `【0day/活跃利用】`；
   - `CVE-EPSS-HIGH`（EPSS 0.97）→ `is_0day=True, epss_high=True, kev=False`，前缀 `【0day/高危利用概率(EPSS)】`；
   - `CVE-EPSS-LOW`（EPSS 0.5）→ 不标记；无 `cve_id` → 不标记。
4. **报告渲染冒烟测试**：构造含勒索/EPSS/普通漏洞的合成 `scan_data`，确认：
   - AI 安全报告含「0day/在野利用专项 — 最高优先级立即处置清单」章节及 `badge-kev`/`badge-ransom`/`badge-epss`；
   - 扫描报告含「0day漏洞」统计块与「0day漏洞」「⛔勒索软件」徽章。
5. **向后兼容**：`_flag_zero_day()` 签名不变；所有新字段均为新增写入，未开启相关能力时行为与改动前一致。

## 六、影响范围与兼容性

| 影响面 | 说明 |
|--------|------|
