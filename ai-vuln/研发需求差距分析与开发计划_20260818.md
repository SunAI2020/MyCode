| 缓存 | Redis 7+ | 无 | 🔴 严重 |
| 搜索 | Elasticsearch 8.x | SQLite LIKE | 🔴 严重 |

## 四、功能模块差距详细分析（FR-01 ~ FR-17，代码核实）

### FR-01 资产管理（~45%）
- ✅ 资产发现（nmap CIDR/IP 范围展开，纯 Python `ipaddress` 实现）、CRUD、类型/重要性/OS 下拉、url 字段（对接 Web 扫描）。
- ❌ 仍缺：批量 CSV/Excel 导入、标签系统、6 阶段生命周期状态机、树状结构（组织→部门→网络→子网→资产）。

### FR-02/03 扫描策略与任务（~40%）
- ✅ 扫描类型（quick/full）、任务创建/状态/进度、停止、`scan_policies` 表。
- ❌ 仍缺：插件体系、策略模板/版本管理、定时调度、优先级调度、暂停/恢复、分布式执行。

### FR-04 漏洞管理（~55%）
- ✅ CVE 库（分页/搜索/CVSS 筛选）、`vuln_dispositions` 表 + `workflow.py` 状态机（**本轮新增**）、`scan_results`/`web_scan_results` 存储。
- ❌ 仍缺：漏洞相似度去重、evidence/remediation 结构化展示。

### FR-05 风险分析（~60%）
- ✅ AI 批量核验（置信度/风险重评/KEV 加权）、CVSS、`generate_ai_analysis` 报告。
- ❌ 仍缺：多因子风险评分（资产价值×威胁×脆弱性）、EPSS 融合评分。

### FR-06 修复管理（~25%）
- ✅ AI 生成修复建议（`ai_remediation`）。
- ❌ 仍缺：可执行修复脚本、工单集成（Jira/ServiceNow/钉钉/飞书，全库 grep 无结果）、复测验证闭环。

### FR-07 报告中心（~50%）
- ✅ HTML/MD/TXT + PDF(weasyprint)/Word(docx)（**本轮已具备**，含 HTML 回退降级）。
- ❌ 仍缺：5 类预定义模板、定时分发、图表导出完善。

### FR-08 系统管理（~55%）
- ✅ 用户 CRUD + 角色 + 审计日志（`audit_logs` 表 + `add_audit_log`）——**本轮新增**。
- ❌ 仍缺：配置中心、组织管理、MFA、令牌吊销（见第八节缺陷 #1）。

### FR-09 API 接口（~65%）
- ✅ REST：`/api/v1/{assets,scans,cve,intel,audit,reports,dashboard,auth,users,webscan,weakpass,workflow}`，Swagger `/api/docs`，API Key + Bearer 双认证。
- ❌ 仍缺：GraphQL、Webhook、开放 SDK 文档、API 限流。

### FR-10 插件管理（~0%）
- ❌ 完全缺失：插件 SDK/上传/版本/热加载/沙箱。

### FR-11 多类型扫描（~20%）
- ✅ 通用 OS + 端口 + **Web 应用扫描（本轮新增）**。
- ❌ 仍缺：网络设备（交换机/路由器）、安全设备、IoT、工控、国产化（麒麟/统信/达梦等）专项检测。

### FR-12 大数据组件扫描（~10%）
- ❌ 仅端口层面识别，无 Hadoop/ES/Kafka/ClickHouse 等深度漏洞检测。

### FR-13 弱口令检测（~40%）
- ✅ HTTP Basic / FTP / SSH（paramiko 可选）+ 字典库（`weak_passwords` 表 + 内置兜底）——**本轮新增**。
- ❌ 仍缺：MySQL/PostgreSQL/Redis/MongoDB/RDP/Telnet 等协议（代码如实返回"暂不支持"），无分布式字典、无锁定策略规避。

### FR-14 漏洞库规则（~60%）
- ✅ NVD 同步框架 + CWE/补丁链接回填 + 去重 + FAKE 清理。
- ❌ 仍缺：450K+ 规模扩充、增量实时同步、供应商公告自动化。

### FR-15 资产管理增强（~20%）
- ❌ 树状结构、服务/Web/漏洞/历史多维详情未完整实现。

### FR-16 自动化漏洞验证（~35%）
- ✅ AI 辅助验证（`AIScanEnhancer`/`AIVerifier`）。
- ❌ 仍缺：PoC 安全执行沙箱、复测自动验证。

### FR-17 隐匿站点探测（~25%）
- ✅ 端口服务识别 + Web 指纹 + 目录枚举（本轮新增）。
- ❌ 仍缺：暴露面综合分析报告、暗网/深网监测。

## 八、具体代码缺陷清单（本轮审查发现，需优先修复）

> 以下为对照实际代码逐行核实的问题，作为技术债务的**可执行清单**（而非抽象风险）。

| # | 位置 | 问题 | 严重度 |
|---|------|------|--------|
| 1 | `api/auth.py:31` / `api/dependencies.py:59` | **停用/删除的用户仍可访问**：令牌校验路径只查 `must_change_password`，从不查 `active`；角色取自令牌而非 DB，停用/降权/删除的账户在令牌 12h 有效期内继续拥有权限，且无服务端吊销机制 | 🔴 高 |
| 2 | `db/migrate.py:59-68` | **PG 迁移破坏外键**：迁移对 SERIAL 表剥离 `id` 列让 PG 重排主键，但 `scan_results.task_id`/`audit_issues.audit_id` 保留 SQLite 旧 id，`clear_all()` 后主键不连续时引用失效，迁移要么 FK 违规失败要么错挂记录 | 🔴 高 |
| 3 | `weak_password_scanner.py:68` | **HTTP Basic 误报**：`return r.status_code == 200`，凡返回 200（非 Basic 认证站点、登录页、开放首页）即判"弱口令命中"，产生大量误报 | 🟡 中 |
| 4 | `database.py:1267` | **`DB_BACKEND=postgresql` 静默失效**：`Database` 硬编码 SQLite，`db/backend.py` 抽象从未被引用 | 🟡 中 |
| 5 | `api/models/__init__.py:80` / `api/routers/webscan.py:53` | **SSRF**：`WebScanRequest`/`HTTPProbeRequest` 缺 URL scheme 校验（`AssetCreate` 有而这两者无），任意已认证用户可探测云元数据/内网地址 | 🟡 中 |
| 6 | `intel_sources.py:383` | **NVD 同步全表入内存**：`search_cve(limit=9990000)` 每次同步加载全部 CVE 建去重集合（库约 225MB） | 🟢 低 |
| 7 | `api/routers/scans.py:13,21` | **列表/详情全表加载**：`get_all_tasks(limit=99999)` 拉全表再 Python 过滤，分页未下沉 SQL | 🟢 低 |

## 九、开发计划（分阶段、可执行）

> 原则：**先修安全与数据正确性缺陷 → 打通 PG 运行期 → 补核心扫描能力 → 平台化 → 云原生**。每项标注目标文件与工作量（人周）。

### 阶段 P0 —— 安全与正确性修复（第 1-2 周，最高优先）

| 任务 | 目标文件 | 说明 | 工作量 |
|------|---------|------|--------|
| 令牌吊销 + active 校验 | `api/dependencies.py`、`api/auth.py` | `require_role`/`verify_api_key`/`get_current_user` 增加 `active` 检查；引入令牌版本/吊销表 | 0.5 |
| 修复 PG 迁移外键 | `db/migrate.py` | 迁移时保留 SQLite 原始 `id`（显式 `INSERT` 含 id），或建 id 映射表 | 0.5 |
| HTTP Basic 误报修复 | `weak_password_scanner.py` | 仅当响应先 401 挑战后再 200 才判定命中，或校验 `WWW-Authenticate` 头 | 0.5 |
| URL scheme 校验 | `api/models/__init__.py` | `WebScanRequest`/`HTTPProbeRequest` 复用 `_validate_http_url` + 内网地址告警 | 0.25 |
| 分页下沉 SQL | `api/routers/scans.py`、`database.py` | `get_all_tasks` 支持 `LIMIT/OFFSET`/`WHERE id=` | 0.25 |

### 阶段 P1 —— 打通 PostgreSQL 运行期（第 3-5 周）

| 任务 | 目标文件 | 说明 | 工作量 |
|------|---------|------|--------|
| Database 接入后端抽象 | `database.py` | `_connect()` 改为 `create_backend()`，SQL 占位符按后端切换（`?`→`%s`） | 1.5 |
| Alembic 版本化迁移 | 新增 `db/alembic/` | 替换手写 `migrate.py`，支持升级/回滚 | 1 |
| 连接池与事务封装 | `db/backend.py` | PG `ThreadedConnectionPool` 的 get/put 配对，修连接泄漏 | 0.5 |
