## 修改概述

本次修改主要围绕仪表盘可视化改造与"今日工作"状态跟踪能力补齐，共涉及 5 个源文件：

1. **仪表盘三张图表改造**：扫描任务饼图、今日工作堆叠柱状图、漏洞等级饼图。
2. **Web 扫描停止修复**：点击停止后立即中断探测并隐藏进度条。
3. **工作状态生命周期跟踪**：为资产管理、Web扫描、AI代码审计、AI代码质量检测、漏洞库更新、威胁情报等类型补齐「进行中 / 被终止 / 已完成」全程埋点。
4. **定时扫描「计划中」跟踪**：添加定时任务后计入「计划中」，触发/取消时正确转移。

## 详细修改

### 1. 仪表盘三张图表改造（`main_window.py`）

**扫描任务（卡片2）** —— 由「按扫描类型（快速/完整/自定义）」改为按 5 类任务次数画饼状图：

- 漏洞扫描、Web扫描、AI代码审计、AI代码质量检测、威胁情报。

**今日工作（卡片3）** —— 由「按工作类型计数」的饼图改为四段堆叠柱状图：

- 横轴：资产管理、漏洞扫描、Web扫描、AI代码审计、AI代码质量检测、漏洞库更新、威胁情报（7 项）。
- 纵轴（分段）：已完成（绿）、进行中（橙）、计划中（蓝）、被终止（红）。
- 新增 `_draw_stacked_bar()` 绘制方法，卡片类型新增 `stack`。

**高危/严重漏洞 → 漏洞等级（卡片8）** —— 标题改为「漏洞等级」，数据源由 CVE 库改为扫描发现的漏洞 `scan_results`，按严重/高危/中危/低危四级画饼图。

### 2. Web 扫描停止修复（`web_scanner.py` + `main_window.py`）

**问题**：点击停止后仅置位停止标志，但「高危敏感路径探测」和「目录枚举」阶段不检查该标志，导致扫描继续运行、进度条不消失。

**修复**：

- `HTTPProber.probe_high_risk_paths()` 新增 `stop_event` 参数，逐路径检查、命中即中断。
- `DirectoryEnumerator.enumerate()` 新增 `stop_event` 参数，循环内检查并用 `shutdown(wait=False, cancel_futures=True)` 立即退出线程池。
- `WebSecurityScanner.scan()` 将 `stop_event` 传入上述两阶段，并在指纹识别后增加停止检查。
- `_stop_web_scan()` 点击后立即隐藏进度条。

### 3. 今日工作状态生命周期跟踪（`database.py` + 多文件）

**数据层**（`database.py`）：

- `work_log` 表新增 `status` 列（默认「已完成」），带 `ALTER TABLE` 迁移兼容旧库。
- 新增会话式方法：
  - `start_work(work_type) -> id`：插入「进行中」记录并返回会话 ID。
  - `finish_work(id, status)`：更新会话终态。
  - `delete_work(id)`：删除记录（如计划中任务转交实际执行）。
  - `log_work(work_type, status='已完成') -> id`：瞬时操作直接以终态记录。
- 新增聚合方法 `get_today_work_status_matrix()`：返回 7 类型 × 4 状态的今日工作矩阵。

**各工作类型埋点**：

| 工作类型 | 启动（进行中） | 完成（已完成） | 停止/出错（被终止） |
|----------|--------------|--------------|--------------------|
| 资产管理 | —（瞬时） | `log_work('资产管理')` | — |
| Web扫描 | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| AI代码审计 | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| AI代码质量检测 | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| 漏洞库更新（更新按钮） | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| 漏洞库更新（CVE修复） | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| 威胁情报 | `start_work` | `finish_work(已完成)` | `finish_work(被终止)` |
| 漏洞扫描（手动） | 沿用 `scan_tasks.status` | 同左 | 同左 |

> AI代码审计 / AI代码质量检测的统计源由 `audit_history`/`reports` 切换为 `work_log`，避免与生命周期埋点重复计数。

### 4. 定时扫描「计划中」跟踪（`main_window.py`）

- `_add_scheduled_scan()`：添加任务时 `log_work('漏洞扫描', '计划中')`，记录 work_id 至 `self._scheduled_work_ids`。
- `_on_scheduled_scan()`：任务触发执行时 `delete_work()` 删除「计划中」标记，改由扫描任务自身跟踪。
- `_cancel_scheduled()`：取消任务时 `finish_work(被终止)`。

### 5. 漏洞库更新覆盖修复（`vuln_db_manager.py`）

该线程会同时发出 `error`+`finished` 或 `stop`+`finished`，导致「被终止」被 `finished` 回写为「已完成」。新增 `_search_stopped` 标志，完成后不再覆盖终态。

## 数据库变更

### `assets_system.db` → `work_log` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| work_type | TEXT | 工作类型（7 类之一） |
| status | TEXT DEFAULT '已完成' | 状态：已完成/进行中/计划中/被终止 |
| created_at | TEXT | 记录时间（`datetime('now','localtime')`） |

迁移语句（自动执行）：

```sql
ALTER TABLE work_log ADD COLUMN status TEXT DEFAULT '已完成';
```

## 注意事项

1. **「进行中」为瞬态值**：仅在任务运行期间切到仪表盘刷新才可见，结束后归入「已完成/被终止」。
2. **「计划中」仅漏洞扫描产生**：其余 6 类是一次性操作，无排队队列，故「计划中」恒为 0。
3. **x 轴标签用「Web扫描」**（大写 W），与代码库既有 `log_work('Web扫描')` 及 UI 文案保持一致。
4. AI代码审计 / 质量检测的「已完成」统计源已切换至 `work_log`，本次代码上线前的历史「今日」审计记录不会计入（仅影响当天首次切换的瞬时窗口）。
