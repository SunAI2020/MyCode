## 一、概述

本次升级对标国际主流漏洞扫描系统（Nessus / Qualys / OpenVAS / Burp / Invicti / Wiz），
以「**借思路自建、复用现有引擎**」的方式，补齐三项核心能力与两项工程增强，
并修复代码审查与安全审查发现的缺陷。核心诉求是：**不引入闭源依赖或重量级外部系统**，
把竞品的差异化能力（认证扫描、确定性验证、可达性优先、蜜罐识别）落到现有架构上。

## 二、功能增强

### 1. 蜜罐识别模块（新文件 `honeypot_detector.py`）

- **能力**：签名匹配（Cowrie / Conpot / Glastopf / Dionaea / OpenCanary）+ 服务组合异常（Honeyd / OpenCanary / T-Pot）
- **原则**：识别 → 标记 → 提示（不阻断扫描）；P0/P1 强信号才标记 `is_honeypot`，P2 弱信号只记证据供 AI 二次判断
- **集成**：`scanner_engine.py` 的 `VulnScanner._detect_honeypots()`，命中生成 `finding_type='honeypot'` 发现

### 2. 认证扫描（新文件 `credentialed_scan.py`）

- **能力**：用已知凭证登录目标主机（SSH paramiko / WinRM pywinrm），枚举已装软件包（Linux rpm/dpkg、Windows 注册表），交给现有 `_get_matched_cves` 匹配 CVE
- **定位**：补无凭证扫描覆盖不到的「补丁缺失」类漏洞（对标 Nessus/OpenVAS credentialed scan，直接对 20% 覆盖率缺口）
- **安全**：SSH 主机密钥校验（RejectPolicy + known_hosts，可指定密钥文件）、WinRM 仅 HTTPS(5986) + 证书校验，**无明文/跳过校验的降级路径**

### 3. proof-based 证据验证（新文件 `proof_verifier.py`）

- **能力**：布尔盲注差分验证（`' AND '1'='1` vs `' AND '1'='2` 响应差分）+ 反射 XSS 唯一 token 未编码回显验证
- **定位**：与 AI 核验互补（对标 Invicti proof-based scanning）——AI 判语义误报，proof 给确定性证据
- **集成**：`web_vuln_scanner.py` 的 `_check_sql_injection` / `_check_xss`，确认成功打 `proof_verified=True`

### 4. 暴露面系数（`risk_scoring.py` 升级）

- **公式升级**：`综合风险 = 资产价值 × 威胁(KEV/EPSS) × 脆弱性(CVSS) × 暴露面(可达性×网络暴露)`
- **对标 Wiz 可达性优先**：公网 1.0 > 内网 0.7 > 回环 0.3，关闭/过滤端口 0.1；默认 1.0 不惩罚（向后兼容）
- **效果**：把大量 CVE 按「可达 + 有利用 + 高价值」收敛排序，等效降低误报负担

### 5. 蜜罐徽标列（`main_window.py` + `report_generator.py`）

- 结果表与 HTML 报告各加「蜜罐」徽标列，命中蜜罐显示紫色「🍯 蜜罐」徽标
- 双重判定：`finding_type=='honeypot'`（实时）或 `description` 前缀 `[蜜罐告警]`（历史重载兜底）

## 三、代码改动与修复

### 代码审查修复（6 项）

| 文件 | 缺陷 | 修复 |
|------|------|------|
| `credentialed_scan.py` | Windows Get-HotFix 输出无法匹配 CVE | 改为枚举注册表已装软件（DisplayName+DisplayVersion） |
| `credentialed_scan.py` | 包名含空格被错误拆分 | `parse_package_output` 改用 `rsplit` 按最后一个空白切分 |
| `proof_verifier.py` | 仅凭长度差 ≥5% 误报（CSRF/时间戳噪声） | 加动态内容归一化（剔除时间戳/随机 token）再比较 |
| `honeypot_detector.py` | http_title/http_body 签名永不触发（死代码） | `detect_host` 只匹配 `field=='banner'`，非 banner 跳过 |
| `ai_scan_enhancer.py` | 产品矛盾预过滤误删真实 CVE（漏报） | 仅在有明确 `product` 字段时做矛盾排除，否则保守保留 |
| `database.py` | 今日工作矩阵丢「资产管理」数据 | `work_types` 补回「资产管理」 |

### 安全审查加固（2 轮）

`credentialed_scan.py` 经两轮安全审查打磨，最终安全姿态为「**始终校验、无降级**」：
- 移除 `paramiko.AutoAddPolicy()` 降级分支 → 始终 `RejectPolicy` + `load_system_host_keys()`
- 移除明文 HTTP(5985) WinRM 分支 → 始终 HTTPS(5986) + `server_cert_validation='validate'`
