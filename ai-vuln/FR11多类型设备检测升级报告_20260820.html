四、检测手段

采用三重检测手段（由强到弱，保守原则，降低误报）：

  1. 端口签名 —— 工业协议 / 私有 SDK 端口等强特征端口（约 28 项），仅收录协议特异性强、误报率低的端口；SNMP/SSH/Telnet 等通用端口不单独判定设备。
  2. 横幅关键字 —— 匹配 nmap -sV 返回的 product / version / service 字段（约 60 项厂商/协议关键字）。
  3. Web 管理界面指纹 —— 设备管理页 title / body / Server 头（约 17 项，可选实时探测增强）。

置信度分级：high / medium / low，多信号聚合时取最高置信度。

六、集成方式

VulnScanner.scan_target 在 CVE 匹配之后调用 _identify_devices：

网络扫描 → CVE 匹配 → 设备识别 + 设备专项风险 → 合并结果
  • 设备分类回写至 scan_result.hosts[*].device，并在结果顶层输出 devices 列表。
  • 设备专项风险发现与漏洞列表结构对齐，直接进入 GUI 结果表与 scan_results 库。
  • 扫描热路径仅跑纯数据识别（零额外网络 IO），Web 界面探测为可选增强。

七、测试覆盖

  • tests/test_device_fingerprint.py —— 35 项测试，覆盖五类设备的端口签名 / 横幅识别 / 置信度聚合 / 风险规则 / 批量回写 / 签名库一致性。
  • 全量回归：python -m pytest tests/ -q → 231 passed（无回归）。

九、后续建议

  1. 国产 OS 精确识别：麒麟/统信等 OS 难以通过 -sV banner 直接区分，建议接 nmap -O OS 指纹并解析 osmatch。
  2. 设备识别结果回填资产 type 字段（NETWORK_DEVICE / SECURITY_DEVICE / IOT_DEVICE 等），与资产类型下拉对齐。
  3. 新增 /api/v1/devices 端点，暴露设备识别与专项发现结果。
  4. 工控离线扫描模式与扫描时间窗口（FR-11-05 安全约束）作为调度层能力后续实现。
