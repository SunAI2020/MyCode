1. 引言

1.1 目的

本文档旨在定义下一代漏洞扫描系统（Vulnerability Scanning System，简称 VSS）的完整软件需求规格，为系统设计、开发、测试和验收提供明确的依据和标准。 本文档的读者包括：
  • 项目管理人员
  • 系统架构师
  • 软件开发工程师
  • 测试工程师
  • 质量保证人员
  • 运维工程师
  • 最终用户代表

    • 1.2 范围

    本系统是一款基于国际前沿安全理念设计的业界领先漏洞扫描系统，主要功能包括：
  • 资产发现与管理: 自动发现和管理网络资产
  • 漏洞检测: 多维度漏洞扫描和检测
  • 风险评估: 智能化风险评分和优先级排序

  • 报告生成: 多维度安全报告
  • 工作流集成: 与第三方系统深度集成

    • 2. 系统概述

    2.1 系统背景

    2.1.1 行业现状

    当前网络安全形势日益严峻，根据权威统计：
  • 2025 年全球披露的漏洞数量超过 25,000 个
  • 平均漏洞修复周期长达 100+ 天
  • 传统扫描器误报率高达 15-30%
  • 60% 的数据泄露源于已知未修复漏洞

    • 2.1.2 现有系统局限性

    问题领域痛点
    检测精度误报率高，人工复核成本大
    扫描速度耗时长，影响业务
    修复支持缺乏可执行方案
    集成能力难以融入 DevSecOps
    智能化无法适应新型攻击

    2.1.3 建设必要性

    基于国际前沿理念，设计新一代漏洞扫描系统，实现：
  • 精准检测: AI 辅助，误报率<5%
  • 快速扫描: 增量扫描，分钟级完成
  • 闭环管理: 发现→修复→验证全流程
  • 智能运营: 自动化、智能化、可视化

    • 2.2 系统目标

    2.2.1 总体目标

    构建一款业界领先的漏洞扫描系统，实现从"漏洞发现"到"风险降低"的转变。

    3.2 资产管理 (FR-01)

    3.2.1 资产发现 (FR-01-01)

    功能描述: 自动发现网络中的资产，包括主机、服务、应用等。 输入:
  • 网段范围 (CIDR 格式)
  • 发现方式 (ICMP/ARP/端口扫描)
  • 发现深度 (快速/标准/深度)
    • 处理逻辑: 
    1. 解析输入的网段范围
2. 根据发现方式执行探测
   - ICMP: 发送 Ping 请求
   - ARP: 发送 ARP 请求 (局域网)
   - 端口扫描: 探测常见端口
3. 收集响应信息
   - IP 地址、MAC 地址
   - 开放端口、运行服务
   - 操作系统指纹
4. 去重并生成资产列表
5. 存储到资产数据库
    输出:
  • 资产列表 (JSON 格式)
  • 发现统计报告
    • 用例: 
    前置条件: 用户具有资产管理权限
主流程:
  1. 用户进入资产发现页面
  2. 输入网段范围 192.168.1.0/24
  3. 选择发现方式：标准
  4. 点击"开始发现"
  5. 系统执行发现任务
  6. 显示发现结果
后置条件: 新资产已录入系统

    3.2.2 资产录入 (FR-01-02)

    功能描述: 支持手动录入和批量导入资产。 输入:
  • 资产信息 (IP、名称、类型、负责人等)
  • 导入文件 (CSV/Excel 格式)
    • 处理逻辑: 
    1. 验证输入数据格式
2. 检查资产唯一性 (IP/MAC)
3. 如已存在，提示更新或跳过
4. 如不存在，创建新资产记录
5. 触发资产基线扫描
    输出:
  • 录入结果 (成功/失败)
  • 导入统计报告

    • 3.2.3 资产分类 (FR-01-03)

    功能描述: 对资产进行分类和标签管理。 输入:
  • 资产 ID 列表
  • 分类/标签信息
    • 处理逻辑: 
    1. 验证分类/标签有效性
2. 批量更新资产属性
3. 记录操作日志
4. 触发相关策略匹配
    输出:
  • 更新结果
  • 资产分类视图

    • 3.2.4 资产生命周期 (FR-01-04)

    功能描述: 管理资产的全生命周期状态。 状态流转: 
    发现 → 待确认 → 已确认 → 运行中 → 维护中 → 已下线
         ↑          ↓
         └──────────┘
    输入:
  • 资产 ID
  • 状态变更请求
    • 处理逻辑: 
    1. 验证状态变更合法性
2. 更新资产状态
3. 如变更为"已下线"，归档相关数据
4. 通知相关人员
    输出:
  • 状态变更结果
  • 生命周期历史记录

2. 验证插件兼容性
3. 保存策略配置
4. 生成策略版本
5. 记录创建日志
    输出:

    输入:

3. 生成可执行策略
    输出:
  • 策略配置

    • 3.3.3 策略版本管理 (FR-02-03)

    功能描述: 管理策略的版本和变更历史。 输入:
  • 策略 ID
  • 操作类型 (查看/回滚/对比)
    • 处理逻辑: 
    1. 查询策略版本历史
2. 根据操作类型执行
   - 查看：显示版本详情
   - 回滚：恢复指定版本
   - 对比：显示版本差异
3. 记录操作日志
    输出:
  • 版本历史列表
  • 版本详情/对比结果

    • 3.4 扫描任务 (FR-03)

    3.4.1 任务创建 (FR-03-01)

    功能描述: 创建扫描任务。 输入:
  • 任务名称
  • 目标资产 (单个/组/网段)
  • 扫描策略
  • 执行时间 (立即/定时)
  • 通知设置
    • 处理逻辑: 
    1. 验证输入完整性
2. 验证目标资产可达性
3. 验证扫描策略有效性
4. 创建任务记录
5. 如为定时任务，加入调度队列
6. 如为立即任务，加入执行队列
    输出:
  • 任务 ID
  • 任务状态

    • 3.4.2 任务调度 (FR-03-02)

    功能描述: 管理和调度扫描任务执行。 处理逻辑: 
    1. 从调度队列获取待执行任务
2. 检查系统资源 (CPU/内存/并发)
3. 检查目标资产状态
4. 分配扫描节点
5. 下发任务到扫描节点
6. 监控任务执行状态
7. 处理任务异常 (超时/失败)
    调度算法: 
    优先级 = 基础优先级 + 时间因子 + 资产重要性因子

基础优先级:

  • 紧急任务: 100
    • 

  • 高危漏洞复测: 80
    • 

  • 定期扫描: 50
    • 

  • 临时扫描: 30
    • 

时间因子:

  • 超过计划时间: +20
    • 

  • 即将超时: +10
    • 

资产重要性因子:

  • 核心资产: +30
    • 

  • 重要资产: +20
    • 

  • 一般资产: +10
    •
    输出:
  • 任务执行状态
  • 资源分配结果

    • 3.4.3 任务执行 (FR-03-03)

    功能描述: 在扫描节点执行扫描任务。 处理逻辑: 
    1. 接收任务配置
2. 加载扫描插件
3. 对每个目标资产执行
   a. 端口扫描
   b. 服务识别
   c. 漏洞检测
   d. 结果收集
4. 实时上报进度
5. 完成后提交结果
    输出:
  • 扫描结果
  • 执行日志

    • 3.4.4 任务监控 (FR-03-04)

    功能描述: 实时监控任务执行状态。 输入:
  • 任务 ID (可选，为空则显示全部)
    • 处理逻辑: 
    1. 查询任务状态
2. 收集执行指标
   - 进度百分比
   - 已扫描资产数
   - 发现漏洞数
   - 剩余时间估算
3. 实时刷新显示
    输出:
  • 任务状态 (等待/执行中/完成/失败)
  • 执行进度
  • 实时统计

    • 3.4.5 任务控制 (FR-03-05)

    功能描述: 控制任务执行 (暂停/恢复/停止)。 输入:
  • 任务 ID

    功能描述: 计算漏洞风险分数。 计算公式: 
    风险分数 = 基础 CVSS × 环境因子 × 威胁因子 × 业务因子

环境因子 = 资产重要性 × 暴露面 × 防护强度
威胁因子 = 在野利用 × 利用难度 × 影响范围
业务因子 = 数据敏感度 × 合规要求 × 停机成本
    输入:
  • 漏洞基本信息
  • 资产信息
  • 威胁情报
  • 业务上下文
    • 处理逻辑: 
    1. 获取基础 CVSS 分数
2. 计算环境因子 (0.5-2.0)
3. 计算威胁因子 (0.5-2.0)
4. 计算业务因子 (0.5-2.0)
5. 计算最终风险分数
6. 映射到风险等级
    输出:
  • 风险分数 (0-100)
  • 风险等级 (严重/高危/中危/低危)
