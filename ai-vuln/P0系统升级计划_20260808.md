# P0 系统升级计划：测试体系 + PostgreSQL + FastAPI

> **项目**：AI漏洞扫描系统 Pro v2.0
> **公司**：山西有信网安科技有限公司
> **日期**：2026-08-08

---

## 一、背景与目标

### 当前状态

| 维度 | 现状 | 问题 |
|------|------|------|
| **架构** | PyQt5 桌面应用，单体架构 | 无法与外部系统集成 |
| **数据库** | 5 个独立 SQLite 文件，raw sqlite3 | 无连接池、无迁移路径、单机限制 |
| **测试** | **零测试覆盖** | 任何修改都有回归风险 |
| **API** | 无 | 无法被其他系统调用 |
| **数据量** | CVE 库 222MB，总计 20 张表 | 数据增长受限 |

### 升级目标

1. **P0-1：自动化测试体系** — 建立 pytest 框架，核心模块 80%+ 覆盖率，保障重构安全
2. **P0-2：SQLite → PostgreSQL 迁移** — 创建 DB 抽象层，支持双后端，数据基础升级
3. **P0-3：FastAPI RESTful API** — 添加 REST API 层，30+ 端点，打开集成能力

---

## 二、执行策略

**执行顺序：P0-1 → P0-2 → P0-3**

```
P0-1 (测试安全网) ──→ P0-2 (数据库抽象层) ──→ P0-3 (API 层)
     ↑                    ↑                      ↑
  独立交付             依赖 P0-1             依赖 P0-1 + P0-2
```

- 每阶段独立可交付，不影响现有 PyQt5 GUI 功能
- P0-1 先行建立安全网，确保后续重构不引入回归
- P0-2 创建 DB 抽象层，P0-3 在此基础上构建 API

## 四、Phase 2：SQLite → PostgreSQL 迁移

### 4.1 架构设计

```
                    ┌──────────────────┐
                    │  Database (门面)  │  ← GUI/API 统一入口，接口不变
                    └──────┬───────────┘
                           │
              ┌────────────┴────────────┐
              │   DBBackend (ABC)       │  ← 新增抽象接口
              └────────────┬────────────┘
                           │
           ┌───────────────┼───────────────┐
           │                               │
  ┌────────┴────────┐            ┌─────────┴─────────┐
  │ SQLiteBackend   │            │ PostgresBackend    │
  │ (现有逻辑提取)   │            │ (psycopg2 连接池)  │
  └─────────────────┘            └───────────────────┘
```

### 4.2 新增文件

| 文件 | 用途 |
|------|------|
| `config.py` | 集中配置（DB_BACKEND, PG_* 环境变量） |
| `.env.example` | 环境变量模板 |
| `db/__init__.py` | 后端工厂 |
| `db/backend.py` | DBBackend ABC + SQLiteBackend + PostgresBackend |
| `db/schema_postgres.py` | PostgreSQL DDL（20 张表 + 索引） |
| `db/migrate.py` | 数据迁移 CLI 工具 |

### 4.3 方言差异处理

| SQLite | PostgreSQL |
|--------|-----------|
| `AUTOINCREMENT` | `SERIAL` / `BIGSERIAL` |
| `datetime('now','localtime')` | `NOW()` |
| `INSERT OR REPLACE` | `INSERT ... ON CONFLICT ... DO UPDATE` |
| `INSERT OR IGNORE` | `INSERT ... ON CONFLICT ... DO NOTHING` |
| `PRAGMA journal_mode=WAL` | 不需要（PostgreSQL 自带 WAL） |
| `sqlite3.Row` | `RealDictCursor` |
| `lastrowid` | `RETURNING id` |
| `?` 占位符 | `%s` 占位符 |

### 4.4 需修改的文件

| 文件 | 改动 |
|------|------|
| `database.py` | `_connect()` 委托给后端；f-string SQL 重构 |
| `main_window.py` | 移除直接 sqlite3 调用 |
| `vuln_db_manager.py` | 移除 `__import__('sqlite3')` |
| `cve_db_repair.py` | 改用 Database 门面 |
| `threat_intel_reporter.py` | 改用适配器查询 |
| `intel_pipeline.py` | 改用适配器写入 |
| `requirements.txt` | 追加 sqlalchemy, psycopg2-binary |

### 4.5 数据迁移

```bash
python -m db.migrate --verify   # 迁移并校验行数一致
```

## 五、Phase 3：FastAPI RESTful API

### 5.1 架构

```
main.py (PyQt5 GUI)          api_server.py (uvicorn)
       │                            │
       └──────────┬─────────────────┘
                  │
          ┌───────┴───────┐
          │ Database 门面  │  ← 共享同一数据访问层
          └───────────────┘
```

API 服务器作为独立进程运行，不导入 PyQt5 模块，避免事件循环冲突。

### 5.2 文件结构

```
api_server.py            # 入口：uvicorn.run()
api/
├── __init__.py
├── server.py            # FastAPI app 创建 + 生命周期
├── dependencies.py      # 依赖注入（get_db, get_current_user）
├── auth.py              # API Key 认证
├── models/
│   ├── __init__.py
│   ├── common.py        # 共享模型（PaginatedResponse, APIResponse）
│   ├── assets.py        # 资产 Pydantic 模型
│   ├── scans.py         # 扫描 Pydantic 模型
│   ├── cve.py           # CVE Pydantic 模型
│   ├── intel.py         # 威胁情报 Pydantic 模型
│   └── audit.py         # 审计 Pydantic 模型
└── routers/
    ├── __init__.py
    ├── assets.py        # /api/v1/assets
    ├── scans.py         # /api/v1/scans
    ├── cve.py           # /api/v1/cve
    ├── intel.py         # /api/v1/threat-intel
    ├── audit.py         # /api/v1/audit
    ├── reports.py       # /api/v1/reports
    └── dashboard.py     # /api/v1/dashboard
```

## 七、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 重构 database.py 引入回归 | GUI 功能异常 | 中 | P0-1 测试先建立，每次修改后立即验证 |
| PostgreSQL 语法差异导致查询失败 | 生产切换故障 | 中 | 双后端 CI 测试；占位符抽象化 |
| FastAPI 与 PyQt5 事件循环冲突 | 无法同时运行 | 低 | API 独立进程，共享 DB 文件 |
| API 未授权访问 | 数据泄露 | 中 | API Key 认证 + 默认仅监听 localhost |
| 连接池耗尽 | API 阻塞 | 低 | 合理 pool size（5+10 overflow） |
| 数据迁移数据丢失 | 生产数据损失 | 低 | 迁移前备份 + 行数校验 + dry-run 模式 |
