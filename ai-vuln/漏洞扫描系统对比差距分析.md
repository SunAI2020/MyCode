## 2. 竞品对比分析

### 2.1 主机/网络漏洞扫描（Nmap 的直接上位替代）

| 系统 | 厂商/模式 | 核心能力 | 比 Nmap 强在哪 |
|------|----------|---------|--------------|
| **Nessus** | Tenable / 商业 | 18–22万+ 插件，主机 CVE + 合规 + 配置核查 | 深度 CVE 覆盖、认证扫描、合规模板（CIS/HIPAA/PCI），误报率最低，速度是 OpenVAS 的 4.9 倍 |
| **Qualys VMDR** | 商业 SaaS | 资产发现→漏洞→TruRisk 优先级→补丁联动 | 云端无部署、**PCI ASV 认证**、漏洞发布 1 小时内告警、REST API 全开放 |
| **OpenVAS/GVM** | Greenbone / 开源 | 10万+ NVT 测试 | 免费无限 IP、覆盖接近 Nessus 的 95%+、GMP API 深度自动化 |

> **关键洞察**：三者共同点是「**认证扫描（credentialed scan）**」——拿到账号后进主机内部查补丁/配置，比 Nmap 的无凭证指纹探测深入一个量级。本系统当前 Nmap/Socket 双引擎均为**无凭证扫描**，这是检测覆盖率 20% 缺口的最主要来源。

### 2.2 Web 应用 DAST 扫描

| 系统 | 定位 | 深度来源 |
|------|------|---------|
| **Burp Suite Pro** | 手工渗透事实标准 | 拦截代理 + Repeater/Intruder/Collaborator，业务逻辑、授权漏洞靠人工 |
| **Invicti（原 Netsparker）** | 自动化最准 | **Proof-based scanning 自动漏洞验证**，号称 99.98% 准确率 |
| **Acunetix** | 合规自动化 | OWASP Top10 + SQLi/XSS 全自动（已被 Invicti 收购） |
| **OWASP ZAP** | 开源默认 | 基线扫描适合 CI/CD，插件生态 |
| **Nuclei** | 模板化 | 数千社区模板，同天出 CVE 检测，CI/CD 阻断构建 |

> **可借鉴**：Invicti 的「扫描→自动验证→给出证据」与本系统 CLAUDE.md 的「扫描→AI 验证→分析」三阶段流水线**思路同构**，但本系统用 AI 做验证，Invicti 用受控利用做验证，二者可互补。

### 2.3 云原生/容器（明确空白）

| 系统 | 类型 | 强项 |
|------|------|------|
| **Trivy** | 开源单二进制 | OS 包+语言依赖+IaC+密钥+许可证+SBOM，一条命令进 CI |
| **Grype/Syft** | 开源 | SBOM 优先，EPSS/CISA KEV 风险评分 |
| **Wiz** | 商业 CNAPP | 无代理云上下文，把 200 个 CVE 收敛到「真正可达+有利用代码」的 3 个 |
| **Prisma Cloud** | 商业 CNAPP | 镜像扫描+运行时防御+云态势一体 |

> **可借鉴**：Wiz 的「可达性优先」——本系统已有 EPSS/CISA KEV 威胁情报表，但缺「漏洞→资产可达性→暴露面」上下文关联，这是把误报进一步压到 12% 以下的关键路径。

### 2.4 攻击面管理 ASM

| 系统 | 定位 | 核心能力 |
|------|------|---------|
| **Cortex Xpanse**（Palo Alto） | 互联网级 ASM | 连续扫描 43 亿 IPv4、每日 5000 亿端口，发现未纳管外网资产 |
| **Tenable One** | 曝光管理平台 | 22万+ 插件 + 外部攻击面 + OT/IoT 统一，Cyber Exposure Score |
| **Rapid7 InsightVM** | 漏洞管理 + ASM | Project Sonar 互联网测绘 + Real Risk™ 评分 |

## 3. 蜜罐识别/规避专题

### 3.1 为什么扫描器需要这个能力

蜜罐对扫描器有两层误导：

- **假阳性**：低交互蜜罐「故意命中所有漏洞模板」，让扫描器误判存在真实漏洞
- **反情报**：操作者一旦在蜜罐上深挖，IP 和行为已被记录，暴露意图

正确姿势：**识别 → 标记 → 提示**，而非静默掉线。

### 3.2 主流蜜罐类型与指纹特征

| 蜜罐 | 类型 | 易识别特征 |
|------|------|-----------|
| **Honeyd** | 低交互（模拟多主机） | TCP/IP 栈模拟不完整，seq/ack 时序异常，Nmap OS 指纹可识别 |
| **Cowrie**（Kippo 现代 fork） | SSH/Telnet 低交互 | 默认 banner、KEX 算法集、提示符与真实 OpenSSH 不一致 |
| **Dionaea** | 多协议（SMB/HTTP/FTP） | 各协议实现有缺陷，SMB 握手不完整 |
| **Conpot** | ICS/SCADA | Modbus 等工控协议响应有模板化特征 |
| **Glastopf** | Web 低交互 | 固定错误页、无真实应用逻辑 |
| **OpenCanary** | 轻量多服务 | 服务组合「过于齐全」，无真实数据 |
| **T-Pot** | 多蜜罐平台 | 各组件指纹叠加 |

> **规律**：低交互蜜罐 = 用协议模拟器「演戏」，模拟器一定有物理/行为层面的破绽，这是所有识别的理论基础。

### 3.3 识别/规避技术（按演进分三代）

**第一代：签名/特征匹配（最成熟）**

发特制请求 → 比对已知蜜罐软件的独特响应。

- **honeydet**（Golang）：多步 hex/string/regex 签名，TCP+UDP，Shodan 集成，/24 单端口约 1 秒
- **Nuclei 2026**：内置 Cowrie/Kippo/Dionaea/Conpot/Glastopf/Elastichoney/Honeyd/HoneyTrap/OpenCanary/T-Pot 等 **18 种签名**，命中输出 `honeypot_detected` 字段

**第二代：匹配密度检测（针对「故意全命中」的蜜罐）**

- 统计一台主机被多少个**不同模板**命中
- 真实主机只命中与其实际服务相关的模板；蜜罐为欺骗扫描器会命中「远超正常」的数量
- Nuclei 提供 `-hpt/-honeypot-threshold`（阈值）+ `-hpsu`（命中蜜罐则抑制输出）

**第三代：物理时序统计指纹（最硬核）**

- **Minerva HDN**（NullRabbit 开源）：**只用 TCP 时序样本**区分真实服务 vs Cowrie/Dionaea 模拟器，不抓 banner、不碰 payload
- 核心思想：**「Banner 可以伪造，物理时序不能伪造」**

**经典行为异常（仍有效）**

- **握手异常**：宣称有某服务却不完成完整 TCP 三次握手
- **环境不真实**：文件系统太空、无用户活动、对不同输入返回相同响应
- **虚拟化痕迹**：VM MAC 前缀、hypervisor 字符串

### 3.4 落地到本系统的结合点

| 现有模块 | 蜜罐识别落点 |
|---------|-------------|
| `device_fingerprint.py` | **最自然宿主**——设备指纹库里加「疑似蜜罐」签名类 |
| `scanner_engine.py` | 扫描结果加 `is_honeypot: bool` + `honeypot_type` 字段 |
| `ai_scan_enhancer.py` | 蜜罐「过于匹配」作为 AI 可判别特征，喂给误报消除流水线 |
| `threat_intel.py` | 蜜罐签名库作为一类情报源定期更新 |

实现优先级：

1. **签名库**（第一代，最快见效）：移植 honeydet 签名，覆盖 Cowrie/Honeyd/OpenCanary
2. **匹配密度阈值**（第二代）：加「单主机命中模板数」计数器
3. **TCP 时序指纹**（第三代，进阶）：对「高仿蜜罐」兜底

### 3.5 防御视角（反制）

- 用**高交互蜜罐**（真实系统+监控）而非易被指纹的低交互模拟器
- **随机化**配置，避开默认 banner/端口/文件名
- **60–90 天轮换** banner、端口、文件，静态蜜罐迟早被指纹
- 蜜罐 banner 与真实资产保持**一致**，不搞「过于完美」的环境

## 4. 差距总结与借鉴优先级

对照四项结构短板，按投入产出排序：

| 优先级 | 方向 | 参考 | 补的短板 |
|--------|------|------|---------|
| 1 | **认证扫描**（SSH/WinRM 凭证通道） | Nessus credentialed scan | 覆盖率 20% 缺口 |
| 2 | **Web DAST 引擎**（动态扫描） | ZAP / Nuclei | 缺动态 Web 扫描 |
| 3 | **可达性优先的优先级模型** | Wiz | 误报率进一步下探 |
| 4 | **容器/云原生**（低成本补） | Trivy 开源组件 | 云原生零覆盖 |
| 5 | **蜜罐识别模块** | honeydet / Nuclei | 扫描可靠性、反侦察 |
| 6 | **攻击面发现**（未纳管资产） | Cortex Xpanse | 外网暴露面 |
