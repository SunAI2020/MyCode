⚠️ 核心问题：
  1. 无视位置特征 — 6 个红球位置各有独特分布（位置 1 偏小、位置 6 偏大），但被平等对待
  2. 蓝球策略失效 — 比随机还差，完全未能捕捉蓝球规律
  3. 策略高度同质 — 频率/遗漏/趋势本质是同一信号的不同变体
  4. 忽视号码关联 — 号码组合的共现关系未被挖掘
  5. 缺乏时间衰减 — 2020 年数据与 2026 年等权重
  6. 融合机制粗糙 — 权重近乎均匀，温度扰动只是随机噪声

一、位置感知分析系统 最优先

原理

双色球 6 个红球位置（从小到大排序后）各有独立的统计分布。历史上位置 1 从未出现过 >18，位置 6 从未出现过 <10。按位置独立建模可大幅缩小搜索空间。

实现

  1. 新增 PositionalStats 类，计算每个位置的频率分布、遗漏、冷热状态、移动平均趋势（10 期/30 期/50 期）、位置边界约束
  2. 新增 PositionAwareStrategy：逐位置采样 → 组合 → 验证，仅此一项即可替代 Frequency/Missing/Trend 三个策略
  3. 修改 _validate() 增加位置边界检查

二、蓝球预测系统重建

问题诊断

蓝球权重计算系数太小（missing * 0.03），信号被噪声淹没。未利用蓝球的短周期模式。

实现

  1. 新增 BlueBallAnalyzer，专注蓝球模式：奇偶交替、大小交替（1-8 小 / 9-16 大）、012 路分析、遗漏回补窗口（遗漏 20 期+）、蓝球与上期红球关系（~15% 概率蓝球=某上期红球）
  2. 新增 BlueDedicatedStrategy：综合 6 个独立蓝球信号加权
  3. 调整融合权重：蓝球使用独立评分体系

三、共现/关联规则挖掘

原理

某些红球号码倾向于成对出现。例如号码 5 出现时，号码 12 的出现概率从基准 18% 提升到 35%。

实现

  1. 新增 CooccurrenceMiner：计算所有球对的共现频次和 lift 值（实际共现率 / 独立期望共现率），筛选 lift > 1.5 的显著关联
  2. 新增 AssociationBoostStrategy：基于高 lift 关联对生成候选组合
  3. 在融合阶段利用共现关系调整权重

四、指数衰减时间加权

所有统计分析器接受 decay_factor=0.98/期（半衰期约 35 期）。加权频率公式：

freq[i] = Σ decay_factor^(total_draws - draw_idx) × indicator(draw 包含号码 i)

应用到：频率分析、冷热分析、转移矩阵、特征提取。2020 年数据的权重仅为 2026 年的 ~1/16。

五、模块化/谐波模式分析

挖掘号码间的数学关系：同尾号（2,12,22,32）、模 3/模 5/模 7 分布、斐波那契数的聚集效应。新增 ModularPatterns 类和 ModularPatternStrategy 策略。

七、Bootstrap 集成替代温度扰动

对训练数据进行 bootstrap 重采样（有放回抽样，保留 80% 数据量），训练 N 个不同版本，每个版本独立生成预测。替代当前的 softmax(score / temp) + random.uniform() 噪声方案。

九、★ 大模型 AI 增强预测

核心理念：传统统计/ML 模型做"粗筛"，大模型做"精判"。通过 Claude Code Agent 调用大模型，在预测 pipeline 中插入推理校验层。

9.1 整体架构

历史数据 → 统计特征提取 → 8 个策略各自生成候选 →
┌─────────────────────────────────────────────┐
│  ★ 大模型推理层 (Claude via CC Agent) ★      │
│  1. 分析当前统计态势（冷热/遗漏/趋势/异常）    │
│  2. 评审各策略候选号码的合理性                │
│  3. 调整融合权重（哪个策略当前更可信）         │
│  4. 生成最终的 TOP 10 推荐号码                │
└─────────────────────────────────────────────┘
→ 保存预测 → GUI 展示

9.2 Prompt 设计要点

将统计特征 + 候选号码打包为结构化 prompt，发送给 Claude：

  • 📊 数据概况：历史总期数、最新一期开奖结果
  • 📈 统计特征：热号/冷号、遗漏 TOP8、和值/跨度/奇偶比/连号概率/区间分布
  • 🎯 各策略候选号码及评分
  • 📋 任务：态势判断 → 策略评审 → 生成 10 组号码 + 推理依据

9.3 大模型增强点

增强点传统方法+ 大模型
态势判断固定阈值（mean±3σ）LLM 综合判断趋势方向

9.4 后验分析闭环

每次开奖后，将预测 vs 实际结果发送给大模型，分析得失原因并给出下期调整建议。分析结果反馈到下一期 prompt 中，形成持续学习闭环。

9.5 成本估算

  • 每次预测：~2000 input + ~1000 output tokens
  • 每次后验：~1500 input + ~500 output tokens
  • 每周 3 次开奖 ≈ 6 次调用 ≈ 15,000 tokens/周
  • 💰 成本极低（按 token 计费模型）

十、权重更新机制修正

  1. 使用相对排名替代绝对分数：每期对策略按命中数排名
  2. 权重更新使用 Elo 评分系统：Δ = K × (actual_score - expected_score)，K=32
  3. 加入策略正交性奖励：预测向量相关性低的策略获得额外权重
